# 知识库文章模板与质量门槛

本模板约束三条学习路线的正式文章。目标不是统一文风，而是让每篇文章都能回答一个明确问题，读者能据此完成实现、选型或排障。

## 一、目录与标题

- 实体目录固定为 `学习路线/知识域/文章.md`，知识域就是思维导图的一级分支。
- 每个知识域只保留一个 `01-学习指南.md`，其余文章从 `02` 连续编号。
- 页面标题统一为 `知识域（序号） - 主题`；指南显示为 `知识域（01） - 学习指南`。
- Demo 不单独占文章。可运行源码、依赖、执行方式、预期结果和沙盒紧跟所属知识点。

## 二、正文骨架

```markdown
# 主题

> 一句话说明读者学完能解决什么问题，以及不解决什么问题。

## 为什么需要它

给出真实场景、输入输出和失败代价，不写技术发展史式铺垫。

## 核心原理

用一张表、一个数据流或一个最小例子讲清关键概念和边界。

## 实现步骤

按可验证步骤给出配置和 Python 3.10+ 类型化代码；涉及依赖时包含 requirements.txt 片段。

## 生产避坑

说明至少三个常见失败：现象、根因、定位信号和修复方式。

## 验收清单

列出可观察结果，不使用“是否理解本文”之类无效问题。

## 参考资料

- [官方文档](https://example.com)
```

## 三、质量指标

| 指标 | 合格标准 |
| --- | --- |
| 聚焦度 | 一篇只解决一个可命名的问题；重复介绍合并或删除 |
| 信息密度 | 每一节至少提供原理、决策、步骤、代码、数据或排障结论之一 |
| 易理解 | 首次出现的术语解释输入、输出和边界，并有最小例子 |
| 知识完整 | 同时覆盖 Why、How、What；工程主题补充安全、稳定性和成本 |
| 可执行 | 可运行示例声明依赖、入口、命令、预期输出和失败处理 |
| 可验证 | 结尾给出结果型清单或场景题，答案能解释为什么 |
| 可追溯 | 每篇至少链接一个官方规范、官方文档或原始论文 |
| 可维护 | 文章、目录和路线思维导图一对一，旧链接有迁移映射 |
| 篇幅 | 主课建议 1000-3500 个正文字符；超过 8000 时拆分，速查表可例外 |

## 四、图与沙盒

- 文章开头的知识图只表达当前主题的关键关系，避免重复正文目录。
- RAG、Agent 和部署链路优先使用 Mermaid；图后写清关键节点和异常分支。
- 纯 Python、HTML 或本地 JavaScript 示例优先提供浏览器沙盒。
- 需要密钥、数据库、GPU 或长驻服务的示例保留完整源码和本地运行命令，不伪装成浏览器可运行。
