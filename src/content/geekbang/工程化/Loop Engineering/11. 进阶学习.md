# 实战营

## 让Agent连续工作之后 怎样让任务可恢复也能及时停止

让 Agent 连续运行，最容易观察到的是它一直在产生动作。更需要检查的却是：这些动作有没有推进目标，失败后是否仍在重复同一种尝试，预算耗尽时能否停下来。

Loop Engineering 知识库通过 Issue Garden 维护循环，带你建立执行、独立验证、状态保存与停止判断的流程。接下来，可以把这个本地闭环放到更复杂的任务里，检查它能否被恢复、接管和追踪。

## 先证明循环知道什么时候结束

选择一个范围明确的维护任务，为它写好验收条件。每一轮结束后，沿着下面几项决定下一步。

![原文图片](../../assets/65782c164028ef3d6884.png)

比如，Agent 修改代码后测试仍然失败，需要先看失败是否与修改有关、是否出现新信息。重复同一种改法却没有改善时，应调整策略或请求帮助，而不是继续消耗调用次数。

给任务设定轮次、时间和成本上限；遇到缺少输入或权限不足时，保存原因和当前状态。一次没有完成的运行，也应让接手的人看懂已经尝试了什么、还需要什么。

你可以主动中断一次本地任务，再检查是否能从记录中恢复。这个练习比只观察一次成功运行，更容易暴露状态保存和恢复逻辑的问题。

## 从本地循环 到可接管的长任务

如果任务变成定期经营分析，过程中要查数据、运行计算、等待审批，单机上的循环就需要补上更完整的运行管理。下面四项是检查起点。

![原文图片](../../assets/f904d6fafab9d5296720.png)

例如，分析报告已生成，但创建工单时服务中断。恢复后应根据已保存的步骤和动作结果继续，先确认工单是否已经创建，再决定重试，避免重复提交。

多个人同时运行任务时，还需要区分任务归属、数据权限与预算。等待人工审批的任务要能暂停，批准或拒绝后再按明确的状态转换继续。

这时，停止条件、检查点和验证结果需要进入统一的运行模型。否则，每个业务各写一套循环，很难共同处理调度、故障接管和问题排查。

## 继续学习运行时与恢复架构

《企业级 Agent 工程架构实战营》围绕这些问题展开架构进阶实践，适合已经能实现基础 Agent、希望进一步建设复杂系统的工程师。

课程在自主分析 Loop 中讨论验证器、停止条件与自主性预算，并用统一的运行、任务、步骤、尝试和事件模型管理执行。随后练习检查点、持久化执行、人工中断与恢复，以及重复执行和副作用控制。

贯穿的零售经营分析与决策 DataAgent 项目，会将自主分析与确定性工作流结合：分析可以迭代补充证据，预算调整等动作则经过审批和受控执行。课程还安排分布式运行与故障注入，检查任务能否恢复和接管。

这些内容能帮助你把知识库中的本地 Runner 设计经验，扩展到调度、运行治理和评测体系，并用执行轨迹定位具体失败步骤。

## 带着一次失败运行 继续深入

整理一个没有顺利结束的任务：当时停在哪一步，已经产生什么结果，恢复需要什么信息，是否可能重复执行。它会成为很具体的架构练习材料。
