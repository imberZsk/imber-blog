# 21. 进阶学习

> 来源：[150 道 AI 面试题](https://time.geekbang.org/space/wiki/AI_Interview)

刷完 150 道 AI 面试题之后，真正要补的是一张能力地图

150 道题看起来很多，但把 14 个模块放在一起，会发现它们并不是 150 个互不相干的知识点。

它们大致可以被整理成三层。

第一层是模型与应用基础。

这里包括大模型通识、API 调用与结构化输出、提示工程，以及最后的 ML、DL 基础扫盲。你会碰到模型选型、Token 与上下文窗口、采样参数、幻觉、Embedding、多模态、开源与闭源模型，也会继续处理流式输出、JSON Schema、多轮 Function Calling、超时和多厂商 API 封装。

这一层解决的是，模型怎样工作，我们怎样稳定地调用它。

第二层是 AI 应用的核心系统。

RAG、数据与知识工程、AI Agent、Harness 与 Loop、LangChain、LangGraph、Spring AI 等框架， 都放在这一层。题目不只问概念，还会追问系统为什么这样设计。

比如，为什么纯向量检索不够，混合检索与 Rerank 怎样配合。为什么 Agent 会死循环， Checkpoint、Trace 和权限边界应该放在哪里。什么时候需要多 Agent，什么时候只是过度设计。框架、编排与 Harness 又该怎样分工。

这一层解决的是，模型怎样进入一个可以完成任务的应用。

第三层是生产与业务。

模型部署与推理优化、应用侧评估、生产可靠性、安全合规、产品与成本意识，都在提醒同一件事。

一个 AI 应用能运行，只是开始。它还要处理量化、KV Cache、vLLM、Continuous Batching、重试、 幂等、限流、缓存、背压、灰度、回滚、内容审核、数据安全与成本熔断。最后还要回答一个很现实的问题，这个功能值不值得做。

所以这 150 道题真正覆盖的，其实是一条从模型到业务的完整链路。

真正值得带走的，是问题之间的关系。

题目 65 到 80 讲 Agent 的规划、工具、记忆、死循环、人工审批、并行调用和评估。题目 81 到 90 紧接着进入 Harness、上下文压缩、中断恢复、Trace、权限与状态持久化。到了题目 109 到 118，又开始讨论 Golden Set、LLM-as-Judge、A/B 测试、回归门禁与完整反馈闭环。

这三组题连起来，就是一套 Agent 系统的主干。

Agent 决定怎样行动，Harness 提供运行环境和安全边界，评测系统判断它有没有变好。

再看生产可靠性模块。超时、重试与幂等不能分开设计，模型调用与有副作用的操作也不能混在一起。否则一次重试就可能重复发消息、重复扣款，或者重复修改外部系统。

这些不是面试话术。是系统真正上线后一定会遇到的问题。

面试题擅长帮我们暴露知识缺口，却很难替代完整项目。

你可以解释 ReAct 和 Plan-and-Execute 的区别，但真实任务来了，仍然要自己定义状态、停止条件和错误升级。你可以回答怎样评估 RAG，但真正构建 Golden Set 时，仍然要从业务问题中整理样本、定义标签并处理争议案例。

你也可以讲清 Trace 的作用，但只有亲手排查过一次跨模型、检索、工具和数据库的失败链路，才会真正理解为什么 Trace 必须成为调试主键。从知道到做到，中间差的是系统设计、代码实现、调试证据和多轮迭代。

这也是刷完题以后最容易产生的错觉。答案看懂了，能力好像也拥有了。

其实还差一次完整交付。

这是为什么想在这里推荐「AI Agent 全栈工程师训练营」的原因。能承接的，是把地图里的关键节点变成项目。

课程用 14 周覆盖 LLM 与 Prompt、RAG、Agent Loop、Memory、Skill、Context Engineering、 Agent Eval、Tracing、MCP 和生产部署。它不是继续增加题目数量，而是让这些概念在同一个系统里协作。

第一个项目会搭建 Agent 工具调用运行时，把 ToolRegistry、Schema 校验、权限分级、审计、超时、重试、降级、MCP 与 Trace 放在一起。

Codebase Agent 项目会让 Agent 搜索和修改文件、运行测试、读取失败日志、自动修复，同时加入人工确认、沙箱、状态和 Checkpoint。

Codebase RAG 项目会继续处理混合检索、Rerank、项目记忆、上下文压缩、任务恢复与引用追溯。

Multi-Agent 与 Eval 项目则会建立多角色协作、Benchmark、LLM-as-Judge、人工评测、Trace Analysis 和版本回归。

再往后，Agent Production Ops Platform 会加入模型网关、监控、回放、版本管理、灰度、回滚与成本治理。收官项目基于 DeerFlow 搭建深度研究平台和新一代软件工厂。

这些项目，刚好把面试题里分散的模块重新装回一套工程系统。
