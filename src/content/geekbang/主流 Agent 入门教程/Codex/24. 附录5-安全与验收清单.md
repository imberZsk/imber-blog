# 24. 附录5-安全与验收清单

> 来源：[Codex](https://time.geekbang.org/space/wiki/Codex_Tutorial)

## 一、开始任务前

- 当前目录是正确项目，不是主目录或磁盘根目录
- `git status` 已检查，知道哪些改动原本就存在
- 重要文件已有版本控制或备份
- 任务目标、范围外事项和完成标准清楚
- 使用完成任务所需的最小权限
- 不需要联网时，网络保持关闭
- 密钥、客户数据和生产数据不进入提示词

## 二、批准命令前

- 看清完整命令，不只看解释
- 读写路径属于本次任务范围
- 网络目标和用途明确
- 没有递归删除、覆盖或大范围移动风险
- 安装的依赖来源可信且确有必要
- 不会把凭据写入日志或构建产物
- 高风险动作有预览和回滚办法

## 三、代码实现验收

- 修改范围与任务一致
- 新行为有测试
- 缺陷修复的回归测试曾在修复前失败
- 错误输入和边界情况有覆盖
- 先跑局部测试，再跑完整测试
- 实际入口至少手动运行一次
- 旧数据或旧接口兼容性已验证
- README 与真实命令一致
- `/diff` 中没有无关重构

## 四、数据与文件操作验收

- 操作前有原文件清单
- 没有直接处理唯一原件
- 重名和覆盖策略明确
- 无法判断的文件保留在待确认区
- 执行前生成移动或修改预览
- 执行后文件数量与完整性已核对
- 记录了原路径、目标路径和失败项
- 删除操作经过单独确认

## 五、数据分析验收

- 字段、行数、日期范围已确认
- 空值、重复和异常值处理口径明确
- 指标公式与单位明确
- 至少抽查一组原始数据和计算结果
- 图表标题、单位、时间范围完整
- 事实、推断和建议清楚区分
- 没有把相关性表述成因果关系
- 引用数字能追溯到数据范围

## 六、发布前

- 工作区状态符合预期
- 完整测试通过并记录命令与结果
- 安装、升级和核心路径实际验证
- 旧版本数据或配置可兼容
- README、CHANGELOG 和实现一致
- 没有 `.env`、API Key、令牌和客户数据
- 没有运行数据、缓存、临时报告和个人绝对路径
- 已知限制已记录
- 提交、标签、推送和发布由人明确确认

## 七、Agent 最终汇报应包含

- 修改了哪些文件
- 为什么修改
- 实际执行了哪些验证
- 测试数量、结果或退出码
- 哪些内容没有验证
- 仍然存在什么风险或限制
- 是否执行了外部写入、提交或发布
