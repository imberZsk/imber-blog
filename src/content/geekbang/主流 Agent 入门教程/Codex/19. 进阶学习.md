# 19. 进阶学习

> 来源：[Codex](https://time.geekbang.org/space/wiki/Codex_Tutorial)

## 用Codex完成第一个项目之后 怎样进一步开发Agent应用

跟着 Codex 知识库完成 TaskFlow，你已经练习过需求拆解、代码修改、问题复现和验收，也开始用项目说明、权限设置与任务记录管理开发过程。

接下来，可以把注意力从一次功能实现扩展到应用本身：如果要让一个 Agent 长期帮助用户处理任务，它需要哪些工具、怎样保存进度，又如何证明结果可靠？

## 先让一次代码修改有清楚的依据

不妨给 TaskFlow 增加一个任务筛选功能。提交给 Codex 之前，先整理下面四项，让它的修改和你的验收围绕同一套约定展开。

![原文图片](../../assets/47198bd65bde1d2a70d6.png)

例如，约定只增加状态筛选，沿用现有页面样式；筛选后仍允许修改任务；没有匹配结果时显示空状态；刷新后按项目原有方式保存数据。随后检查正常输入、空列表和刷新场景，而不只看页面是否出现了一个按钮。

如果结果不符合预期，先复现问题，再提供操作步骤和实际结果。这些知识库中的练习，能帮助你更稳定地组织 AI 辅助开发，也让每次修改更容易检查和接手。

## 把开发经验用到Agent应用里

当你想做一个能读取代码库、运行测试并定位问题的助手，项目就会出现新的设计要求。可以先沿着下面四项拆解。

![原文图片](../../assets/7d8bf2cc19b4fca910ef.png)

读取文件的工具需要约定参数与返回值；长任务需要保存已完成的步骤；测试失败后要决定重试、调整计划还是请求帮助；完成后还要检查代码质量、工具调用记录和运行成本。

这里的难点，是把模型、工具和任务过程连接起来。可以从一个小任务开始：只允许助手读取指定目录，生成修改建议，由人审核后执行。待验证清楚，再逐步增加测试和修改能力。

Codex 可以继续帮助你实现这些模块。你也需要理解模块为什么这样设计，才能在发生超时、信息遗漏或重复执行时，找到问题所在。

## 从使用编码助手 到构建自己的Agent

《AI Agent 全栈工程师训练营》可以承接这一步学习。课程围绕工具调用、RAG、Agent Loop、上下文管理、评测和生产部署，安排多项工程实践。

其中，工具调用基础设施项目涉及参数校验、权限与风险分级、超时重试和调用追踪；Codebase Agent 项目练习规划、文件操作、测试与失败修复，以及人工确认和任务检查点。

后续的 Codebase RAG 与 Agent 实践，会加入代码检索、项目记忆和任务恢复；多 Agent 与评测项目，则练习协作、基准管理和版本比较。这些内容能让你把知识库中积累的项目经验，进一步用于 Agent 应用的开发与验证。

如果你希望从用 Codex 完成功能，走向独立组织一套 Agent 应用，可以带着自己的代码库或任务场景，对照课程项目判断学习重点。

## 选一个任务 作为下一步实践

先写清你希望 Agent 完成的一件事，再列出它需要读取什么、调用什么、交付什么，以及什么时候停止。一个范围明确的任务，更容易成为完整的实践项目。
