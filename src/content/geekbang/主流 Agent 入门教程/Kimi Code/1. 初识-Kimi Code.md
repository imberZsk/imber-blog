# 1. 初识-Kimi Code

> 来源：[Kimi Code](https://time.geekbang.org/space/wiki/Kimi_Code_Tutorial)

在正式敲下第一行命令之前，我们先花一章的篇幅，把几个最基础的问题聊清楚：Kimi Code 到底是什么？它能帮你做什么？它有哪几种形态，你该选哪一个？

这一章不需要你动手操作，安心读完就好。但这些认知很重要——很多人对 AI 编程工具的误解，都是从"没搞清楚它是什么"开始的。

## 1.1 Kimi Code 是什么

一句话概括：**Kimi Code 是一个 AI 编程 Agent**——你用自然语言交代任务，它自己动手读代码、改文件、跑命令，把开发任务从头到尾做完。

如果你用过网页版的 AI 聊天助手，可能会想：不就是让 AI 写代码吗？我把需求发给它，它生成一段代码，我复制粘贴过来，不就行了？

不太一样。聊天式的 AI 更像一位"电话顾问"：你描述问题，它口头给你建议，但动手的永远是你自己——它说"你应该在 `src/utils.ts` 里加一个函数"，然后你得自己打开文件、敲代码、跑测试，出了问题再回去问它。

Kimi Code 则是一位"坐在你旁边的同事"。你跟它说"帮我修一下这个 bug"，它会自己去翻项目里的文件，找到问题所在，动手修改，然后运行测试验证，最后告诉你它做了什么、结果如何。如果中途发现情况不对，它还会自己调整方案，或者停下来问你的意见。

这种"能自己动手"的能力，行话叫 **Agent（智能体）**。具体来说，Kimi Code 可以：

- **读**：浏览项目文件、搜索代码、抓取网页资料；
- **写**：新建、修改、删除文件；
- **跑**：在终端里执行命令，比如安装依赖、运行测试、启动服务；
- **想**：根据每一步的结果，自主规划下一步该做什么。

所以，与其说它是一个"代码生成器"，不如说它是一个"能干活的搭档"。你要学会的不是"怎么向它要代码"，而是"怎么跟它分工合作"——这也是本教程要教你的核心。

## 1.2 它能帮你做什么

知道了原理，再来看看实际场景。下面这些事情，Kimi Code 都能胜任：

**写新功能。** 描述清楚你想要什么，它就规划步骤、动手实现。比如："给这个应用加一个深色模式切换按钮，点击后整个页面换肤，刷新后设置不丢。"

**修 bug。** 把症状、复现步骤、期望行为一次性告诉它，它会定位问题、修复、跑测试确认。比如："偶现登录成功后刷新页面又跳回登录页，第二次刷新就正常了，帮我查查原因。"

**读懂陌生项目。** 刚接手一个不熟悉的代码仓库，可以让它先带你逛一圈："给我讲讲这个项目的架构，入口在哪，各个模块是怎么依赖的。"比自己闷头翻半天文件快得多。

**重构和补测试。** "把这几个文件里重复的逻辑提取成公共函数，改完跑一遍测试，确保行为没变。"——这类边界清晰的任务，它做得又快又稳。

**自动化琐事。** 批量重命名文件、分析最近七天的访问日志并生成报表、把某种格式的数据全部转换成另一种……这些你不想亲手干的活儿，一句话就能派给它。

**写文档。** 生成 README、给没有注释的函数补文档、根据代码变更更新 CHANGELOG，都不在话下。

**定时任务。** 你还可以让它"每天早上九点提醒我记录体重"或者"每小时检查一次服务是否正常"，它会设置好定时任务，到点自动执行。

值得一提的是，虽然 Kimi Code 是为编程而生，但"编程"不等于"只有职业程序员才用得上"。本教程的实战项目就是一个很生活化的例子——我们会从零做一个**体重管理小助手**，能记录每天吃了什么、运动了多少、体重怎么变。你不需要有开发经验，跟着做就能完成；而如果你本身就是开发者，这个过程学到的方法可以直接搬回你的日常工作中。

## 1.3 四种产品形态，各适合谁

Kimi Code 不是一个单一的软件，而是一组产品。同一个账号、同一份会员权益，可以在不同形态里使用。我们先建立一个全局印象，后面章节再逐一深入：

| 形态 | 运行环境 | 适合的场景 |
| --- | --- | --- |
| **CLI（命令行）** | 终端，支持 macOS / Linux / Windows | 本教程的主角。功能最完整、更新最快，适合日常开发和一切自动化任务 |
| **VS Code 扩展** | VS Code 编辑器内 | 习惯在图形化编辑器里边看代码边和 AI 协作的开发者 |
| **Desktop 桌面客户端** | macOS / Windows 图形应用 | 偏好独立应用、不想碰终端的用户，登录 Kimi 账号即可使用 |
| **API Key** | 接入 Claude Code 等第三方工具 | 已经有自己习惯的工具链，只想接入 Kimi 的模型能力 |

**为什么本教程以 CLI 为主？** 三个原因：

1. CLI 是 Kimi Code 能力最完整的形态，新功能往往也最先在 CLI 上线；
2. CLI 在各个操作系统上的体验高度一致，学会一次，到哪台机器上都能用；
3. 其他形态本质上都是 CLI 能力的延伸——VS Code 扩展和 IDE 集成的背后，跑的就是 CLI 这个核心。把 CLI 学透了，再用其他形态基本不用重新学。

Desktop 客户端我们会在最后一章单独介绍；VS Code 扩展和 API Key 的用法在第 11 章讲解。

## 1.4 会员、额度与模型

开始安装之前，还有几件"行政事务"需要心里有数。

**需要 Kimi 会员。** Kimi Code 是会员权益的一部分，使用前先确认你的 Kimi 账号已开通相应会员。不同等级的会员，可用的模型和上下文长度不同。

**额度是按周期刷新的。** 使用过程中，随时可以输入 `/usage` 命令查看当前额度和会员状态。如果额度用完了，可以等下一个周期刷新，或者在会员页面升级。

**模型可以自由切换。** 登录后，在 CLI 里输入 `/model` 就能切换当前使用的模型。目前主要有两类可选：

- **标准模型**（如 K3 旗舰模型、K2.8 Preview）：能力强，适合复杂任务，旗舰型号最高支持约 100 万 token 的超长上下文——足够一次性装进一个大型项目的全部代码；
- **高速模型**（K2.7 Code HighSpeed）：输出速度可达约 260 tokens/s，适合追求响应快的日常小任务。

刚开始不用纠结选哪个，用默认的就好。等你在实战中体会到差别（比如第 6 章开发功能、第 9 章讲配置时），再根据自己的习惯调整。

> **注意：别把两个平台搞混了。**
>
> Kimi Code 的会员权益（订阅制，含额度）和 Kimi 开放平台的 API（按量计费）是两套体系，Base URL 和 API Key 互不通用。本教程全程使用 Kimi Code 会员权益，登录时用 `/login` 选择 "Kimi Code (OAuth)" 即可，不需要自己去开放平台申请 Key。

## 本章小结

这一章我们认识了 Kimi Code：

- 它是一个**能干活的 AI 搭档**（Agent），会读、会写、会跑命令、会自己规划，而不只是一个"代码生成器"；
- 它能做**写功能、修 bug、读项目、重构、自动化、写文档、定时任务**这些事；
- 它有 **CLI、VS Code 扩展、Desktop 客户端、API Key** 四种形态，本教程以 CLI 为主线；
- 使用前需要 **Kimi 会员**，额度用 `/usage` 查看，模型用 `/model` 切换。

下一章我们就要动手了：在你自己的电脑上安装 Kimi Code CLI。macOS、Linux、Windows（WSL2 和 PowerShell 两条路线）的安装方式略有不同，我会把每条路线的每一步都写清楚，你照着做就行。
