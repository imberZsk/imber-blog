# 13. 进阶学习

> 来源：[Kimi Code](https://time.geekbang.org/space/wiki/Kimi_Code_Tutorial)

## 用 Kimi Code 做出小工具之后 你可以再往前走一步

第一次让 Kimi Code 做出一个能用的小工具，最让人开心的时刻，往往是点下按钮，发现它真的按自己的想法运行了。

跟着知识库完成体重管理小助手，你已经能记录饮食、运动和体重，也开始学着检查计算结果、修复问题、保存代码版本。接下来，你可能会想：这套方法，能不能用到工作中的项目里？

## 先把本周统计说明白

给小助手增加“本周统计”，看起来只有一句话，实际却有四个需要提前约定的问题。

![原文图片](../../assets/ad90d28d47dc43d840da.png)

比如，你可以选择按自然周统计；漏记的日期不计入平均值，并提示记录不完整；没有记录时显示 “本周暂无数据”；刷新之后保留已有记录。这是一套示例约定，你也可以根据自己的需求调整。

把这些约定写进项目文件，再让 Kimi Code 实现，就有了清楚的验收依据。知识库里的项目规则、测试和会话管理，也能帮助你把依据留下来，方便以后继续开发。

## 到了真实项目 先理清关联再动手

工作中的项目通常没有小工具这么整齐。给已有系统增加一个模型调用入口，可能同时涉及页面、登录权限、配置、日志和旧接口，可以先按下面的顺序推进。

![原文图片](../../assets/1edd0626a8e5a191ad2e.png)

例如，先让 AI 找到原来的登录和接口处理流程，再约定只改模型入口相关文件，保留已有行为。每完成一小步，都留下测试或实际运行结果。

随着项目变大，有条理地提供背景、控制修改范围、保存验证依据，会成为你与 AI 协作的重要能力。

## 找一个复杂项目 继续练习

如果你已经完成入门练习，想把 AI 编程带进真实仓库，可以进一步了解《企业级 AI 编程实战营》。

课程以 Claude Code 为主要实践工具，通过规格驱动开发，把需求、任务拆解、实现和验证串起来。 对 Kimi Code 用户来说，可以继续学习其中能够迁移到其他工具的开发方法。

例如，DifyPro 项目会练习理解陌生的大型仓库，再完成小范围修改；OryxOS 项目则把需求、架构、 工具接入和最终验证连接起来。它们提供了比入门小工具更复杂的练习环境。

你可以带着自己的项目来对照课程大纲：目前最难的是理解仓库、控制修改范围，还是验证结果？先找到需要补齐的环节，再决定下一步学什么。
