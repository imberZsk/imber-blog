# 10. 进阶学习

> 来源：[ZCode](https://time.geekbang.org/space/wiki/ZCode_Tutorial)

## 用 ZCode 做出一个能用的页面 下一步该学什么

在 ZCode 知识库中，你做出了一个“今日专注清单”：可以添加、完成、删除事项，按状态筛选，刷新后保留数据，还能逐步加入周统计和导出功能。

这个小应用有一个很好的学习特点：结果看得见，也检查得了。

按钮有没有反应、数据有没有保存、手机上能不能操作，打开页面试一试就知道。它让你走完了从提出需求到检查结果的第一段路。

## 把这套检查方法留下来

每次增加功能，都留下一份可以重复操作的检查清单。可以从下面四类情况开始。

![原文图片](../../assets/7bb1af50c44eb6bb32c2.png)

然后，看看 Git 中的代码差异：这次改了哪些文件，有没有顺手修改无关内容？修复后，再用清单确认已有功能仍然正常。

这样，你积累的不只是一个能用的页面，还有一套以后可以反复使用的验收方法。

## 当清单开始给多人使用

如果有一天，你想让同事也用这个清单，验收就要扩展到页面之外。下面四个问题，需要接口、数据和权限一起配合。

![原文图片](../../assets/640aaca928b17a510fb3.png)

可以先做一个小升级：增加一个后端接口，约定字段和错误返回，再接上页面。最后，主动模拟一次接口失败，看看应用怎样回应。

浏览器里的检查仍然重要，但你还需要检查接口返回、失败提示和发布后的行为。学习可以沿着真实需求逐步展开。

## 把小应用里的经验 带到更完整的项目

如果你准备继续学习完整项目交付，可以了解《企业级 AI 编程实战营》。

课程以 Claude Code 为主要实践工具，通过规格驱动开发，把需求、实现、测试和审查放进同一条流程。ZCode 用户可以从中继续练习项目交付方法。

OryxOS 项目会涉及工具接入、权限和端到端验证；DifyPro 项目则练习在已有大型仓库中做增量修改，检查对旧功能的影响。

从本地页面走向真实系统，需要把验收范围一步步扩展。你可以先对照课程项目，看看自己的下一步是前后端协作，还是维护已有仓库，再选择合适的学习内容。
