# 15. 进阶学习

> 来源：[TraeCode](https://time.geekbang.org/space/wiki/TraeCode_Tutorial)

这套 TraeCode 教程选择了一条很务实的主线——做一个家庭账本。

先安装和初始化，再让 CLI 调查项目。然后建立账本骨架，写下开发规范，完成功能开发、测试调试和 Git 工作流。后面的章节继续加入斜杠命令与 AGENTS.md、自定义智能体与记忆、MCP、自动化与 CI、Hooks、ACP、权限安全和 Desktop。

第 3 章第一次进入项目时，要求先调查，不急着修改。第 7 章强调小步提交和合并前审查。第 10 章接 MCP 时，只接一个可验证的账本工具，还提醒服务端与客户端不能混淆。第 11 章谈自动化与 CI 时， 明确把确定性检查与 AI 建议分开。

这最后一点尤其重要。

测试是否通过，格式是否合规，构建是否成功，这些可以由确定性程序给出结果。代码结构是否清晰、某段实现是否存在潜在风险，AI 可以提供建议。但建议不能冒充门禁，门禁也不该依赖一段不稳定的自然语言判断。

所以读完这套知识库，真正掌握的是一套分层思路。

### 从家庭账本到真实项目，还差什么

先调查，再修改。

先用 AGENTS.md 和项目约定告诉 TraeCode 规则，再让它执行。

先把可确定的部分交给测试、Git Hook 和 CI，再让 AI 处理需要解释与判断的部分。

先验证 MCP 工具的输入和结果，再把外部能力接进工作流。

家庭账本规模不大，这些动作已经足够形成闭环。但真实项目会立刻放大每一个问题。

一个账本功能可能只涉及几个文件。企业项目里的需求会跨前端、后端、数据库和部署配置。一个 AGENTS.md 可以写清小项目约定，大型仓库还需要分层规则、架构文档、启动脚本与模块边界。一个 CI 检查可以守住测试，复杂交付还需要权限、审计、安全扫描、发布和回滚。

自定义智能体也会遇到协作问题。

让多个 Agent 分别调研、编码、测试和 Review，听起来很高效。但它们共享什么上下文，修改怎样隔离，冲突如何处理，哪个角色可以执行高风险动作，最后谁对结果负责，都需要提前设计。

否则多智能体不是并行开发，而是并行制造混乱。。

教程里的家庭账本已经给出了很好的最小版本。继续往企业级走，需要把这些方法系统化。

需求不只是一段自然语言，而要成为 spec、plan 和 tasks。项目规则不只告诉 AI 代码风格，还要让开发环境可以启动，让日志和运行状态可读，让完成条件可以机器验证。Hooks 不只做本地提醒，还要

成为稳定的工程门禁。Worktrees 用于隔离并行修改，Skills 用于沉淀团队重复流程。

「企业级 AI 编程实战营」接的就是这一层。

### 课程具体怎样承接

课程用 SDD 管理需求与任务，用 Harness Engineering 建立 Agent 可工作的仓库环境，再组合 Subagents、Worktrees、Permission、Hooks、Skills 与 Slash Commands 完成复杂交付。

三个企业级项目分别覆盖从零构建、复杂自有系统和大型开源项目改造。

AI 智能体操作系统会处理 Agent Runtime、工作空间隔离、多模型路由与 MCP。分布式延时投递服务会处理高可用、故障切换和消息可靠性。Dify 平台二次开发会训练怎样用 Subagents 理解陌生代码， 用增量规格约束修改，并通过权限与 Hooks 守住回归边界。收官还有 mq9 开源协作，PR 是否合并以维护者实际 review 为准。
