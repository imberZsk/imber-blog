# 14. TraeCode桌面版使用入门

> 来源：[TraeCode](https://time.geekbang.org/space/wiki/TraeCode_Tutorial)

## 第十四章（附录）TraeCode Desktop 使用入门

前面十三章都在讲 CLI。这一章我们看看 TraeCode 的 IDE 形态——**TraeCode Desktop**，了解它和 CLI 如何互补。

### 14.1 TraeCode IDE 是什么

TraeCode 是一款**深度融合 AI 能力的集成开发环境**，保留完整的 IDE 基础能力（编辑器、终端、调试、插件、源代码管理），同时内置 AI 编程能力。简单说：它是一个「AI 原生 IDE」。

### 14.2 IDE 模式 vs SOLO 模式

TraeCode 提供两种模式，按任务灵活切换：

| 模式 | 特点 | 适合场景 |
| --- | --- | --- |
| **IDE 模式** | 保留编辑器、终端、调试、插件、源码管理等工作流，你精细控制每一步 | 需要精准控制代码改动和执行过程 |
| **SOLO 模式** | AI 主导，用自然语言或语音描述需求，AI 自动规划任务、生成代码、测试、预览、总结 | 复杂任务、想快速出原型 |

### 14.3 下载与安装

**下载入口**：访问 [trae.cn/download](https://www.trae.cn/ide/download)，根据操作系统下载对应安装包。

| 操作系统 | 安装方式 |
| --- | --- |
| macOS | 下载 `.dmg`，双击打开，把 TraeCode 拖入「应用程序」文件夹 |
| Linux | 下载 `.deb` 或 `.rpm`，双击安装或用包管理器安装 |
| Windows | 下载 `.exe` 安装包，双击按向导安装 |

安装后打开 TraeCode，首次启动会引导你登录 TRAE 账号（和 CLI 同一套账号体系）。

### 14.4 核心能力速览

**CUE 代码补全**：

- 普通补全：基于上下文预测后续代码。
- **补全 Pro**：基于你上一次的编辑动作，预测下一个改动点——批量重构时特别省事。
- 多行修改、修改点预测与跳转。
- 在 Python、TypeScript、Golang 项目中辅助智能导入和重命名。

**智能体**：用自然语言定义任务，AI 理解需求、检索代码库、制定多步骤计划、调用工具完成开发。也能创建自定义智能体。

**上下文管理**：可以把文件、文件夹、代码片段、终端输出、代码仓库、文档集甚至网页作为上下文，让 AI 基于更完整的信息回答。

**智能代码审查**：对未提交变更、单次提交或分支差异做总结和审查，配摘要、流程图和 diff 视图。

**Git 工作流**：内置完整 Git 支持，AI 可生成规范的 Commit Message。

**安全能力**：

- **隐私模式**：开启后，对话内容、代码片段和 AI 输出不用于数据分析、产品优化或模型训练，代码库文件始终在本地。
- **沙箱运行**：智能体生成的命令在受限环境执行，降低误操作风险。

### 14.5 CLI 与 IDE 的协同

CLI 和 IDE 不是二选一，而是互补的：

| 用 CLI 做什么 | 用 IDE 做什么 |
| --- | --- |
| 自动化脚本、CI 流水线 | 精细编辑、断点调试 |
| 多步骤复杂任务（测试修复、重构） | 实时补全（CUE Pro） |
| 批量处理、代码迁移 | 可视化 diff、代码审查 |
| 终端原生工作流 | 需要图形界面的场景 |

**ACP（Agent Client Protocol）让两者打通**：TraeCode CLI 支持 ACP，可作为智能体服务端接入支持 ACP 的编辑器或客户端。这意味着你可以在 IDE 里调用 CLI 的能力，获得一致的 AI 编码体验。

**实际协同方式**：

- 日常写代码用 IDE 的 CUE 补全，效率最高。
- 需要跑一轮「测试→修 bug→评审」的多步骤任务，切到 CLI 让它自动完成。
- CI 里用 CLI 非交互模式做自动化检查。
- 大重构前用 CLI 的 `/review` 审查，再到 IDE 里精细调整。

## 结语

恭喜你读完了整篇教程。回顾一下我们走过的路：

1. **认识产品**：四类产品形态及适用场景。
2. **安装上手**：macOS、Linux、WSL2、PowerShell。
3. **初体验**：TUI、@提及、图片输入、斜杠命令、会话恢复。
4. **实战项目**：家庭账本从零搭建。
5. **功能开发**：分类统计、月度报表与分支管理。
6. **测试调试**：生成测试、修 Bug、回归验证。
7. **Git 工作流**：自动化提交、审查、解冲突。
8. **自定义命令与 AGENTS.md**：沉淀常用流程。
9. **全局配置、自定义智能体与记忆**。
10. **MCP、插件与技能扩展**。
11. **自动化与 CI 集成**。
12. **Hooks 与 ACP**。
13. **进阶**：权限模式、工具权限、沙箱与诊断。
14. **TraeCode Desktop 速览**。

最重要的是贯穿全程的那条主线——**好习惯**：

- 每个功能一个分支，提交前看 diff。
- 不盲目接受 AI 输出，先理解再采纳。
- 把规范和流程沉淀进 AGENTS.md 和自定义命令。
- 改完跑测试，提交前做 review。

这些习惯不只让 TraeCode 用得顺，更是任何工程项目的通用素养。祝你在 AI 辅助开发的路上越走越顺。
