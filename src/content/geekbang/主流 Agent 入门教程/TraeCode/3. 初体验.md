# 3. 初体验

> 来源：[TraeCode](https://time.geekbang.org/space/wiki/TraeCode_Tutorial)

## 3.1 启动与核对环境

在一个独立练习目录运行 traecli，先输入 /status，核对当前目录、模型与权限。也可 `traecli --cd "/实际项目路径"`，其中路径先替换。Enter 发送，Shift+Enter 换行；不生效时查看 /help 或 /terminal-setup。

## 3.2 第一次只做调查

选择一个自己了解的小项目，要求助手说明入口、主要模块、依赖和测试命令，并为结论给出文件位置。此阶段使用只读权限，明确不运行未知安装脚本。对照目录和源码核查答案，未找到测试时应如实报告，不编造命令。

## 3.3 文件引用与命令输入

输入 @ 后从列表选择实际存在的文件，追问某个函数的输入、输出和调用方。不要照抄示例中的 src/main.py，当前项目可能没有它。

CLI 2.0 的输入框支持以 ! 进入 Shell 命令模式，例如 !pwd（PowerShell 环境可用 !Get-Location）；它会执行真实命令。先读命令与当前目录，别把查看环境变量变成打印全部凭据。自然语言请求执行命令同样受实际权限约束。

## 3.4 先掌握少量斜杠命令

| 用途 | 入口 |
| --- | --- |
| 帮助、状态 | /help、/status |
| 新任务 | /new |
| 历史会话 | /resume |
| 长上下文 | /compact、/context |
| 模型与权限 | /model、/permissions |
| 代码差异与审查 | /diff、/review |

先用 /status 检查，再用 /new 开始另一项小调查。旧文档中的 /clear、--resume、--session-id 不作为本课程 2.0 的必需入口；当前会话恢复使用已在 2.0 文档列出的 /resume。

## 3.5 图片和恢复后的验收

支持图片输入的终端可用 Cmd+V／Ctrl+V 粘贴截图，先遮挡敏感内容。识别小票后先给出拟录入字段，由你核对金额和日期，不直接写入真实账本。

恢复会话后先重新检查 git status、目录和现有测试。会话记忆不是当前文件状态；/fork 也不自动创建 Git worktree。试验回退先在副本进行：2.0 文档的 /rewind 会回退对话与工作区，使用前先保存要保留的改动，之后检查 diff。

## 3.6 信任目录

首次打开项目可能询问信任。项目配置、规则和 Hook 可影响执行行为，陌生仓库先检查这些文件。下一章从自己的新项目开始，固定账本接口后再让助手实施。

参考：[2.0 基础用法](https://docs.trae.cn/cli_basic-usage)、[2.0 斜杠命令](https://docs.trae.cn/cli_slash-command)。
