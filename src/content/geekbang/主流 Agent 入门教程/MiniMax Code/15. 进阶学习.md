# 15. 进阶学习

> 来源：[MiniMax Code](https://time.geekbang.org/space/wiki/MiniMax_Code_Tutorial)

## 把长任务交给 MiniMax Code 先明确完成标准

如果 AI 能连续工作，把一个多步骤任务做完，我们是不是就能少盯一会儿屏幕？

学到 MiniMax Code 的目标模式时，你可能会有这样的期待。知识库中的 habitlog 命令行工具，也让你开始尝试把功能开发、测试和修复交给 Agent 持续推进。

不过，任务越长，越需要提前说清楚：做到什么程度算完成，遇到什么情况应该停下来。

## 长任务 从一份验收清单开始

假设你想给 habitlog 增加金额记录功能。“支持记录金额”背后，至少有四类要求需要说清楚。

![原文图片](../../assets/d5693ca0f20488f22d92.png)

例如，可以约定保留两位小数，非法输入不给保存，历史记录仍能读取，再明确汇总规则。具体规则由需求决定；关键是把它们变成能重复检查的步骤。

测试覆盖了哪些情况、实际运行得到了什么结果，也应留下记录。知识库里的项目约定、测试和状态管理，可以帮助你开始关注任务完成的证据。

## 给持续执行 留几个检查点

长任务推进到中途，经常会遇到接口变化、测试失败或修改范围扩大。可以先约定几个停下来检查的地方。

![原文图片](../../assets/d6daf332f27c762582e1.png)

检查点的作用，是让问题在小范围内暴露。发现偏离预期时，先判断原因，再决定继续修复还是重新拆分任务。

如果多个 Agent 并行工作，还要先约定共享接口和各自修改的文件。分别完成以后，仍需要检查合并结果和整体测试。

## 继续练习复杂项目中的协作

《企业级 AI 编程实战营》可以承接这一阶段的学习。

课程以 Claude Code 为主要实践工具，包含任务拆解、多 Agent 协作、独立工作区隔离、权限控制， 以及自动化验证。它提供的是复杂项目中的开发组织方法，适合已经能完成小任务、希望进一步练习长任务的学习者。

其中，分布式延时投递项目会涉及多个模块的协作、测试和故障处理；OryxOS 项目还会练习运行环境、模型路由，以及成本和错误的追踪。

你可以带着一个曾经“越改越大”的任务，看看课程如何安排边界、协作和验收，再判断它是否能补上自己目前的短板。
