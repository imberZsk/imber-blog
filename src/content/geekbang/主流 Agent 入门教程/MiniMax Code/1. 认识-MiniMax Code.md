# 1. 认识-MiniMax Code

> 来源：[MiniMax Code](https://time.geekbang.org/space/wiki/MiniMax_Code_Tutorial)

> 这一章不写一行命令，只回答一个问题：MiniMax Code 是什么、能做什么、你应该选哪种形态。  
> 学完这一章，你会知道接下来的章节为什么以 CLI 为主、桌面端为什么放在最后一章。

## 1.1 一句话定位

**MiniMax Code 是 MiniMax 出品的 AI 编程 Agent**，由 Mavis 这个核心 Agent 驱动，可以直接读你的代码、改文件、跑命令、跑测试、提交改动 —— 不是陪你聊天的机器人，而是能动手干活的同事。

它的关键能力是把"自然语言描述"变成"在仓库里实际发生的变化"。你可以告诉它"重构这个模块，并保证现有测试通过"，它会自己去读代码、看测试、动手改、改完跑一遍验证。

## 1.2 它能做什么

按用途分，MiniMax Code 主要能干这六类事：

| 能力 | 你可以做什么 | 本教程对应章节 |
| --- | --- | --- |
| 仓库协作 | 读懂项目结构、搜索/修改文件、跑命令、看 diff、执行测试 | 第 4–7 章 |
| 多轮任务与 Session | 创建、暂停、恢复、分叉、回退、压缩、导出会话 | 第 10 章 |
| 计划与权限 | 先讲方案再动手；逐项确认或全权委托 | 第 5、6 章 |
| 模型与 Provider | 用官方 Token Plan、自带 API Key（BYOK）或自建 Provider | 第 13 章 |
| 扩展能力 | 用 Skills 让 Agent 学工作流、用 MCP 连外部数据、用 Plugin 打包 | 第 8 章 |
| 自动化与集成 | 用 Headless 模式接 CI、用 ACP 协议接入编辑器 | 第 11、12 章 |

不在 MiniMax Code 能力范围内的事：

- 不能直接连到你公司的 VPN、内网服务才执行代码
- 不是 IDE（集成开发环境）；不会取代 VS Code / JetBrains 写代码本身
- 不是云端运行环境；本教程所有项目都跑在你本地

## 1.3 产品形态与适用场景

MiniMax Code 有五种使用入口，按使用强度从低到高大致排一下：

### 1. CLI（终端命令 `mcode`）

- **入口**：在终端里跑 `mcode` 进入交互式 TUI（Text-based User Interface，文本用户界面），或 `mcode exec` 进入 Headless 模式（无交互、纯输出结果）
- **适合**：写代码、改脚本、跑命令、接 CI（持续集成）、做自动化
- **不擅长**：看 HTML 渲染、做视频/图片预览

### 2. Desktop（Electron 桌面客户端）

- **入口**：从官方下载安装的图形应用，左侧对话，右侧内置浏览器/文件/画布面板
- **适合**：不习惯终端的人、需要看渲染、做多媒体生成、远程控制（手机扫码接管）
- **不擅长**：写 CI 脚本、批处理

### 3. Web / H5（在线版）

- **入口**：浏览器即开即用
- **适合**：临时用一下、不想装客户端
- **不擅长**：连本地仓库（除非配工作区）

### 4. ACP 编辑器接入（通过 `mcode acp`）

- **入口**：在 VS Code / JetBrains / Zed 等支持 ACP（Agent Client Protocol，Agent 客户端协议）的编辑器里调起 Agent
- **适合**：不想离开编辑器的人
- **不擅长**：编辑器不支持 ACP 协议时

### 5. IM 接入（微信 / 飞书 / Telegram）

- **入口**：在聊天软件里发指令，让远端的桌面端 Agent 干活
- **适合**：移动端、远程控制
- **不擅长**：需要本地文件系统的精细操作

## 1.4 你应该选哪种形态

本教程的设计选择是：**前 13 章以 CLI 为主线**，最后一章（第 14 章）单独讲桌面端概览。理由是：

- CLI 是最完整的形态，所有能力都通过它暴露
- CLI 强迫你养成清晰的输入/输出习惯，便于调试、自动化、复用
- CLI 的每一步操作都能写在文档里重现，桌面端图形界面则难以脱离截图讲清楚

如果你的使用场景不重合，可以这样调整阅读路径：

| 你的身份 | 推荐阅读路径 |
| --- | --- |
| 程序员 / DevOps（运维工程师）/ SRE（站点可靠性工程师） | 全部 14 章，第 11、12 章重点看 |
| 后端 / 数据 / 算法工程师 | 全部 14 章，第 8、13 章重点看 |
| 不太碰终端的产品 / 设计 | 先看第 1 章、第 14 章，CLI 部分按需挑选章节 |
| 完全不会写代码 | 从第 14 章桌面端入手，再决定要不要补 CLI |

## 1.5 中国区 vs Global 区

MiniMax Code 在不同地区有不同的账号体系和文档入口。本教程以\*\*中国大陆账号（`region: cn`）\*\*为默认：

- 登录命令：`mcode login`
- 文档入口：`https://agent.minimaxi.com/docs/`

如果你使用 Global 账号：

- 登录命令：`mcode login --region global`
- 文档入口：`https://agent.minimax.io/docs/`

本教程后续所有命令、配置示例都基于中国区。Global 账号的差异会在必要时单独标注。

## 1.6 本章小结

- MiniMax Code 是一个能读代码、改文件、跑测试、提交改动的 AI 编程 Agent
- 它有 CLI、Desktop、Web、ACP、IM 五种形态，覆盖不同使用强度
- 本教程以前 13 章讲 CLI、最后 1 章讲桌面端
- 默认针对中国大陆账号，Global 账号用法略有差异
