# 4. macOS安装

> 来源：[DeepSeek Harness](https://time.geekbang.org/space/wiki/DSH_Tutorial)

> 本文属于《DeepSeek Harness 入门教程（实战版）》· 第二部分 · 安装并完成第一次启动

# 第 4 章　macOS 安装

这一章提供两条路线：

- 想尽快开始，安装 **DeepSeek Harness 桌面端**；
- 明确需要 Headless、自定义 Profile 或命令行环境，安装 **CLI/Web**。

两条路线任选其一即可。不过，「日报助手」是一个 Node.js 项目，即使你选择桌面端，也要在本章最后确认系统终端能够运行 Node.js。

## 4.1 先确认 Mac 的处理器架构

点击屏幕左上角的苹果菜单，打开“关于本机”，查看“芯片”或“处理器”：

- 显示 Apple M 系列芯片，选择 **Apple Silicon / arm64** 安装包；
- 显示 Intel，选择 **Intel / x64** 安装包。

也可以在“终端”中执行：

```
$ uname -m
```

输出 `arm64` 表示 Apple Silicon，输出 `x86_64` 表示 Intel。下载错误架构的安装包，常见结果是无法启动或直接提示不兼容。

## 4.2 推荐路线：安装桌面端

### 第一步：从官方发布页下载

打开 [DeepSeek Harness 官方 Releases 页面](https://github.com/deepseek-ai/deepseek-harness/releases)，进入本教程基线版本 `v0.1.7-rc.2` 或更新的正式发布项，在 Assets 中选择与你的 macOS 架构匹配的安装包。

版本仍处于快速迭代期，文件名和可用架构可能变化，所以不要照抄第三方文章里的旧下载地址。只从 DeepSeek 官方页面或 `deepseek-ai/deepseek-harness` 官方仓库获取安装包。

### 第二步：安装应用

下载完成后：

1. 双击下载的 macOS 安装包；
2. 如果看到应用图标和“Applications”文件夹，把 DeepSeek Harness 拖入“Applications”；
3. 打开“应用程序”，双击 DeepSeek Harness；
4. macOS 第一次提示“这是从互联网下载的应用”时，确认来源无误后选择打开。

如果系统提示应用损坏、签名异常或开发者无法验证，先停止操作，重新确认文件来自官方发布页并重新下载。不要一上来就执行网上流传的 `xattr`、关闭 Gatekeeper 或其他绕过系统验证的命令。

### 第三步：完成首次启动引导

应用第一次启动时会进入欢迎与初始化流程。当前版本会引导你了解可用额度、选择主要用途，以及设置工作过程显示的详细程度；中途关闭后可以继续完成。[v0.1.7-rc.2 更新说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-rc.2)

这一章只确认应用能够启动，不必急着研究所有选项：

1. 按欢迎页提示继续；
2. 遇到账号或 API Key 选择时，可以完成登录，也可以选择稍后配置；
3. 进入主界面后，确认左侧出现工作区区域，中间出现空白会话或新任务入口；
4. 如果系统要求选择目录，暂时选择第3章准备的 `daily-report` 空目录。

全新安装会创建默认工作区和空白会话，因此没有立刻出现文件夹选择器也属于正常情况。第7章会重新确认工作区，再发送第一条真正的任务。

### 第四步：核对版本

在 macOS 顶部菜单栏打开“DeepSeek Harness”菜单，选择“关于 DeepSeek Harness”，确认能够看到当前安装版本。

版本可以比教程的 `v0.1.7-rc.2` 更新，但如果跨度较大，后续按钮名称可能不同。遇到差异时，先阅读安装版本对应的发布说明。

## 4.3 桌面端关闭以后，任务是否还在运行

macOS 左上角的红色窗口按钮只是关闭窗口，不等于退出应用。当前版本中，关闭桌面窗口后，正在执行的任务可以继续在后台运行；真正退出应用前，系统会提示对运行中任务的影响。[v0.1.7-rc.2 更新说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-rc.2)

可以用下面的方法判断：

- Dock 中应用图标下仍有运行标记：应用通常还在后台；
- 再次点击图标，原工作区和会话重新出现：说明刚才只是关窗；
- 使用菜单栏“DeepSeek Harness → 退出 DeepSeek Harness”或按 `Command + Q`：才是退出应用。

以后执行长任务时，不要因为窗口关闭就立刻重复提交同一任务；先重新打开应用查看原任务状态。

## 4.4 CLI/Web 路线：先准备 Node.js

如果你选的是桌面端，可以先跳到 4.6；如果选择 CLI/Web，Node.js 必须满足 DSH 当前要求：`^22.19.0` 或 `>=24.0.0`。

### 方式 A：Node.js 官方安装包

对只需要一个 Node.js 版本的初学者，这是最直接的方式：

1. 打开 [Node.js 官方下载页](https://nodejs.org/en/download)；
2. 选择 macOS 安装包；
3. 选择符合 DSH 要求的 Node.js 22 LTS，并确认版本不低于 22.19.0；
4. 双击 `.pkg`，按安装向导完成；
5. 关闭并重新打开“终端”。

### 方式 B：nvm

如果你的其他项目还依赖不同 Node.js 版本，使用 [nvm 官方仓库](https://github.com/nvm-sh/nvm)给出的最新安装方法。nvm 生效后执行：

```
$ nvm install 22
$ nvm use 22
$ nvm alias default 22
```

`nvm install 22` 会安装当前可用的 Node.js 22.x。安装后仍要检查实际小版本是否满足要求。

### 验证 Node.js

重新打开终端，执行：

```
$ node -v
$ npm -v
```

示例结果：

```
v22.19.0
10.x.x
```

具体 npm 版本不必与示例相同。关键是两条命令都存在，并且 Node.js 满足版本范围。

## 4.5 CLI/Web 路线：启动 DSH

第一次体验建议直接使用 npx，不必全局安装：

```
$ npx @deepseek-ai/dsh@0.1.7-rc.2 web
```

首次运行会下载官方 npm 包。终端随后应打印本地访问地址，并自动打开默认浏览器；默认地址通常是：

```
http://127.0.0.1:3080
```

页面能打开并显示 DSH 主界面，说明 CLI/Web 已经可以使用。此时不要关闭运行命令的终端，否则 Web 服务会停止。

如果不希望自动打开浏览器，可以使用：

```
$ npx @deepseek-ai/dsh@0.1.7-rc.2 web --no-open
```

需要长期使用 `dsh` 短命令时，可以在 nvm 管理的 Node.js 环境中安装：

```
$ npm install -g @deepseek-ai/dsh
$ dsh --version
$ dsh web
```

不要用 `sudo npm install -g ...` 解决权限错误。它容易在 npm 缓存和全局目录中留下 root 所有的文件。出现 `EACCES` 时，优先使用 nvm，或者继续用无需全局安装的 npx 路线。

## 4.6 为日报助手准备 Node.js

如果你选择桌面端，DSH 本身已经能运行，但还需要检查练习项目能不能运行。

打开 macOS“终端”，执行：

```
$ node -v
$ npm -v
```

- 有符合要求的版本：可以继续；
- 找不到命令：按 4.4 安装 Node.js；
- 版本较旧：使用官方安装包或 nvm 升级。

桌面端内置的私有 Node.js 不会自动进入 Agent Shell 的 `PATH`，所以不能用“应用能打开”代替这一步验证。

然后在 Finder 中建立以下空目录，或者使用你自己的等价位置：

```
文稿/dsh-learning/daily-report
```

确认目录中没有私人文件、密钥或其他项目。第7章会把它添加为工作区。

## 4.7 常见问题

| 现象 | 先检查什么 | 处理方法 |
| --- | --- | --- |
| 桌面应用无法打开 | 安装包来源与芯片架构 | 从官方 Releases 重新下载匹配架构的安装包，不要先关闭系统安全校验 |
| 关闭窗口后 Dock 仍显示运行 | 只是关窗，没有退出 | 需要彻底停止时用应用菜单退出或按 `Command + Q` |
| `node: command not found` | 系统 Node.js 未安装或终端未刷新 | 安装后重开终端；使用 nvm 时确认 shell 初始化已生效 |
| `npm install -g` 报 `EACCES` | npm 全局目录权限不属于当前用户 | 改用 nvm 或 npx，不要使用 `sudo npm` |
| npx 下载失败 | 包名或 npm 网络 | 确认包名是 `@deepseek-ai/dsh`，保留完整报错并检查 npm 连接 |
| 浏览器没有自动打开 | 自动打开被系统阻止 | 手动打开终端打印的地址；或检查命令是否仍在运行 |
| 端口 3080 被占用 | 本机已有服务使用该端口 | 根据 `dsh web --help` 查看当前版本的端口选项，再换一个未占用端口 |

## 4.8 完成检查

选择桌面端时：

- DeepSeek Harness 能从“应用程序”正常打开；
- “关于 DeepSeek Harness”能显示版本；
- 主界面能显示工作区和会话区域；
- 系统终端中的 `node -v` 与 `npm -v` 可用。

选择 CLI/Web 时：

- Node.js 版本满足要求；
- `npx @deepseek-ai/dsh@0.1.7-rc.2 web` 能启动；
- 浏览器能打开终端打印的本地地址；
- 关闭该终端进程后，Web 页面停止连接。

macOS 用户可以跳过接下来的 Linux 和 Windows 安装章节，直接前往第7章创建日报助手。
