# 实战课

### 从会用一套 Harness，到能自己选一套 Harness

最近整理了一套《DeepSeek Harness 入门教程（实战版）》知识库。

写完之后的感受是：Agent 工具的学习，难点从来不在“装上”，而在“敢不敢用它做真事”。

这套知识库围绕一个叫「日报助手」的小项目展开，从空目录开始，一路做到能运行、能测试、能审查、能 Headless 自动化。

它没有堆概念，而是把 DSH 拆成五层——模型与 Provider、Agent 预设、插件、Profile、交互入口 ——然后让读者在每一层都留下可检查的证据：文件、diff、测试输出、退出码、配置 dump、子会话轨迹。

它反复强调一件事

Agent 说“完成了”不算完成，系统终端里的结果才算。

所以这套知识库适合谁？

适合已经决定要用 Agent 做点真事、但不想停留在“聊聊天、生成一段代码”的人。

它教的是怎么选工作区、怎么控权限、怎么看审批、怎么用 Skill 固化方法、怎么用 MCP 接外部工具、怎么让子智能体并行审查、怎么让一个长目标跨多轮推进、怎么在 Headless 里跑自动化。

学完一遍，你至少能独立判断：这次任务该用哪个预设、权限开到哪一档、出了问题先查哪一层。

但它也有一件事没有解决

它解决的是“把 DSH 这一套 Harness 用起来”。

它不解决“如果我想自己选一套 Agent 脚手架、自己搭一个能上业务的项目，应该怎么选、怎么拆、 怎么交付”。

这两件事之间，其实隔着一层很实际的坎：

你已经会用一个 Harness 了，但换一个框架、换一个业务场景，你还能不能独立选型、独立搭起来？

比如同样是 Harness 思路，Smolagents、Claude Agent SDK、DeepAgents、Pi-Mono 各自适合什么场景？

数据洞察、投研、知识库、合同审查这些真实业务，Agent 项目应该怎么拆、怎么编排、怎么把安全和交付边界做进去？

这就不是单靠一套 DSH 教程能覆盖的了。

如果你正好走到这一步

可以看看邢云阳老师的专栏《Harness Agent 脚手架实战课》。

它沿着 Smolagents、Claude SDK、DeepAgents、Pi-Mono 四条路线，把数据洞察、投研、知识库、 合同审查四个场景从头到尾做了一遍。

重点不是再教你一个工具，而是帮你建立一套可迁移的 Agent 工程判断——框架选型、业务流重构、 合规安全交付，这些在一个具体项目里是绕不开的。

![原文图片](../../assets/d973a9113f04b79ad846.png)

不用急着现在决定

先把这套知识库的项目验收做完。

等你真正开始想“下一个 Agent 项目我要自己选型”的时候，再去翻它，可能会更顺。

会用一套，是入门；能选一套、搭一套、交付一套，才是工程能力。
