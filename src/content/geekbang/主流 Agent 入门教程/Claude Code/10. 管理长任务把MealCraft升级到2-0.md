# 10. 管理长任务把MealCraft升级到2-0

> 来源：[Claude Code](https://time.geekbang.org/space/wiki/Claude_Code_Tutorial)

> 预计用时：90～140 分钟，可分两次完成  
> 本篇目标：用固定规范和测试把 MealCraft 分四阶段升级到 2.0，并实际练习命名、恢复、压缩、对话分支、后台会话和磁盘交接。

长任务的可靠性不来自“一次聊天记住全部细节”，而来自可重复的输入、阶段提交、测试结果和磁盘台账。会话可以退出、压缩甚至更换；`MEALCRAFT_2_SPEC.md`、`UPGRADE_PLAN.md`、Git 和测试才是事实来源。

本篇仍是个人本地项目，不引入数据库、账号、云部署或多人协作系统。

## 开始状态

从完成第 9 篇并已提交的 MealCraft 项目开始。

macOS、Linux 或 WSL2：

```

git status --short
python3 scripts/verify_project_instructions.py

```

Windows PowerShell：

```
Set-Location "$HOME\claude-code-course\mealcraft"
git status --short
py scripts/verify_project_instructions.py
py -m unittest discover -s tests -v
```

预期工作区为空，项目说明检查通过，旧套件 13 项全部通过。若还有未提交修改，先辨认并保存，不要把未知改动混入 2.0。

检查本机能力：

```

claude --help
```

进入一次会话并运行 `/help`。本篇会用 `/rename`、`/compact`、`/branch`、`/resume`、`/fork` 和 `/background`，以及外部终端中的 `claude agents`、`attach`、`logs`、`stop`。命令是否显示取决于版本、平台和环境；若缺少后台会话命令，先按第 2 篇升级并重查。升级后仍不可用时，可以完成 2.0 主线，把后台练习标为“本机不可用”，不要猜旧命令的行为。

## 四、用 `/branch` 安全比较一个想法

`/branch` 会从当前位置创建对话分支，并把当前终端切到新分支；原对话仍保留，可从 `/resume` 返回。它分的是对话，不自动建立 Git 分支。

```
/branch report-layout-notes
```

在对话分支里只做讨论：

```
不要调用工具，也不要修改文件。比较“按天列菜单”和“按食材分类优先”两种个人周菜单版式；依据 MEALCRAFT_2_SPEC.md 说明为什么本练习应保留按天版式，不要新增需求。
```

讨论结束后运行 `/resume`，在选择器中回到 `mealcraft-2-upgrade`，再检查：

```
git status --short
```

应没有由讨论产生的文件修改。若已经编辑文件，先看实际 Diff；不要以为切回原对话会自动还原磁盘。


## 九、用 `/fork` 启动独立只读审计

当前 `/fork` 会复制当前对话到新的后台会话，原会话继续留在当前终端；它与 `/branch` 的“切换到对话分支”不同。输入：

```
/fork 只读审计 MealCraft 2.0：核对固定规范、测试覆盖、UPGRADE_PLAN.md 和 git diff；运行允许的本地检查，但不要编辑、提交、推送或访问网络。最后列出最多 5 个有证据的问题；没有问题就明确写未发现阻塞项。
```

在另一个终端，从 MealCraft 根目录查看独立会话。

macOS、Linux 或 WSL2：

```
claude agents --json --cwd "$PWD"
```

Windows PowerShell：

```
claude agents --json --cwd $PWD.Path
```

输出中的短 `id` 用于管理。下面的 `<id>` 必须替换，不能原样执行：

以下为参数模板，执行前先将尖括号占位符替换为实际值：

```
claude logs <id>
claude attach <id>
```

附加后可以回复审计问题；输入 `/exit` 只是再次脱离，后台会话仍可继续。只有明确要终止仍在运行的会话时才执行：

以下为参数模板，执行前先将尖括号占位符替换为实际值：

```
claude stop <id>
```

`claude agents` 负责独立后台会话；当前会话内的 `/tasks` 主要列出该会话自己的后台任务和 Subagent，不是同一个列表。

## 十、练习 `/background` 与 shell 启动方式

`/background`（别名 `/bg`）把当前整个会话脱离终端继续运行。选择没有写入需求的停点，输入：

```
/background 只读检查 Stage 4 验收项和当前 Git Diff；不要修改、提交或推送。检查完等待我的下一条消息。
```

终端返回后，用 `claude agents` 找到它，再用 `attach` 回去。这验证了“会话离开终端仍由本机后台服务托管”。后台会话在本机运行、消耗正常用量；电脑关机后不会继续，等待权限确认时也可能停住。

也可以从 shell 直接启动一个新的只读后台会话：

```
claude --bg --name mealcraft-2-audit "只读运行 MealCraft 2.0 完整测试并报告结果；不要修改、提交、推送或访问网络"
```

提示文本是位置参数，不能把 `--bg` 与 `-p` 混用。启动成功会打印短 ID，以及 `agents`、`attach`、`logs`、`stop` 命令。Git 仓库中的后台会话在需要编辑前通常会进入隔离 worktree；本篇审计明确只读，因此不应产生新代码。不要关闭 worktree 隔离来省步骤。

后台会话是完整、可独立恢复和附加的 Claude Code 会话。第 13 篇的 Subagent 则由主会话为局部任务派生，使用独立上下文，并把结果汇报回主会话。个人项目中，先用单会话分阶段；只有确实可独立的只读审计才值得并行。

## 关键排错

**恢复到了错误会话**：先退出，确认当前目录，再用 `claude --resume` 按名称选择。恢复后先查 Git 和台账；不要根据聊天标题判断代码状态。

**`/branch` 后文件也变了**：对话分支不是文件快照。查看 `git diff`，用已提交阶段作为恢复依据；不要盲目回滚用户自己的改动。

**后台会话一直 blocked**：运行 `claude logs <id>` 或 `attach`，通常是权限问题、需要澄清或测试失败。给出最小必要回复，不要改成 `bypassPermissions` 绕过安全设置。

**`claude agents` 找不到刚启动的会话**：去掉 `--cwd` 查看全部活动会话，核对启动目录；若后台服务无响应，先运行 `claude daemon status`，再按官方 Agent view 的故障步骤处理。

**完整测试数量不是 23**：检查三个固定测试文件是否都在 `tests/`，并确认没有用 `-p` 过滤完整套件。不要以聚焦测试代替全量回归。

**生成命令找不到 `mealcraft`**：必须从项目根目录运行，并确认脚本把项目根目录加入导入路径；参考覆盖层包含这一处理。

## 本篇小结
