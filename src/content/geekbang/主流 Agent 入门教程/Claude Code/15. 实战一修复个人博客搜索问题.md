# 15. 实战一修复个人博客搜索问题

> 来源：[Claude Code](https://time.geekbang.org/space/wiki/Claude_Code_Tutorial)

> 预计用时：55～75 分钟  
> 本篇目标：在一个陌生但固定的个人博客项目中，先用测试和页面稳定复现异步竞态，再比较请求编号与 `AbortController` 两种方案，只修改一个控制器文件完成最小修复。

前 14 篇一直围绕 MealCraft。本篇开始验证迁移能力：换成一个原生 HTML、CSS、JavaScript 的个人博客，没有框架、后端或企业流程。你已经知道如何调查、规划、控制权限、查看 Diff 和独立验收；现在要证明这些方法不依赖 MealCraft 的目录结构。

原稿让 Claude 临场生成 20 篇文章和一个“可能存在”的竞态。不同读者会得到不同代码，后续步骤无法共享同一个失败。本篇改用课程固定夹具：请求延迟、失败名称、可修改文件和成功条件都确定；你仍然负责让 Claude 调查、比较方案并实施修复。

## 开始状态与额外前置

这个练习不修改 `mealcraft/`。需要：

- Claude Code、Git 与 Python 3.11+ 仍可用；
- Node.js 的受支持 LTS 版本可用；截至 2026-09-30，官方列出的 LTS 主版本是 22 和 24；
- `~/claude-code-course/blog-search-lab` 尚不存在；
- 知道修订版教程目录的实际位置。

先检查运行时：

```
claude --version
git --version
python3 --version
node --version
```

Windows PowerShell 把 `python3` 换成 `py`。若 `node` 不存在或版本已停止支持，从 [Node.js 官方下载页](https://nodejs.org/en/download) 安装当前 LTS，重新打开终端后再检查。练习不执行 `npm install`，也不下载第三方包；Node 只用于运行实际 JavaScript 控制器的固定测试。

## 一、从课程素材建立独立仓库

把课程目录占位符替换成你的实际路径。

macOS、Linux 或 WSL2：

```
export COURSE_SOURCE="/替换为实际路径/claude-code-tutorial-v0.2"
export BLOG_SOURCE="$COURSE_SOURCE/exercise-assets/blog-search-lab"
test -f "$BLOG_SOURCE/scripts/verify_blog_lab.py"
cd ~/claude-code-course
test ! -e blog-search-lab
mkdir blog-search-lab
cp -R "$BLOG_SOURCE/." blog-search-lab/
cd blog-search-lab
git init
```

Windows PowerShell：

```
$CourseSource = "C:\替换为实际路径\claude-code-tutorial-v0.2"
$BlogSource = "$CourseSource\exercise-assets\blog-search-lab"
if (-not (Test-Path "$BlogSource\scripts\verify_blog_lab.py")) { throw "博客素材路径错误" }
Set-Location "$HOME\claude-code-course"

New-Item -ItemType Directory blog-search-lab | Out-Null
Copy-Item "$BlogSource\*" -Destination blog-search-lab -Recurse
Set-Location blog-search-lab

```

先核对素材布局和不可修改文件的哈希：

python3 -B scripts/verify_blog_lab.py --layout-only

Windows PowerShell：

```

## 二、用命令行稳定复现三个竞态

直接运行测试：

```
node tests/run-tests.mjs
```

这次命令应以非零状态退出。稳定结果是 7 项中 4 项通过、3 项失败：

```
FAIL latest_query_wins: ...
FAIL clearing_query_invalidates_pending_response: ...
FAIL stale_error_does_not_replace_latest_success: ...
PASS current_error_is_reported
PASS chinese_query_filters_posts
PASS english_query_filters_posts
PASS empty_query_returns_no_posts
SUMMARY total=7 passed=4 failed=3
```

失败文字中的 JSON 细节是诊断信息，稳定判定条件是三个失败名称和 `total=7 passed=4 failed=3`。这证明问题不只是“慢请求覆盖快请求”：清空输入也可能被旧结果覆盖，旧请求的错误也可能覆盖新请求的成功。

再让课程检查器确认这正是预设缺陷，而不是别的语法错误。

macOS、Linux 或 WSL2：

```
python3 -B scripts/verify_blog_lab.py --expect-bug
```

Windows PowerShell：

```
py -B scripts\verify_blog_lab.py --expect-bug
```

预期：

```
PASS layout: 20 posts and immutable fixture hashes
PASS bug state: 7 tests, 3 expected race failures
```

检查器会真实运行 JavaScript 测试，并要求目标控制器与缺陷基线一致。它不会把“任意测试失败”误判为成功复现。

## 三、在页面中看见用户影响

从练习根目录启动只监听本机回环地址的静态服务器。

macOS、Linux 或 WSL2：

```
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows PowerShell：

```
py -m http.server 8000 --bind 127.0.0.1
```

在普通浏览器打开 `http://127.0.0.1:8000/`，点击“运行确定性竞态”。页面会先发起耗时 220 ms 的 `JavaScript` 搜索，10 ms 后把输入改为 `CSS` 并发起耗时 35 ms 的搜索。

缺陷态的稳定现象是：输入框最后显示 `CSS`，状态和列表却在稍后变回 `JavaScript` 的结果。记录这个现象后回到终端按 `Ctrl+C` 停止服务器。

如果直接双击 `index.html`，浏览器可能因 `file://` 模块限制而拒绝加载 JavaScript；这不是目标缺陷，必须通过上面的 HTTP 地址访问。若 8000 端口已占用，换成 8001，并相应修改浏览器 URL。

## 四、让新会话先调查，不要立即改

在仓库根目录以 Plan Mode 启动一个全新 Claude Code 会话：

```
claude --permission-mode plan
```

发送：

```
这是一个我刚接手的个人博客搜索项目。先只读调查，不要修改文件。

请完成：
1. 阅读 README.md、src/app.js、src/api.js、src/search-controller.js 和 tests/run-tests.mjs；
2. 运行 node tests/run-tests.mjs 和适合缺陷态的课程检查器；
3. 追踪“输入 -> 控制器 -> 异步搜索 -> 渲染”的数据流；
4. 对三个失败分别说明请求开始顺序、完成顺序、预期最后事件和实际最后事件；
5. 给出最小根因，指出哪些文件是固定证据、哪个文件允许修改。

每个结论引用文件路径或测试输出。不要提出重写框架，也不要修改任何文件。
```

合格的调查应能解释：`runSearch` 每次调用都独立等待结果，却没有记录“这还是不是当前查询”；所以 UI 的最终状态取决于响应完成顺序，而不是用户输入顺序。

仅仅增加 debounce（防抖）不能证明修复。防抖可以减少请求数量，但一旦两个请求都已发出，它仍不能阻止旧响应晚到后覆盖新结果。

## 五、用当前项目证据比较两种最小方案

继续保持 Plan Mode，发送：

```
暂时不要修改。请只比较以下两种方案：

A. 在 createSearchController 内递增请求编号，只允许最新编号渲染结果或错误；
B. 在 createSearchController 内保存 AbortController，新查询开始时取消旧查询，并正确忽略 AbortError。

请基于当前 src/api.js 是否接受 signal、三个失败覆盖什么行为、改动文件数量、旧工作的资源消耗和错误处理，推荐一种方案。两种机制不要叠加。最终修复必须只改 src/search-controller.js，并让已有测试证明结果。
```

两种方案都能通过固定测试，但取舍不同：

| 方案 | 优点 | 代价与前提 |
| --- | --- | --- |
| 递增请求编号 | 改动最小；即使底层不能取消也能阻止旧结果渲染 | 旧搜索仍会继续消耗少量工作 |
| `AbortController` | 底层支持 `signal` 时可尽早停止旧工作 | 必须把 `signal` 传给搜索函数，并只忽略 `AbortError`，不能吞掉当前请求的真实错误 |

本夹具的 `src/api.js` 已支持可选 `signal`，因此两种都成立。对这个 20 篇文章的本地假 API，请求编号通常是更小、更容易解释的修复；选择 `AbortController` 也可以，但理由应是取消能力，而不是“代码更新”。

## 六、只批准一个文件的最小修复

确认计划有以下四点后再离开 Plan Mode：

- 新查询必须让旧查询失去渲染资格；
- 清空输入也必须使在途查询失效；
- 旧请求错误不能覆盖新成功，当前请求错误仍要显示；
- 不修改 API、页面接线、文章数据、测试、baseline 或校验器。

按 `Shift+Tab`，直到状态栏回到 Manual 模式。然后发送：

```
按刚才推荐的单一方案实施最小修复，只允许修改 src/search-controller.js。

不要修改 tests、src/api.js、src/app.js、data、baseline、README 或检查器；不要增加依赖、固定延迟、防抖或第二套竞态机制。

修改后运行 node tests/run-tests.mjs。若仍失败，先解释失败证据再继续；全部通过后停止，不要提交 Git。
```

权限提示中的写入目标必须只有 `src/search-controller.js`。如果 Claude 要改测试来适配实现、延长延迟“让结果稳定”，或同时叠加请求编号和取消机制，拒绝并要求回到已批准范围。

预期测试变为：

```

PASS clearing_query_invalidates_pending_response
PASS stale_error_does_not_replace_latest_success
PASS current_error_is_reported
PASS chinese_query_filters_posts

## 八、做一次真实页面验收

重新启动静态服务器：

```
python3 -m http.server 8000 --bind 127.0.0.1
```

Windows 使用 `py`。在浏览器刷新页面，依次验证：

1. 点击“运行确定性竞态”：输入框、状态和列表最终都应是 `CSS`；等待一秒也不能回到 `JavaScript`。
2. 搜索 `中文`：应至少出现“中文排版检查清单”。
3. 搜索 `javascript`：应出现多篇中英文结果。
4. 输入一个查询后立即清空：页面最终保持“请输入关键词”，旧结果不能回来。
5. 输入 `error`：当前请求的模拟失败必须显示，不能因为处理取消而吞掉全部错误。

完成后按 `Ctrl+C` 停止服务器。命令行测试控制精确时序，页面验收证明用户可见接线仍然工作；两类证据互相补充。

## 九、审查 Diff 并保存修复

如果仍在 Claude Code 会话，可用 `/diff` 查看变更；最终仍回到普通终端检查并提交：

```
git diff --check
git diff --stat
git status --short
git add src/search-controller.js
git commit -m "prevent stale blog search results"
git status --short
```

预期提交只含一个文件，最后工作区为空。请自己用一句话解释修复，而不是只复述实现：**用户当前查询是唯一可渲染的状态，先前查询即使更晚完成也必须失去更新 UI 的资格。**

## 十、失败恢复

### 初始测试不是恰好三个失败

先运行：

```
git status --short
python3 -B scripts/reset_blog_lab.py
python3 -B scripts/verify_blog_lab.py --expect-bug
```

Windows 把 `python3` 换成 `py`。重置脚本只覆盖 `src/search-controller.js`，不会清理其他文件或改写 Git 历史。若哈希检查仍失败，说明固定素材也被修改；查看 `git diff`，重新复制练习目录比盲目修测试可靠。

### 最新查询通过，但清空查询仍失败

这通常表示请求编号或取消动作发生在空字符串的提前返回**之后**。清空也是一次新的用户意图，必须先使旧请求失效，再渲染空状态。

### `AbortController` 方案吞掉当前错误

只忽略 `error.name === "AbortError"` 且属于已经取消的请求。`current_error_is_reported` 失败说明 catch 分支过宽，把真实服务错误也当成取消处理了。

### 浏览器仍显示旧结果，但测试全绿

先强制刷新，再在开发者工具 Network 中确认浏览器加载的是当前仓库的 `src/search-controller.js`。同时检查服务器的工作目录；如果从 `~/claude-code-course` 而不是 `blog-search-lab` 启动，URL 需要多一层路径，容易误看旧页面。

### 8000 端口被占用

改用：

```
python3 -m http.server 8001 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8001/`。不要结束一个来历不明的系统进程来抢端口。
