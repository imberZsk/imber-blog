# 19. 进阶学习

> 来源：[Claude Code](https://time.geekbang.org/space/wiki/Claude_Code_Tutorial)

## 你的 Claude Code，还停留在“会聊天的终端”吗？

同一个工具，有人用它改几行代码，有人用它跑通一条生产线。但大部分人卡在这三关：

第一关：上下文放哪里。

项目里总有几件事每次会话都得让 Claude 知道：测试命令是什么、源数据在哪、哪些目录不能碰。全塞进提示词，会话一长就被挤掉；什么都不写，它每次都要重新摸索。

正确做法是分两层： `CLAUDE.md` 保存每次都会用到的最小事实，路径 Rules 只在处理匹配文件时才加载。关键是验证它们真的生效——用 `/context` 看 Memory files，再开一个全新会话做只读提问。很多人写了却从没验证过，以为生效了，其实压根没加载。

第二关：动作怎么控。

提示词里写“请只读”，只是给模型的行为说明，不是强制边界。 `--allowedTools` 也不是工具白名单，它只让匹配的调用免去审批，不会把其他工具移出可用池。真正限制内置工具要用 `--tools`，而它又不控制 MCP。

再往下还有权限模式和 Sandbox。一个典型例子： `Edit(/data/recipes/**)` 能拒绝内置编辑工具改源菜谱，却管不住任意 Python 程序内部打开什么路径——真正需要阻止子进程越界时，得靠 Sandbox。

第三关：结果怎么证。

Claude 说“测试已经修好”，这只是模型的报告。你还要看到命令真的运行、退出结果符合预期，并确认测试调用了真实业务代码。单元测试、真实 HTTP 检查、浏览器人工操作，三层缺一不可。

### 当任务从“一次”变成“一直”

长任务的可靠性不来自“一次聊天记住全部细节”，而来自阶段提交、测试结果和磁盘台账。会话可以退出、压缩甚至更换，事实来源始终是磁盘上的规范和 Git 历史。

Subagent 的首要价值不是“多叫几个模型”，而是隔离上下文。一个只读审查 Agent，用工具白名单限制到 Read、Grep、Glob，把大量搜索结果挡在主会话之外，只把结构化结论带回来。但主 Agent 仍要亲自复核——报告只是线索，测试、哈希与 Git 才是文件没有越界的证据。

自动化则要纠正一个更危险的误区： `--allowedTools` 只免审批，不会移除工具。真正受限的自动化应拆成三段——本地确定性采集器产生事实，受限的 `claude -p` 只做映射，本地校验器负责验收。模型的“我完成了”不再是唯一信号。

### 这套方法，值得系统学一遍

上面这些，来自一套完整的 Claude Code 命令行实战教程。它用一个本地项目走完调查、规划、修改、测试、验收和自动化，再用三个独立练习检验你能否把方法迁移到别的项目。

但如果你想要的不仅是“跟着做完”，而是吃透背后的工程化思路——Skill、Subagent 怎么配合， 多 Agent 怎么编排，Hooks、MCP、Agent SDK 怎么在真实场景落地，Plugins 怎么打包分发——那么这套教程更像是地图，而系统性的课程是更完整的路线。

《Claude Code 工程化实战》，极客时间出品，作者黄佳（新加坡科研局资深研发工程师，前埃森哲新加坡公司资深顾问，入行 20 余年，著有《大模型应用开发 RAG 实战课》《大模型应用开发：动手做 AI Agent》等）。

课程用 7 讲子代理专题覆盖从核心概念到只读安全审计、日志分析、多任务并行和 Agent Teams；用 7 讲 Skills 专题讲透 `SKILL.md` 结构、触发机制、渐进式披露、与 SubAgent 配合；再用 4 讲核心机制拆开 Hooks、MCP 和 Tools 内核；最后 5 讲工程化进阶落到 Headless 与 CI/CD、Rules、Agent SDK 和 Plugins 打包分发。

从用户到开发者，从“会用”到“用得住”。
