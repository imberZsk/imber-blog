# 1. Claude Code到底是什么

> 来源：[Claude Code](https://time.geekbang.org/space/wiki/Claude_Code_Tutorial)

> 预计阅读时间：12 分钟  
> 本篇目标：建立一个不会误导后续操作的工作模型，分清模型、Claude Code CLI 和验证证据分别负责什么。

Claude Code 不是“会聊天的终端”，也不是收到一句需求就能保证交付正确结果的自动程序。它是运行在终端中的编码 Agent：模型负责理解和判断，Claude Code CLI 为模型提供读取文件、搜索、编辑和执行命令等工具，再把工具结果交还给模型继续决定下一步。

这套教程只使用终端中的 Claude Code CLI。桌面客户端、IDE 扩展和网页端不在课程范围内。

## 一次任务是怎样推进的

官方文档把核心过程概括为三个会反复交替的阶段：

```
收集上下文 -> 采取行动 -> 验证结果
      ^                       |
      +-------- 根据结果调整 --+
```

例如你提出：

```
找出菜谱份数换算错误，先补一个能复现问题的测试，再做最小修复，最后运行完整测试。
```

Claude 可能先搜索换算函数和现有测试，运行测试观察失败，再编辑文件、重跑局部测试和完整测试。每次文件内容、命令输出和错误信息都会成为下一步判断的上下文。

这个循环的价值不在于“Claude 一次猜对”，而在于它能根据真实反馈持续纠正。你也在循环里：可以中断、补充约束、拒绝越界权限，或者要求先停下来报告现状。

## 三层职责不要混在一起

| 层次 | 负责什么 | 不能保证什么 |
| --- | --- | --- |
| Claude 模型 | 理解目标、阅读上下文、提出计划、判断下一步 | 推理一定正确，或不会遗漏边界 |
| Claude Code CLI | 提供工具、组织上下文、执行权限与会话机制 | 被允许执行的动作一定符合你的真实意图 |
| 验证证据 | 用测试、实际运行、文件内容和 Diff 证明结果 | 自动替你决定需求是否合理 |

这一区分会贯穿整套课程。

如果 Claude 说“测试已经修好”，这只是模型的报告。你还要看到测试命令真的运行、退出结果符合预期，并确认测试调用了真实业务代码。如果权限提示显示将写入某个文件，CLI 负责让你批准或拒绝，但你仍要判断这个路径是否属于当前任务。

## Claude Code 能接触什么

在项目目录中运行 `claude` 后，它通常可以在权限和配置允许的范围内：

- 读取、搜索和编辑项目文件；
- 运行测试、构建、格式化、脚本和 Git 命令；
- 查看当前分支和未提交修改；
- 读取项目中的 `CLAUDE.md` 等说明；
- 使用你明确配置的 Skills、Hooks、MCP 或 Subagents。

“能接触”不等于“应该接触”。启动目录决定了最初的项目边界，权限规则和 Sandbox 进一步约束动作，但真正重要的数据仍需要 Git、独立备份和人工验收保护。

扩展功能也不是开始使用 Claude Code 的前提。内置的文件、搜索和命令工具已经能完成 MealCraft 前半程；只有出现重复流程、外部数据或需要隔离大量调查时，我们才会依次引入 Skill、Hook、MCP、插件和 Subagent。

## 什么任务适合交给它

适合的任务通常有明确边界，而且结果可以观察：

- 理解一个本地项目的入口和数据流；
- 实现一个行为清楚的小功能；
- 复现缺陷、补回归测试并做最小修复；
- 批量修改前先盘点、Dry Run，再分批执行；
- 分析构建或测试日志并验证根因；
- 核对文档、命令和代码是否一致。

下面这类任务描述就比“帮我优化项目”更可靠：

```
只调查当前项目的菜谱筛选逻辑，不要修改文件。
列出入口、调用路径、现有测试和两个仍未验证的风险，每个结论附文件证据。
```

它给出了范围、禁止动作、交付内容和证据要求。第 4 篇会让你在可丢弃目录中亲自完成这种闭环。

## 哪些事情不能一句话放手

以下动作即使 Claude 能执行，也需要额外预览、审批或隔离：

- 删除、覆盖或批量移动真实文件；
- 修改生产数据库、云资源或公开网站；
- 推送代码、合并分支、发布软件或发送外部消息；
- 读取密钥、私人笔记、客户数据和其他敏感内容；
- 安装来源不明的插件、Hook 或 MCP 服务；
- 在没有 Git 或备份时执行批量迁移；
- 为了减少提示而跳过所有权限检查。

不要用一句“请小心”代替强制边界。后续课程会分别用权限规则、Sandbox、Hook、临时目录、测试和备份处理这些风险。

## 贯穿项目：MealCraft

从第 5 篇开始，你会制作 **MealCraft**：一个只在本地运行的个人菜谱与一周菜单工具。它最终可以：

- 浏览和筛选中文菜谱；
- 按人数调整可计算的食材数量；
- 生成一周菜单并合并购物清单；
- 导出 Markdown 报告；
- 用自动测试保护换算、筛选和路径边界。

MealCraft 不接入支付、企业账号、生产数据库或真实个人数据。课程会提供固定练习起点，让不同读者面对相同的文件和缺陷，而不是依赖模型临场生成一个不可预测的项目。

完成主线后，你还会在个人博客、旅行笔记和个人开源项目三个独立夹具上练习迁移方法。

## 检查自己是否理解

读完后，你应该能回答：

1. Claude 报告“完成”为什么不等于任务已经通过验收？
2. 权限提示为什么不能替你判断命令是否符合真实需求？
3. 什么情况下应该先只读调查，而不是立即允许修改？

如果答案分别包含“需要独立证据”“CLI 只执行规则而不知道全部业务意图”和“现状、根因或边界尚不清楚”，就已经掌握了本篇最重要的工作模型。
