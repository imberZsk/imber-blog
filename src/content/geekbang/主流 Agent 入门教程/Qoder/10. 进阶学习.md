# 10. 进阶学习

> 来源：[Qoder](https://time.geekbang.org/space/wiki/Qoder_Tutorial)

这套 Qoder 教程的主线很具体。

先安装和登录，再给项目建立 Git 存档，用小步提交保留每一次可回退的状态。接着通过 /init 生成项目约定，认识权限模式，然后按照固定接口契约做第一个功能。

教程甚至特意固定日期，准备可以手算的数据。

这个细节看起来很小，却很能说明它的态度。功能不是页面跑起来就算完成，而是结果要能被人独立核对。

第 5 章继续制造 Bug，让 Qoder 根据报错排查，再补测试、重构，并分别用 /rewind 和 Git 处理不同范围的回退。第 6 章把能力扩到代码库向导、Skills、MCP、子代理、记忆和项目约定。第 7 章完成月度报告导出，再补文档、Review、安全扫描和提交历史，直到项目能交付。

所以读完整套知识库，最值得留下来的是四个真正值得复用的动作。

有存档，有契约，有验证，有交付。

有存档，AI 改错时可以回退。小步提交不是为了让 Git 历史好看，而是把风险切小。

有契约，Qoder 才知道接口、输入、输出与边界。需求模糊时，生成越快，返工也越快。

有验证，结果不靠感觉。固定日期和可手算数据，就是最朴素的验收证据。测试、Review 和安全扫描，则把证据扩到功能、质量与风险。

有交付，代码、文档、提交历史和最终检查要放在一起。一个只能在当前会话里运行的结果，还不是完整项目。

这套方法在个人练习里很有效。进入企业项目以后，它会遇到更大的尺度。

接口契约会变成跨模块、跨服务的规格。Git 小步提交会扩展到 Worktree 和并行分支。单个子代理会变成调研、开发、测试、安全和 Review 的角色协作。项目约定不只是格式规范，还要包含架构决策、 启动环境、依赖边界、权限与上线要求。

Skills 和 MCP 也会从能不能接上，变成接上以后是否安全、稳定、可审计。

一个 MCP 工具可以让 Qoder访问外部系统，但谁能调用，参数怎样校验，失败是否重试，调用是否留痕，都要由工程系统负责。一个 Skill 能打包专业流程，但流程本身也需要版本、测试与清晰输出。

还有一个更难的问题，怎样把业务需求变成 Agent 真正能执行的工作单元。

教程里的固定契约已经给了起点。再往前，需要把模糊目标整理成 spec、plan 和 tasks，明确非目标、风险与验收。新项目可以先建立完整规格，老项目则要控制增量修改范围，避免 AI 为了实现一个

功能顺手重写半个系统。

「企业级 AI 编程实战营」承接的正是这种规模升级。

课程围绕 SDD 与 Harness Engineering，把规格定义、项目规则、权限、Hooks、测试、 Subagents、Worktrees、Skills 和 Slash Commands 组合成可控工作流。重点不是多学一个编程助手，而是让同一套方法能够进入复杂项目。

AI 智能体操作系统项目训练从零设计 Agent Runtime、多模型路由、MCP 和工作空间隔离。分布式延时投递服务训练复杂系统、高可用、故障切换与消息可靠性。Dify 二次开发训练大型陌生代码库的理解、增量规格与回归边界。mq9 开源协作则把交付放进真实维护者 review，最终是否合并以实际 review 为准。
