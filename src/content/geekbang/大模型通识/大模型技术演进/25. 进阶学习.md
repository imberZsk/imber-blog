# 25. 进阶学习

> 来源：[大模型技术演进](https://time.geekbang.org/space/wiki/LLM_History)

这套知识库从 2022 年末的 ChatGPT 写起，一直写到 2026 年的个人 Agent、工程框架和硬件工作负载。

真正重要的是四次任务边界的变化。

第一次变化，是模型从生成文字走向理解指令。

ChatGPT 把自然对话带到大众面前，GPT-4、Claude、Bard 和新 Bing 又推动了第一轮应用扩张。提示词和 API 让模型成为可调用能力，插件、Function Calling 和代码执行开始把回答连接到外部世界。

第二次变化，是模型开始使用你的资料。

RAG 与知识库问答解决模型不知道私有资料的问题，长上下文让模型一次看到更多材料。GPTs、 Dify、Coze 等定制助手与工作流工具，则把多步骤调用变成普通用户也能配置的流程。

第三次变化，是模型从处理文字走向处理工作。

多模态让图片、语音和视频进入任务。推理模型愿意为难题投入更多计算。Deep Research 把搜索、 阅读、综合和引用组织成一项研究任务。Coding Agent 开始读取仓库、修改文件、运行测试并根据反馈继续行动。

第四次变化，是 Agent 开始拥有持续运行的环境。

Computer Use、MCP、A2A、Skills、个人 Agent 与 OpenClaw 生态，把浏览器、桌面、消息入口、 外部服务和任务交接连接起来。模型不只是给建议，而是在一个环境里持续完成工作。

所以这段历史的主线，是我们交给模型的任务越来越完整。

知识库讲 Vibe Coding 时，专门区分了原型与可交付应用。讲 Deep Research 时，也提醒有引用不会自动让答案正确。到了可靠 Agent 工程，知识库又把上下文、记忆、评测、追踪、沙箱、Harness 和 Loop 放在一起。

这些内容都指向同一条分界线。

模型有能力完成动作，不代表系统有能力可靠交付。

一个 Agent 可以调用工具，但工具参数是否合法，权限是否允许，调用失败后要不要重试，操作是否留下审计，都需要工程系统处理。

一个 Agent 可以跑十几个步骤，但中途失败后状态怎样恢复，上下文怎样压缩，重复操作怎样避免， 任务什么时候应该停，都不是模型自己就能解决的。

一个 Agent 可以给出结果，但没有评测集、Trace 和版本对比，我们就不知道结果是不是比上一版更好。

历史走到 Agent 阶段，瓶颈自然从模型会不会，移动到系统稳不稳。

### 从看懂趋势到做出 Agent，还差什么

看发展史时，我们很容易按照时间理解变化。

2023 年是 API 和 RAG，2024 年是长上下文、多模态和推理，2025 年是 Coding Agent 与任务 Agent，2026 年是个人 Agent 生态。

可真实项目不会按年份整齐出现。

一个企业 Agent 往往同时需要模型选型、Prompt、RAG、工具调用、状态、记忆、权限、评测、部署、监控和成本治理。任何一层太弱，最终都会表现成一句话。

这个 Agent 不太稳定。所以继续深入时，不能只顺着产品时间线学，还要横向建立一套系统能力。

模型怎样进入应用，工具怎样进入 Loop，上下文怎样进入每一步，评测怎样进入版本迭代，权限与监控怎样进入生产环境。这些问题组合起来，才是一套 Agent 工程。

所以我们在这里推荐了「AI Agent 全栈工程师训练营」。这个训练营要补的，正是怎样亲手构建一套可以评测、追踪、恢复和部署的 Agent 系统。

课程用 14 周覆盖 LLM、Prompt、RAG、Agent Loop、Memory、Skill、Context Engineering、 Agent Eval、Tracing、MCP 和生产部署。知识库里的历史节点，在这里会变成同一个项目链路中的工程组件。
