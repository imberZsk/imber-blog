# 2. 注意力机制：模型怎样利用上下文中的信息

> 来源：[大模型理论基础](https://time.geekbang.org/space/wiki/LLM_Basic)

你把这样一段笔记交给复习助手：

> 我把新买的词典放进书包。它很厚，翻起来却很方便。

如果助手要围绕“它”生成一道题，就不能只知道“它”这个字的含义，还得把它与前面的“词典”联系起来。换成“它的肩带断了”，指向的对象又很可能变成书包。

上一篇讲到，文字会变成 Token，再变成向量。但是，仅仅给每个 Token 配上一串数字，还不足以处理这些关系。模型还需要一种计算，让某个位置的表示吸收其他位置的信息。

\*\*注意力机制，就是完成这种信息汇集的一种办法。\*\*本篇会把它拆成三个动作：计算匹配分数、分配权重、汇集内容。读完后，你应该能解释 Query、Key、Value 的分工，并亲手核对一次极小的注意力计算。

这里只需要向量是“一串数字”、加权平均是“按比例混合”这两个基础。所有句子、向量和权重示例均为教学构造，不是从某个大模型内部提取的结果，也不需要安装软件。

## 一、先看清问题：同一个位置，为什么需要其他位置的信息

在词典的例子里，有几种信息会一起影响我们的判断：前文出现了什么对象，“厚”常用来描述什么，“翻”与什么活动有关。

注意力并没有内置一条规则，规定“看到‘它’，就去找最近的名词”。它提供的是计算结构；能否从数据中学到有用的关联，还要看模型的训练以及其他计算环节。

还有一个时序细节。对常见的从左向右生成的语言模型而言，当它只读到“它”这个位置时，后面的“很厚”还不能参与该位置的计算；读完整句话后，后面位置的表示才可以综合这些线索。把整句交给模型再问“它指什么”，与要求模型仅凭“它”之前的前缀判断，是两个不同任务。

因此，我们不能画一条“它 → 词典”的箭头，就宣称模型内部一定这样运作。这个句子只是说明：**语言任务需要根据上下文建立关联，而且可用的上下文受计算规则限制。**

在自注意力中，同一段序列内的各个位置可以通过这种机制交换信息；允许建立哪些连接，则由具体结构决定。[《动手学深度学习》：自注意力](https://d2l.ai/chapter_attention-mechanisms-and-transformers/self-attention-and-positional-encoding.html)

## 二、Query、Key、Value 各自负责什么

先暂时离开模型。假设你在自己的笔记库里找“解释梯度下降的小例子”。你可能先看笔记标题与标签，判断哪些条目有关，再阅读其中的内容。

这个过程可以帮助我们理解三个名字：

| 名称 | 中文与缩写 | 在注意力计算里的分工 |
| --- | --- | --- |
| Query | 查询，Q | 当前这个位置用什么向量去匹配其他位置 |
| Key | 键，K | 每个候选位置拿什么向量参与匹配 |
| Value | 值，V | 匹配完成后，实际参与汇集的内容向量 |

Q 与 K 决定“从各处取多少”，V 决定“取回什么”。注意力通常不是只选一个条目，而是把多个 Value 按权重组合起来。[《动手学深度学习》：查询、键和值](https://d2l.ai/chapter_attention-mechanisms-and-transformers/queries-keys-values.html)

不过，笔记检索只是类比。模型内部的 Q 不是用户写下的整句问题，K 不一定对应可读的标签，V 也不是原文字符串。它们都是数字向量。即使用户没有提出问题，模型在处理普通陈述句时，也能为各位置计算 Query。

### 这些向量从哪里来

以标准自注意力的一种写法为例，设当前层某个位置的表示为 `x`。模型用三组参数分别变换它：

```
q = x × WQ
k = x × WK
v = x × WV
```

这里的乘号表示向量与矩阵的乘法。你不必现在学会矩阵运算，只需把它理解为：\*\*同一份输入，经过三套不同的加权组合，得到三个不同用途的向量。\*\*为简化，本篇省略可能存在的偏置及其他实现细节。

`WQ、WK、WV` 是训练得到的参数矩阵；`q、k、v` 是用这些参数处理本次输入后产生的中间值。标准做法是在同一层、同一注意力头内，对不同位置使用相同的一组投影参数；不同输入仍会产生不同结果。[《动手学深度学习》：注意力中的可学习投影](https://d2l.ai/chapter_attention-mechanisms-and-transformers/multihead-attention.html)

这也解释了为什么“自注意力”不等于 `Q = K = V`。它们可以来自同一份序列表示，却经过不同变换。后面的层接收到的表示还已经混入了前文信息，不再只是最初从词表中查到的那一行嵌入。

普通推理时，输入改变，Q/K/V 和注意力权重会跟着变；这不代表模型的参数刚刚被重新训练了。

## 三、用一组数字，完整算一次注意力

下面只观察**一个查询位置，对三个允许访问的位置 A、B、C 进行汇集**。这些位置标签没有固定语言含义；不把它们硬说成“词典”“书包”，是为了避免用我们手工填的数字冒充模型学到的语义。

我们直接给出投影之后的向量，不演示前面的参数训练。查询向量是：

```
q = [1, 0, 0, 0]
```

候选位置的 Key 和 Value 如下：

| 位置 | Key，4 维 | Value，2 维 |
| --- | --- | --- |
| A | [4, 0, 0, 0] | [2, 0] |
| B | [2, 0, 0, 0] | [0, 2] |
| C | [0, 0, 0, 0] | [1, 1] |

Q 与 K 在这里都必须有 4 个分量，才能直接计算点积；V 可以有不同的维数。这个例子中的输出会是 2 维向量，而不是 4 维。

### 第一步：用 Q 与每个 K 算匹配分数

**点积**就是对应数字相乘，再相加。比如：

```
q · kA = 1×4 + 0×0 + 0×0 + 0×0 = 4
q · kB = 2
q · kC = 0
```

标准的**缩放点积注意力**还会除以 Q/K 维数的平方根。这里维数是 4，平方根是 2，因此得到分数：

```
A：4 ÷ 2 = 2
B：2 ÷ 2 = 1
C：0 ÷ 2 = 0
```

缩放是为了控制分数的尺度：维数增大时，点积的波动可能增大，过大的分数差会让后面的权重分配过于集中，影响训练。它不是根据句子长度随意设定的折扣。[《Attention Is All You Need》§3.2.1](https://arxiv.org/html/1706.03762v7)

注意，“匹配分数高”只是当前这组向量计算的结果，不等于候选内容更真实，也不一定等于日常语言中“两个词意思更相近”。Q 和 K 可以学到适合任务的不同关系。

### 第二步：把分数变成权重

还记得第一部分的 Softmax 吗？它把一组分数转换成非负、总和为 1 的数。在这里，这组数表示各个 Value 的混合比例。

计算方法是：先对每个分数取指数，再除以所有指数的总和。`e` 是约等于 2.718 的数学常数；无需记忆，下面直接给出近似值。

| 位置 | 缩放后分数 | 指数近似值 | 除以总和后得到的权重 |
| --- | --- | --- | --- |
| A | 2 | 7.389 | 0.665 |
| B | 1 | 2.718 | 0.245 |
| C | 0 | 1.000 | 0.090 |

分母约为 `7.389 + 2.718 + 1 = 11.107`。例如，A 的权重约为 `7.389 ÷ 11.107 = 0.665`。

这里有两个可独立核对的结果：权重之和约为 1；分数最高的 A 获得最大权重。C 的分数虽然是 0，权重却**不是 0**，因为 `e⁰ = 1`。

这一做法及下一步的向量汇集，就是缩放点积注意力的核心计算。[《动手学深度学习》：注意力评分函数](https://d2l.ai/chapter_attention-mechanisms-and-transformers/attention-scoring-functions.html)

### 第三步：按权重组合 Value

```
输出 z ≈ 0.665×[2,0] + 0.245×[0,2] + 0.090×[1,1]
       ≈ [1.420, 0.580]
```

第一维是 `0.665×2 + 0.245×0 + 0.090×1`；第二维按同样方式计算。使用未四舍五入的权重时，结果约为 `[1.421, 0.579]`。

这就是本次注意力汇集的结果：\*\*一个新的内容向量。\*\*它既不是“选择了 A”这个文字结论，也不是已经生成好的回答。A 的信息占比最大，但 B、C 仍有贡献。

现在做两个小改动，看看你是否真的理解了分工：

- 如果保持 Q、K 不变，只把 A 的 Value 从 `[2,0]` 改为 `[0,0]`，权重仍然不变，输出却会变成约 `[0.090,0.579]`。
- 如果保持三个 Value 不变，让三个匹配分数完全相同，权重就都是 `1/3`，输出为 `[1,1]`。

第一个改动说明：\*\*权重不是被传递的内容本身。\*\*第二个改动说明：权重决定了怎样混合已有的内容。实际模型修改输入时，往往会同时影响 Q、K、V；这里把它们单独固定，是为了做教学对照。

## 四、从一个查询，扩展到一整段文字

真实计算通常会把多个位置的查询向量叠在一起，组成矩阵 Q；K、V 也各自组成矩阵。你可能会在论文里见到：

$$  
\operatorname{Attention}(Q,K,V)  
=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d\_k}}\right)V  
$$

这是上面三步的批量写法：`QKᵀ` 算出各查询与各 Key 的点积分数，`d_k` 是 Q/K 的维数，Softmax 对**每个查询对应的一行**分别分配权重，最后乘 V 汇集内容。上式暂不包含掩码。

不必背公式，可以沿着下面的图读：

```
flowchart LR
    X[当前层的序列表示] --> Q[生成 Q]
    X --> K[生成 K]
    X --> V[生成 V]
    Q --> S[逐个查询与 Key 计算分数]
    K --> S
    S --> M[按规则屏蔽不可访问的位置]
    M --> A[每行 Softmax 得到权重]
    A --> Z[对 Value 加权汇集]
    V --> Z
    Z --> N[交给后续网络处理]
```

在三位置的自注意力例子中，权重表有三行、三列。行表示“谁在查询”，列表示“从哪里取信息”。\*\*A 取 B 的权重，与 B 取 A 的权重，不需要相等。\*\*方向不同，使用的查询和键也不同。

这里的“每行总和为 1”指正常有效行的 Softmax 输出；本篇没有加入训练时可能使用的 Dropout，也就是随机丢弃部分数值的正则化操作。

### 为什么生成模型不能提前看后面的答案

假设教学 Token 序列是：

```
[我] [用] [卡片] [复习]
```

在标准的因果自注意力中，允许访问的关系是：

| 查询位置＼被访问位置 | 我 | 用 | 卡片 | 复习 |
| --- | --- | --- | --- | --- |
| 我 | ✓ | — | — | — |
| 用 | ✓ | ✓ | — | — |
| 卡片 | ✓ | ✓ | ✓ | — |
| 复习 | ✓ | ✓ | ✓ | ✓ |

这叫 **Causal Mask，因果掩码**。计算第三个位置的表示时，可以使用“我、用、卡片”，不能使用第四个位置“复习”。随后用第三个位置的结果预测下一个 Token，才不会直接看到目标答案。训练中即使整句话已经放进计算设备，也要遵守这一限制。[《Attention Is All You Need》§3.1、§3.2.3](https://arxiv.org/html/1706.03762v7)

被屏蔽的位置，要在 Softmax 之前排除。数学上常把其分数设为负无穷，使相应权重为 0；**把分数改成 0 并不能屏蔽它**，前面的 C 已经展示了原因。

自注意力本身不强制只能向左看。用于整段文本理解的结构可以采用双向访问；生成模型则通常需要因果限制。也存在 Q 来自一组表示、K/V 来自另一组表示的**交叉注意力**，例如翻译时生成端查询源文的表示。不要把所有“看上下文”都理解成同一种连接方式。

## 五、多头注意力：同时保留不同的汇集方式

对于一句话，只形成一种混合结果，可能不足以承载不同关系。模型可能既需要关联对象与代词，又需要关联动作与对象，还要利用代码里的变量或括号关系。

**多头注意力，Multi-Head Attention**，让模型使用多组投影，分别计算注意力，再把各头的结果拼接、变换后交给后续网络。[《动手学深度学习》：多头注意力](https://d2l.ai/chapter_attention-mechanisms-and-transformers/multihead-attention.html)

你可以把它理解成允许几种不同的信息汇集方式并行存在。但不要给它硬贴标签，说“第一个头负责语法，第二个头负责逻辑”。这些分工不是程序员必须预先规定的，学到的模式也不保证这么整齐。

“多头”也不是多个完整大模型开会投票。它是同一个网络内部的一组计算。多层则意味着：前一层更新表示后，后一层在新的表示上继续计算。注意力之外还有哪些部件、这些结果如何组合，下一篇 Transformer 再展开。

另一个相关问题是顺序。单看“逐个比较内容并加权”的操作，并没有完整说明“前一个词”“第几个位置”如何表示；模型还需要位置相关的设计。否则，只知道有哪些内容，不足以区分“小林帮助小周”与“小周帮助小林”。我们也把具体的位置处理方法留到下一篇。

## 六、理解注意力之后，怎样改进你的复习助手

注意力让模型有机会利用上下文，但没有替应用完成所有工作。下面三类错误尤其值得区分。

### 资料没有进入输入，注意力无从读取

你电脑里保存着一本教材，不代表本次模型调用已经拿到它。应用需要先读取或检索相关内容，再把内容送入模型，模型才能通过上下文计算使用这些材料。

这也是内部注意力与外部检索的区别：前者处理已有表示，后者决定哪些资料能进入这次任务。两者可以配合；注意力不是自动搜索整个硬盘或互联网的功能。

### 资料进入输入，也不保证被正确利用

例如，两份笔记都叫“复习安排”，一份说周三复习，一份说周五复习。如果没有日期、版本或适用对象，模型可能缺少判断依据。

对这个项目，一个可操作的做法是：保留标题、来源和版本，把“参考资料”与“这次要求”写清楚；遇到相互冲突的材料，允许助手指出冲突。这是减少任务歧义的设计建议，效果仍需要用你自己的案例检验。

也不要把“上下文能装下很多 Token”直接理解成“任何位置的信息都会用得同样好”。《Lost in the Middle》在其测试模型和任务中发现，相关信息所处的位置会影响表现。它提示我们测试信息利用能力，而不能据此断言所有新模型永远都会出现相同程度的问题。[原始论文](https://arxiv.org/abs/2307.03172)

### 注意力权重高，不代表内容可靠

刚才 A 的权重约为 0.665，并不意味着“A 有 66.5% 的概率是真的”。那只是一个查询、一个计算环节中的混合系数，不能代替事实校验。

即使你看到了漂亮的注意力热力图，也不能直接把最深的色块当成“模型得出最终答案的完整原因”。后续层、Value 的具体数值以及其他计算路径都会影响结果。Jain 与 Wallace 的研究在所考察的 NLP 模型和任务中展示了注意力权重作为解释的局限；这不是说权重毫无研究价值，而是不能仅凭它认定因果贡献。[《Attention is not Explanation》](https://arxiv.org/abs/1902.10186)

对复习助手，更直接的验证仍然是：生成的题目和答案是否得到原文支持，换一个对象或版本后是否相应改变，缺少资料时是否会承认无法判断。

## 七、理解检查：不用运行模型，也能检验自己

先作答，再看下面的解释。

**1. 用户只输入“今天复习概率”，没有问号，模型就不需要 Query 吗？**

不对。Query 是内部参与匹配的向量，不是“自然语言问句”的别名。普通陈述句的各个位置同样可以产生 Query。

**2. 三个未被屏蔽的位置，匹配分数都是 0，权重和输出分别是什么？**

每个指数都是 1，因此权重各为 `1/3`。使用本篇的三个 Value，输出为 `[1,1]`。分数为 0 不等于禁止访问。

**3. 某次汇集的权重为 `[0.5,0.25,0.25]`，Value 仍是 `[2,0]、[0,2]、[1,1]`，结果是多少？**

第一维为 `0.5×2 + 0.25×0 + 0.25×1 = 1.25`；第二维为 `0.5×0 + 0.25×2 + 0.25×1 = 0.75`，得到 `[1.25,0.75]`。这仍是向量，不是生成的两个词。

**4. 在上面的四 Token 因果掩码中，“卡片”位置能读取“复习”吗？如果不能，模型如何学习预测“复习”？**

不能在前向计算这个位置的表示时读取它。但训练程序知道正确的下一个 Token 是“复习”，可以在模型给出预测后计算损失，再据此更新参数。作为监督目标，与作为当前预测的输入，是两种不同用途。

**5. 用户换了一段笔记，Q/K/V 和注意力权重全变了，是否说明模型学会了这段笔记，以后不传也能记住？**

不能这样推断。变化的是本次输入产生的中间结果；普通推理没有因此更新参数，也不能保证跨请求保存内容。长期记忆需要另行设计。

**6. 某个注意力头给旧版笔记 90% 的权重，是否可以据此认定旧版安排更正确？**

不可以。权重不是正确率，注意力也没有自动承担版本裁决。应用应提供版本信息，并根据可核对的来源检查回答。

---

回到开头的“它”：现在你已经知道，模型不是只拿一个固定词义去查答案。它会在允许访问的范围内，通过 Q/K 的匹配计算汇集 V，让各位置的表示携带更多上下文信息。能否把这些信息转化成正确回答，还取决于整个网络和任务设计。
