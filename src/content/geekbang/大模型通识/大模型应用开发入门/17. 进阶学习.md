# 17. 进阶学习

> 来源：[大模型应用开发入门](https://time.geekbang.org/space/wiki/LLM_App_Develop_Basic)

## 从 DeepSeek 笔记助手到企业级 Agent，中间还隔着什么

这套大模型应用开发入门，用 16 篇内容和一条很完整的项目主线，带着读者从 Python 调用 DeepSeek 开始，一步步做出个人笔记助手。

先把调用整理成可重复运行的项目，再处理消息角色与多轮对话，加入流式输出。接着把笔记变成复习卡，用 JSON 和业务规则验证结构化结果。然后继续处理思考模式与输出预算、超时与有限重试、 用量成本与上下文缓存。

做到这里，它已经不只是聊天壳子了。

后面的内容又加上白名单工具调用、参数校验和人工确认，读取本地文件并保留来源快照，做一个可追溯证据的最小 RAG，再接上本地 Web 页面、SQLite 会话与复习计划，最后整理配置、启动、部署边界、验收与项目迁移。

知识库的最终项目还有 10 个可运行的离线验收场景。

而且它很诚实地写明，未进行真实 API 质量和费用验证，所以不把离线检查冒充线上实测。

这个细节我觉得挺重要。你为它刚好划出了入门应用和生产系统之间的边界。

你已经知道怎样接模型、控制消息、解析输出、处理错误、调用工具、读取资料、保存状态，也知道结果需要验证。

但当应用开始执行更长的任务，面对更多用户和更复杂的外部系统，问题会从功能有没有，变成系统稳不稳。

比如，笔记助手调用一次本地工具失败，人工重试就行。Agent 连续执行搜索、读取、分析、修改和生成时，第三步失败以后怎么办？前两步的状态是否保留，任务应该重试、重新规划，还是交给人处理？

知识库讲过有限重试。到了长任务里，重试还要判断错误类型，防止 Agent 在错误路径上无限循环。

知识库讲过白名单工具和确认机制。到了生产环境里，还要有工具注册、Schema、权限分级、审计、 超时、降级和 Trace。

知识库讲过最小 RAG 与来源快照。到了大型知识库和代码库里，还会碰到解析、分块、混合检索、重排、上下文压缩、记忆和任务恢复。

知识库讲过 10 个离线验收场景。到了 Agent 系统里，评测对象不只有最终答案，还包括规划、工具选择、执行轨迹、失败恢复和不同版本的回归结果。

所以从笔记助手走向 Agent，需要一套新的工程骨架。

状态要能保存，动作要能追踪，权限要能限制，失败要能恢复，结果要能评测，系统要能部署和回滚。模型负责判断下一步，工程系统负责不让每一步失控。

这一点其实在知识库大纲里已经留下了明确入口。本部分专注模型接入与应用基础，Harness 与 Loop 工程另行展开。

「AI Agent 全栈工程师训练营」接的正是这里。

课程用 14 周覆盖 LLM 与 Prompt、RAG、Agent Loop、Memory、Skill、Context Engineering、 Agent Eval、Tracing、MCP 和生产部署，并用六个项目逐层增加复杂度。

第一个项目搭建 Agent 工具调用运行时，加入工具注册、参数校验、权限、审计、超时、重试和 Trace。第二个 Codebase Agent 让系统处理搜索、改代码、跑测试、读日志和自动修复，并加入人工确认、沙箱、状态和 Checkpoint。第三个项目加入代码库 RAG、混合检索、Rerank、项目记忆、上下文压缩与来源追溯。

再往后是 Multi-Agent 与 Eval，建立多角色协作、Benchmark、LLM-as-Judge、人工评测和回归测试。第五个项目进入生产运维，加入模型网关、监控、回放、版本、灰度、回滚与成本治理。收官项目则基于 DeerFlow 搭建深度研究平台和新一代软件工厂。
