# 13. 进阶学习

> 来源：[AI 理论基础](https://time.geekbang.org/space/wiki/AI_Basic)

## 理解AI理论之后 怎样判断一个Agent方案是否可靠

模型在训练中学到了什么，为什么换一批数据效果就变了，指标提高是否意味着用户体验变好？读完 AI 理论基础知识库，你已经有了一套理解这些问题的基本概念。

从数据、表示、训练到泛化与评估，这些知识能帮助你读懂技术方案，也能提醒你在看到一次漂亮演示时，多问一句：它在什么条件下成立？进入真实项目后，这个问题会变得更具体。

## 先把理论变成检查方案的工具

假设你要做一个客服助手，模型能够流畅回答，并不代表它已经完成了客服任务。可以从下面四个角度检查方案。

![原文图片](../../assets/cefc06d70873c3084763.png)

例如，客服知识里缺少最近的退款规则，回答可能依旧流畅，却没有正确依据。此时要先检查资料是否完整、检索是否拿到了相关内容，再判断模型如何使用这些信息。

知识库讲到的泛化与分布变化，也可以用在这里：演示中只有措辞清楚的提问，实际用户却可能带着错别字、多个诉求和含糊描述。测试样本需要覆盖这些输入，才能看清方案的适用范围。

练习时，可以整理一小组真实风格的问题，分别记录正确依据、预期回答和需要人工处理的情况。你会更容易判断，问题来自信息不足、模型理解，还是业务规则没有说清楚。

## 从判断回答 到判断整个执行过程

当助手开始查询订单、创建工单，评估对象就从一段回答扩展到了整条业务流程。下面几项值得一起检查。

![原文图片](../../assets/5217b30141fa3677372d.png)

比如，用户要求修改收货地址，系统需要先核实身份和订单状态，再确定是否允许修改。模型理解了请求，只是其中一步；是否访问了正确订单、有没有获得授权、操作失败后怎样恢复，都需要单独验证。

可以先选择一个低风险流程，把输入、工具、预期结果和异常路径写出来。每次调整模型或提示词后，用同一组样本比较结果，保留失败记录。这样，理论中的评估意识就有了实际落点。

## 有了开发实践 再深入系统架构

如果你已经做过大模型应用或基础 Agent，希望进一步解决这些系统问题，可以了解《企业级 Agent 工程架构实战营》。

课程从 LLM 与 Agent 的底层认知出发，进一步讨论架构选型、运行时设计、上下文与工具治理，以及结果、执行轨迹和系统代价三个层面的评测。学习重点是把判断依据落实到系统设计中。

贯穿项目是企业级多租户零售经营分析与决策 DataAgent。学员围绕数据查询、分析、证据验证和受控业务操作，比较候选方案、建立评测基线，并练习故障诊断和发布控制。

这是一门面向已有大模型应用和基础 Agent 开发经验的架构进阶课程。刚读完理论的同学，可以先补一个小型应用实践，再带着遇到的具体问题继续学习。
