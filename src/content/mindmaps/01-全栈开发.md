# 全栈开发
- 前端
  - 页面结构、样式与 JavaScript
    - HTML 语义化
      - 含义：用符合内容含义的标签组织页面，有利于可访问性、SEO 和代码维护。
      - 示例：页面主体用 `<main>`，导航用 `<nav>`，独立文章用 `<article>`，按钮行为用 `<button>`。
      - 官方链接：[MDN HTML 语义](https://developer.mozilla.org/zh-CN/docs/Glossary/Semantics#html_中的语义)
    - HTML 表单
      - 含义：表单收集用户输入，浏览器可基于输入类型和约束提供基础校验。
      - 示例：`<input type="email" required>` 会在提交前检查必填和邮箱格式。
      - 官方链接：[MDN Web 表单](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Extensions/Forms)
    - CSS 盒模型
      - 含义：元素尺寸由内容、内边距、边框和外边距共同决定。
      - 示例：设置 `box-sizing: border-box; width: 200px; padding: 16px` 后，总宽度仍是 `200px`。
      - 官方链接：[MDN 盒模型](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/Styling_basics/Box_model)
    - Flex 布局
      - 含义：Flex 适合沿一个主轴排列和对齐元素，常用于工具栏、导航和一维列表。
      - 示例：`display: flex; justify-content: space-between; align-items: center;` 让标题与操作按钮分居两端并垂直居中。
      - 官方链接：[MDN Flexbox 基本概念](https://developer.mozilla.org/zh-CN/docs/Web/CSS/CSS_flexible_box_layout/Basic_concepts_of_flexbox)
    - Grid 布局
      - 含义：Grid 同时控制行和列，适合仪表盘、表单和二维页面结构。
      - 示例：`grid-template-columns: 240px 1fr;` 创建固定侧栏和自适应主内容区。
      - 官方链接：[MDN Grid 基本概念](https://developer.mozilla.org/zh-CN/docs/Web/CSS/CSS_grid_layout/Basic_concepts_of_grid_layout)
    - 响应式设计
      - 含义：同一界面根据屏幕宽度、输入方式和内容空间调整布局，而不是简单缩小桌面页面。
      - 示例：小屏把三列表格改为可横向滚动，工具栏操作收进菜单，并保留主要按钮可见。
      - 官方链接：[MDN 响应式设计](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/CSS_layout/Responsive_Design)
    - JavaScript 变量与类型
      - 含义：`const` 保存不重新赋值的绑定，`let` 保存会变化的绑定；对象和数组是引用类型。
      - 示例：`const user = { name: 'Lin' }; let loading = false;`。
      - 官方链接：[MDN JavaScript 语法与类型](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Grammar_and_types)
    - JavaScript 函数
      - 含义：函数封装可复用行为，可以接收参数并返回结果；异步函数会返回 Promise。
      - 示例：`const total = (price, count) => price * count;`。
      - 官方链接：[MDN 函数](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Functions)
    - Promise 与 async/await
      - 含义：Promise 表示未来完成或失败的异步结果，`async/await` 让异步流程更接近顺序代码。
      - 示例：`const user = await fetch('/api/user').then(r => r.json());`。
      - 官方链接：[MDN 使用 Promise](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Using_promises)
    - HTTP 与接口协议
    - HTTP 方法
      - 含义：`GET` 查询、`POST` 创建或执行动作、`PUT` 整体替换、`PATCH` 局部更新、`DELETE` 删除资源。
      - 示例：查询订单用 `GET /orders/1`，修改收货地址用 `PATCH /orders/1`。
      - 官方链接：[MDN HTTP 请求方法](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Reference/Methods)
    - HTTP 状态码
      - 含义：状态码表达协议层结果；`2xx` 成功、`4xx` 客户端问题、`5xx` 服务端问题。
      - 示例：参数格式错误返回 `400`，未登录返回 `401`，无权限返回 `403`，资源不存在返回 `404`。
      - 官方链接：[MDN HTTP 状态码](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Reference/Status)
    - 请求头与响应头
      - 含义：Header 携带内容类型、认证、缓存、语言和链路信息，不应把大段业务数据放入 Header。
      - 示例：请求用 `Authorization: Bearer <token>`，JSON 响应用 `Content-Type: application/json`。
      - 官方链接：[MDN HTTP 标头](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Reference/Headers)
    - Cookie 与 Session
      - 含义：Cookie 保存在客户端并随请求发送，Session 通常把登录状态保存在服务端，只让 Cookie 携带会话 ID。
      - 示例：登录成功返回 `Set-Cookie: session_id=...; HttpOnly; Secure; SameSite=Lax`。
      - 官方链接：[MDN Cookie](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/Cookies)
    - CORS 跨域
      - 含义：浏览器用同源策略保护资源，服务端通过 CORS 响应头声明允许哪些来源、方法和请求头。
      - 示例：开发环境允许 `http://localhost:5173`，生产环境只允许正式前端域名，不使用带凭据的任意来源 `*`。
      - 官方链接：[MDN CORS](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/Guides/CORS)
    - REST API
      - 含义：以资源为中心设计 URL，利用 HTTP 方法和状态码表达操作与结果。
      - 示例：使用 `/api/orders/123/items` 表示订单 `123` 的明细集合，避免 `/getOrderItemsByOrderId`。
      - 官方链接：[Microsoft REST API Guidelines](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md)
    - JSON 数据交换
      - 含义：JSON 用对象、数组、字符串、数字、布尔值和 null 表达跨语言数据，不支持注释和日期类型。
      - 示例：`{"id":1,"items":[{"sku":"A1","count":2}],"paid":false}`。
      - 官方链接：[MDN JSON](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Core/Scripting/JSON)
  - 浏览器运行机制
    - DOM
      - 含义：浏览器把 HTML 解析成 DOM 树，JavaScript 通过 DOM API 查询、创建和修改页面节点。
      - 示例：`document.querySelector('#save')` 获取按钮；Vue、React 最终也会把组件更新转化为 DOM 变化。
      - 官方链接：[MDN DOM 简介](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model/Introduction)
    - 事件捕获与冒泡
      - 含义：事件先从外层向目标捕获，再从目标向外层冒泡；事件委托利用冒泡统一处理动态子元素。
      - 示例：列表容器监听一次 `click`，通过 `event.target` 判断点击的行，不给每一行重复绑定监听器。
      - 官方链接：[MDN Event Bubbling](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Event_bubbling)
    - 事件循环
      - 含义：JavaScript 通过调用栈、任务队列和微任务队列协调同步代码、Promise、定时器和浏览器事件。
      - 示例：同步日志先执行，`Promise.then` 微任务通常早于 `setTimeout(..., 0)` 的任务执行。
      - 官方链接：[MDN JavaScript Event Loop](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Event_loop)
    - ES Modules
      - 含义：ESM 用 `export/import` 组织模块，静态依赖便于 Tree Shaking，动态 `import()` 可按需加载代码。
      - 示例：路由进入报表页时执行 `import('./ReportPage')`，避免首屏下载低频页面代码。
      - 官方链接：[MDN JavaScript Modules](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules)
    - localStorage 与 sessionStorage
      - 含义：Web Storage 是同步的字符串键值存储；localStorage 跨会话保留，sessionStorage 随标签页会话结束。
      - 示例：保存非敏感主题偏好可以用 localStorage，不能存数据库密码或长期高权限 Token。
      - 官方链接：[MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)
    - IndexedDB
      - 含义：IndexedDB 是浏览器中的异步事务型对象数据库，适合较大结构化数据和离线缓存。
      - 示例：离线巡检应用把待上传表单和图片元数据保存在 IndexedDB，恢复网络后批量同步。
      - 官方链接：[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)
    - WebSocket
      - 含义：WebSocket 在单个长连接上提供双向通信，适合聊天、协作和实时状态，不适合所有普通 CRUD。
      - 示例：订单状态变化由服务端主动推送；断线后客户端退避重连，并根据版本号补拉遗漏数据。
      - 官方链接：[MDN WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)
    - Service Worker
      - 含义：Service Worker 独立于页面运行，可拦截网络请求、缓存资源、支持离线和推送，但必须使用安全上下文。
      - 示例：缓存应用壳和静态资源；接口数据采用明确更新策略，不能无期限返回过期订单状态。
      - 官方链接：[MDN Service Worker API](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)
    - 浏览器渲染性能
      - 含义：样式计算、布局、绘制和合成构成渲染流水线；频繁强制同步布局会造成卡顿。
      - 示例：批量读取布局后再统一写样式，动画优先使用 `transform` 和 `opacity`，并用 Performance 面板验证。
      - 官方链接：[web.dev Rendering Performance](https://web.dev/articles/rendering-performance)
  - TypeScript
    - TypeScript 与 JavaScript
      - 含义：TypeScript 是 JavaScript 的带类型超集，类型在编译后被擦除，最终仍由 JavaScript 运行时执行。
      - 示例：`number` 能阻止编译期传入字符串，但接口返回的未知 JSON 仍需运行时校验。
      - 官方链接：[TypeScript for the New Programmer](https://www.typescriptlang.org/docs/handbook/typescript-from-scratch.html)
    - 类型推断与显式注解
      - 含义：能从初值和上下文推断时不必重复注解；公共函数边界和复杂数据结构应明确输入输出类型。
      - 示例：`const count = 1` 自动推断为 number；`function parse(input: unknown): Order` 显式声明边界。
      - 官方链接：[TypeScript Everyday Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html)
    - 联合类型与字面量类型
      - 含义：联合类型表示多个可能类型，字面量类型把值限制在明确集合，适合状态和模式建模。
      - 示例：`type Status = 'PENDING' | 'PAID' | 'CANCELED'`，传入其他字符串会在编译期报错。
      - 官方链接：[TypeScript Everyday Types: Union Types](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#union-types)
    - interface 与 type
      - 含义：两者都能描述对象结构；interface 支持声明合并，type 更擅长联合、交叉和类型运算，项目应保持一致规则。
      - 示例：领域对象用 `interface User`，状态联合用 `type RequestState = Loading | Success | Failure`。
      - 官方链接：[TypeScript Object Types](https://www.typescriptlang.org/docs/handbook/2/objects.html)
    - 类型收窄
      - 含义：通过 `typeof`、`in`、判别字段和自定义类型守卫，把宽泛类型缩小到当前分支可安全使用的类型。
      - 示例：判断 `result.ok` 后，成功分支读取 `result.data`，失败分支读取 `result.error`。
      - 官方链接：[TypeScript Narrowing](https://www.typescriptlang.org/docs/handbook/2/narrowing.html)
    - 泛型
      - 含义：泛型在保持类型关系的前提下复用函数、组件和数据结构，避免把具体类型退化成 `any`。
      - 示例：`function first<T>(items: T[]): T | undefined` 返回值自动保持数组元素类型。
      - 官方链接：[TypeScript Generics](https://www.typescriptlang.org/docs/handbook/2/generics.html)
    - Utility Types
      - 含义：`Partial`、`Pick`、`Omit`、`Record` 等工具类型基于已有类型构造新类型，减少重复声明。
      - 示例：`type UserUpdate = Partial<Pick<User, 'name' | 'email'>>` 表示可选的用户可编辑字段。
      - 官方链接：[TypeScript Utility Types](https://www.typescriptlang.org/docs/handbook/utility-types.html)
    - unknown、any 与 never
      - 含义：`unknown` 使用前必须收窄，`any` 关闭类型检查，`never` 表示不可能出现的值或无法正常返回。
      - 示例：接口原始响应先标 `unknown` 并校验；用 `never` 做状态 switch 的穷尽检查。
      - 官方链接：[TypeScript Functions: never](https://www.typescriptlang.org/docs/handbook/2/functions.html#never)
    - 模块与类型声明
      - 含义：模块控制代码边界，`.d.ts` 描述没有内置类型的 JavaScript 库或全局 API。
      - 示例：为旧 SDK 编写 `legacy-sdk.d.ts`，声明其初始化参数和返回值，而不是在调用处到处写 `any`。
      - 官方链接：[TypeScript Modules](https://www.typescriptlang.org/docs/handbook/2/modules.html)
    - tsconfig 与 strict
      - 含义：`tsconfig.json` 定义编译目标、模块解析和严格检查；新项目应优先启用 `strict`。
      - 示例：开启 `strictNullChecks` 后，访问可能为空的 `user` 前必须判断或提供默认值。
      - 官方链接：[TypeScript TSConfig Reference](https://www.typescriptlang.org/tsconfig/)
    - 运行时校验边界
      - 含义：TypeScript 只检查编译期代码，接口、Storage、URL 和表单等外部数据必须用 Schema 在运行时验证。
      - 示例：用 Zod 解析 `fetch` 返回的 unknown 数据，失败时进入可控错误流程，不直接断言 `as User`。
      - 官方链接：[Zod Basic Usage](https://zod.dev/basics)
  - 样式与组件工程
    - CSS 自定义属性
      - 含义：CSS 变量在层叠中传递，适合主题、颜色、间距和组件 Token，并可在运行时切换。
      - 示例：根节点定义 `--color-primary`，暗色主题只覆盖 Token，不复制整套组件样式。
      - 官方链接：[MDN CSS Custom Properties](https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties)
    - Sass
      - 含义：Sass 在 CSS 上增加变量、嵌套、Mixin 和模块系统，构建后输出标准 CSS。
      - 示例：用 Mixin 复用响应式规则；避免过深嵌套导致选择器优先级难以维护。
      - 官方链接：[Sass Guide](https://sass-lang.com/guide/)
    - CSS Modules
      - 含义：CSS Modules 在构建时生成局部类名，减少全局样式冲突，适合组件级样式隔离。
      - 示例：引入 `Button.module.css` 后使用 `styles.primary`，不会与其他页面的 `.primary` 冲突。
      - 官方链接：[Vite CSS Modules](https://vite.dev/guide/features.html#css-modules)
    - Tailwind CSS
      - 含义：Tailwind 用可组合 Utility Class 构建设计，适合有统一 Token 和组件规范的团队，不等于无需组件抽象。
      - 示例：用响应式和状态类组合按钮外观，把重复业务组件封装起来，而不是复制长串类名。
      - 官方链接：[Tailwind Styling with Utility Classes](https://tailwindcss.com/docs/styling-with-utility-classes)
    - 组件库
      - 含义：Ant Design、Element Plus 等组件库提供表单、表格、弹窗和主题能力，应结合框架、交互密度和可访问性选型。
      - 示例：React 管理后台选 Ant Design，Vue 项目可选 Element Plus；业务规则仍封装在项目组件中。
      - 官方链接：[Ant Design Introduction](https://ant.design/docs/react/introduce)
    - Storybook
      - 含义：Storybook 在应用外独立开发和展示组件状态，适合组件库、视觉回归和团队共享。
      - 示例：为订单卡片创建默认、加载、空数据、超长文本和错误五个 Story。
      - 官方链接：[Storybook Why Storybook](https://storybook.js.org/docs/get-started/why-storybook)
    - Design Token
      - 含义：Design Token 用语义名称表达颜色、字号、间距和阴影，使设计与多端实现共享同一套决策。
      - 示例：使用 `color.status.danger` 而不是在各组件散落 `#ff4d4f`，主题切换时统一替换映射。
      - 官方链接：[Design Tokens Format Module](https://www.designtokens.org/tr/drafts/format/)
  - 前端通用工程
    - 组件化
      - 含义：把界面拆成职责清楚、输入输出明确的组件；是否拆分取决于复用和复杂度，不是越碎越好。
      - 示例：订单页拆成 `OrderFilter`、`OrderTable` 和 `OrderDetailDrawer`，页面组件负责组合与数据协调。
      - 官方链接：[Vue 组件基础](https://vuejs.org/guide/essentials/component-basics.html)
    - 单向数据流
      - 含义：父组件通过 Props 传数据，子组件通过事件表达变化意图，避免子组件直接修改父级状态。
      - 示例：父组件传入 `order`，子组件触发 `cancel` 事件，父组件调用取消接口并刷新列表。
      - 官方链接：[React 共享状态](https://react.dev/learn/sharing-state-between-components)
    - 本地状态与全局状态
      - 含义：只影响一个组件的状态放本地，跨页面共享的登录用户、权限和主题才进入全局状态。
      - 示例：弹窗开关用组件内 `open`；当前用户用 Pinia 或 Redux Store；服务端列表交给请求缓存管理。
      - 官方链接：[Redux Style Guide](https://redux.js.org/style-guide/)
    - 客户端路由
      - 含义：路由把 URL 映射到页面组件，并处理参数、嵌套页面、重定向和访问守卫。
      - 示例：`/orders/:id` 显示订单详情，进入前检查登录状态和订单读取权限。
      - 官方链接：[Vue Router 动态路由匹配](https://router.vuejs.org/guide/essentials/dynamic-matching.html)
    - 表单状态与校验
      - 含义：表单需要管理初值、编辑值、错误、提交中和服务端错误；前端校验用于体验，后端校验才可信。
      - 示例：邮箱为空立即显示必填提示，提交时禁用按钮，接口返回邮箱已存在后把错误绑定到邮箱字段。
      - 官方链接：[MDN 客户端表单校验](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Extensions/Forms/Form_validation)
    - 请求层封装
      - 含义：集中处理基础 URL、认证头、超时、错误解析和取消请求，业务组件只关心接口输入输出。
      - 示例：`orderApi.list(params)` 内部调用 `fetch`，统一把 `401` 转为重新登录流程。
      - 官方链接：[MDN Fetch API](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API/Using_Fetch)
    - 加载、空、错误与成功状态
      - 含义：异步页面至少要区分首次加载、无数据、失败、局部刷新和成功，避免只显示一个永久转圈。
      - 示例：列表首次请求显示骨架屏，空数组显示空状态，失败显示重试按钮，刷新时保留旧数据。

      - 示例：用户点击“选择位置”时再调用位置能力，拒绝后提供手动填写地址的替代方案。
      - 官方链接：[微信小程序用户隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)
    - 分包加载
      - 含义：把非首屏页面拆入分包可减小主包体积，改善首次下载与启动速度。
      - 示例：主包保留首页和登录，报表、管理后台和低频功能放到独立 `subpackages`。
      - 官方链接：[微信小程序分包加载](https://developers.weixin.qq.com/miniprogram/dev/framework/subpackages.html)
    - npm 支持
      - 含义：小程序可使用符合运行限制的 npm 包，开发者工具会把依赖构建为小程序可加载文件。
      - 示例：安装工具库后，在开发者工具执行“构建 npm”，并检查包体积和浏览器 API 兼容性。
      - 官方链接：[微信小程序 npm 支持](https://developers.weixin.qq.com/miniprogram/dev/devtools/npm.html)
    - 性能优化
      - 含义：重点关注启动耗时、包体积、`setData` 数据量、长列表和图片资源，并用性能面板验证。
      - 示例：只更新变化字段、列表分页、图片懒加载、低频页面分包，避免一次 `setData` 整个大对象。
      - 官方链接：[微信小程序性能优化](https://developers.weixin.qq.com/miniprogram/dev/framework/performance/)
    - 调试与发布
      - 含义：开发者工具用于调试和预览，体验版供测试，正式发布还需要上传代码、提交审核和发布版本。
      - 示例：先用真机预览验证授权和网络，再上传体验版回归，审核通过后由有权限人员发布。
      - 官方链接：[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/devtools.html)
  - Electron
    - Electron 定位
      - 含义：Electron 用 Chromium 渲染界面、用 Node.js 访问桌面能力，让 Web 技术构建 macOS、Windows 和 Linux 应用。
      - 示例：用 React 或 Vue 构建界面，Electron 提供窗口、菜单、文件系统、托盘和安装包能力。
      - 官方链接：[Electron Introduction](https://www.electronjs.org/docs/latest/)
    - 主进程
      - 含义：每个 Electron 应用只有一个主进程，负责应用生命周期、窗口创建和受信任的原生能力。
      - 示例：在 `app.whenReady()` 后创建 BrowserWindow，在全部窗口关闭时按平台规则决定是否退出。
      - 官方链接：[Electron Process Model: Main Process](https://www.electronjs.org/docs/latest/tutorial/process-model#the-main-process)
    - 渲染进程
      - 含义：每个窗口在独立渲染进程运行 Web 页面，默认不应直接拥有 Node.js 和操作系统高权限。
      - 示例：订单窗口运行 React 页面，只通过受控 API 请求读取文件，不直接调用 `fs.readFile`。
      - 官方链接：[Electron Process Model: Renderer Process](https://www.electronjs.org/docs/latest/tutorial/process-model#the-renderer-process)
    - BrowserWindow
      - 含义：BrowserWindow 管理桌面窗口、页面加载和 WebPreferences；窗口尺寸、显示时机和安全选项需要显式配置。
      - 示例：窗口先 `show: false`，等待 `ready-to-show` 再显示，减少白屏；外部 URL 不直接在应用窗口加载。
      - 官方链接：[Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)
    - Preload 与 contextBridge
      - 含义：Preload 在受控环境中连接主进程能力与页面，通过 contextBridge 暴露最小、明确、不可任意调用的 API。
      - 示例：只暴露 `window.files.openTextFile()`，不把整个 `ipcRenderer` 或任意文件路径读取能力暴露给页面。
      - 官方链接：[Electron Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)
    - IPC 通信
      - 含义：主进程与渲染进程通过 IPC 交换消息，`invoke/handle` 适合请求响应，`send/on` 适合事件通知。
      - 示例：渲染进程调用 `saveDocument(data)`，主进程验证数据和目标路径后保存并返回结果。
      - 官方链接：[Electron IPC](https://www.electronjs.org/docs/latest/tutorial/ipc)
    - Context Isolation
      - 含义：上下文隔离让 Preload 的特权环境与页面 JavaScript 使用不同全局对象，降低页面注入代码获得原生权限的风险。
      - 示例：保持 `contextIsolation: true`，通过 contextBridge 暴露窄接口，不向 `window` 直接挂高权限对象。
      - 官方链接：[Electron Context Isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)
    - Sandbox 与 Node Integration
      - 含义：渲染进程应启用沙箱并关闭 Node Integration，除非有充分威胁分析和隔离措施。
      - 示例：远程或用户生成内容只在沙箱渲染器中展示，不能获得 `require`、`process` 或文件系统访问。
      - 官方链接：[Electron Security Recommendations](https://www.electronjs.org/docs/latest/tutorial/security)
    - 导航与外部链接安全
      - 含义：必须限制窗口导航、新窗口创建和外部协议，不能让不可信页面在有特权的窗口中打开。
      - 示例：用 `will-navigate` 阻止未知来源，白名单 HTTPS 链接通过系统浏览器打开，并校验自定义协议参数。
      - 官方链接：[Electron Security: Navigation](https://www.electronjs.org/docs/latest/tutorial/security#13-disable-or-limit-navigation)
    - 原生能力边界
      - 含义：文件、剪贴板、通知、菜单和 Shell 都属于系统能力，应在主进程集中封装并校验输入。
      - 示例：文件选择由 dialog 返回用户明确选择的路径，保存前再次确认允许的目录和扩展名。
      - 官方链接：[Electron Main Process Modules](https://www.electronjs.org/docs/latest/api/app)
    - 应用生命周期
      - 含义：`ready`、`window-all-closed`、`activate` 和 `before-quit` 等事件决定不同平台上的启动、窗口恢复和退出行为。
      - 示例：macOS 关闭全部窗口后保留应用，点击 Dock 时重新创建窗口；退出前等待必要数据落盘。
      - 官方链接：[Electron app API](https://www.electronjs.org/docs/latest/api/app)
    - 打包与分发
      - 含义：开发目录不能直接交付用户，需要生成各平台安装包，并控制应用 ID、图标、资源和产物白名单。
      - 示例：macOS 生成 DMG，Windows 生成安装程序；发布前只上传用户需要的安装资产。
      - 官方链接：[Electron Packaging Your Application](https://www.electronjs.org/docs/latest/tutorial/tutorial-packaging)
    - 代码签名与公证
      - 含义：代码签名证明发布者身份并防止安装包被篡改，macOS 分发通常还需要 Apple 公证。
      - 示例：CI 从安全凭据存储读取签名证书，对最终安装包签名并在干净机器验证安装。
      - 官方链接：[Electron Code Signing](https://www.electronjs.org/docs/latest/tutorial/code-signing)
    - 自动更新
      - 含义：自动更新需要可信更新源、版本比较、签名验证、下载状态、失败恢复和用户确认策略。
      - 示例：后台检查新版本，下载完成后提示重启；更新失败不阻断旧版本启动，并保留手动下载入口。
      - 官方链接：[Electron Updating Applications](https://www.electronjs.org/docs/latest/tutorial/updates)
    - 性能
      - 含义：Electron 每个窗口都有 Chromium 成本，应减少不必要窗口、阻塞主进程工作和大型依赖。
      - 示例：CPU 密集任务放 Worker 或 Utility Process，窗口隐藏时暂停高频轮询，并分析启动阶段耗时。
      - 官方链接：[Electron Performance](https://www.electronjs.org/docs/latest/tutorial/performance)
    - 自动化测试
      - 含义：除普通前端测试外，还需验证主进程、IPC、窗口生命周期和打包应用的真实启动行为。
      - 示例：Playwright 启动 Electron，检查窗口出现、Preload API 可用、危险 Node 全局不可访问和关键流程完成。
      - 官方链接：[Electron Automated Testing](https://www.electronjs.org/docs/latest/tutorial/automated-testing)

- 后端
  - 后端通用工程
    - Controller 或 Router
      - 含义：接口入口负责接收请求、解析参数、调用业务层并组织响应，不承载大段业务规则。
      - 示例：`OrderController.create()` 校验请求模型后调用 `orderService.create(command)`，不直接写 SQL。
      - 官方链接：[Spring MVC Annotated Controllers](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller.html)
    - Service 业务层
      - 含义：业务层编排规则、事务和多个数据源，是“能不能做、按什么顺序做”的核心位置。
      - 示例：创建订单时检查库存、计算价格、保存订单并记录领域事件，整个写操作放在一个事务边界中。
      - 官方链接：[Spring Transaction Management](https://docs.spring.io/spring-framework/reference/data-access/transaction.html)
    - Repository 或 Mapper
      - 含义：数据访问层封装数据库查询和持久化细节，让业务层不依赖具体 SQL、连接和表结构操作。
      - 示例：`orderRepository.findById(id)` 返回订单对象，Service 不直接拼接 `SELECT * FROM orders`。
      - 官方链接：[Spring Data Repositories](https://docs.spring.io/spring-data/commons/reference/repositories/core-concepts.html)
    - DTO 与领域对象
      - 含义：请求 DTO、响应 DTO、数据库实体和领域对象职责不同，不能默认一个类贯穿所有层。
      - 示例：`CreateUserRequest` 接收密码，`UserResponse` 永不返回密码哈希，`UserEntity` 映射数据库字段。
      - 官方链接：[OWASP Mass Assignment Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Mass_Assignment_Cheat_Sheet.html)
    - 参数校验
      - 含义：后端在业务执行前校验类型、范围、格式和跨字段约束，并返回可定位的错误信息。
      - 示例：数量必须为 `1..999`，结束时间必须晚于开始时间，订单中的商品 ID 必须真实存在。
      - 官方链接：[Jakarta Bean Validation Specification](https://jakarta.ee/specifications/bean-validation/)
    - 统一异常处理
      - 含义：把业务异常、参数错误和系统异常集中映射为稳定错误结构，避免每个接口重复 try/catch。
      - 示例：`OrderNotFound` 映射为 `404` 和 `ORDER_NOT_FOUND`；未知异常记录 traceId 后返回通用 `500`。
      - 官方链接：[Spring MVC Exception Handler](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-exceptionhandler.html)
    - 统一响应与错误模型
      - 含义：成功和失败响应应有清晰一致的字段，但不要用 HTTP `200` 掩盖所有协议错误。
      - 示例：失败返回 `{code:'ORDER_CLOSED', message:'订单已关闭', traceId:'...'}`，HTTP 状态为 `409`。
      - 官方链接：[RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)
    - 依赖注入
      - 含义：对象不在内部自行创建依赖，而由容器或框架提供，便于替换实现、集中配置和测试隔离。
      - 示例：`OrderService` 构造函数接收 `OrderRepository`，测试时注入内存实现或 Mock。
      - 官方链接：[Spring IoC Container](https://docs.spring.io/spring-framework/reference/core/beans/introduction.html)
    - 配置外置化
      - 含义：端口、数据库地址、功能开关和第三方端点从环境或配置中心注入，同一构建产物可运行在不同环境。
      - 示例：应用读取 `DATABASE_URL` 和 `ORDER_TIMEOUT_SECONDS`，不把生产地址写进源码。
      - 官方链接：[12-Factor Config](https://12factor.net/config)
    - 日志
      - 含义：结构化日志记录时间、级别、服务、请求、traceId 和关键业务标识，不能泄露密码或令牌。
      - 示例：记录 `orderId=123 status=PAID traceId=abc`，错误日志保留异常栈，但脱敏手机号和身份证号。
      - 官方链接：[OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)
    - 事务
      - 含义：事务保证一组数据库操作要么全部成功，要么全部回滚；事务边界应覆盖完整业务不变量。
      - 示例：扣库存成功但订单写入失败时整体回滚，避免库存减少却没有订单。
      - 官方链接：[PostgreSQL Transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html)
    - 幂等
      - 含义：同一个业务请求重复执行时，最终效果与执行一次相同，常用于支付回调、重试和防重复提交。
      - 示例：客户端发送 `Idempotency-Key`，后端用唯一约束记录处理结果，重复请求直接返回首次结果。
      - 官方链接：[Stripe Idempotent Requests](https://docs.stripe.com/api/idempotent_requests)
    - 分页
      - 含义：大集合必须分页；页码分页简单但深页慢，游标分页适合持续增长和稳定滚动的数据。
      - 示例：管理后台用 `page=2&size=20`，时间线用 `cursor=last_created_at` 获取下一页。
      - 官方链接：[GitHub REST API Pagination](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api)
    - 文件上传
      - 含义：后端限制大小、类型和数量，使用随机存储名并隔离执行权限；大文件可直传对象存储。
      - 示例：客户端先向后端申请预签名 URL，再把图片上传对象存储，后端只保存文件元数据。
      - 官方链接：[OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
    - 同步与异步
      - 含义：必须立即返回结果的操作同步执行，耗时且可稍后完成的操作交给消息队列或任务系统。
      - 示例：创建订单同步返回订单号；短信、报表和搜索索引更新异步处理。
      - 官方链接：[RabbitMQ Work Queues](https://www.rabbitmq.com/tutorials/tutorial-two-python)
    - API 版本控制
      - 含义：破坏性接口变更需要版本或兼容期，新增可选字段通常可以向后兼容。
      - 示例：保留 `/api/v1/orders`，推出 `/api/v2/orders` 后给旧客户端迁移期限和弃用通知。
      - 官方链接：[Microsoft REST API Versioning](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md#12-versioning)
    - OpenAPI 与 Swagger UI
      - 含义：OpenAPI 用机器可读文档描述 HTTP 接口，Swagger UI 等工具可据此展示和调试，文档应由真实接口契约持续校验。
      - 示例：CI 校验 `openapi.yaml`，前端据此生成类型客户端；接口字段变化时文档和实现一起评审。
      - 官方链接：[OpenAPI Specification](https://spec.openapis.org/oas/latest.html)
    - GraphQL
      - 含义：GraphQL 让客户端按 Schema 查询所需字段，适合多端组合数据，但需治理鉴权、查询复杂度和 N+1 查询。
      - 示例：订单详情一次查询订单、客户和明细；每个 Resolver 仍按当前用户和资源执行授权。
      - 官方链接：[GraphQL Learn](https://graphql.org/learn/)
    - gRPC
      - 含义：gRPC 基于 Protocol Buffers 定义强类型服务和消息，常用于内部服务通信与流式调用，浏览器接入需要额外方案。
      - 示例：Java 订单服务调用库存 gRPC 接口，双方由同一 `.proto` 生成客户端和服务端代码。
      - 官方链接：[gRPC Introduction](https://grpc.io/docs/what-is-grpc/introduction/)
    - WebSocket 服务端

      - 含义：备份只有经过恢复演练才可信，需要明确恢复点目标、恢复时间目标和异地保存策略。
      - 示例：每日全量备份加持续 WAL 或 binlog，定期在隔离环境恢复并核对关键表与时间点。
      - 官方链接：[PostgreSQL Backup and Restore](https://www.postgresql.org/docs/current/backup.html)
  - 非关系型数据库与对象存储
    - MongoDB Document
      - 含义：MongoDB 以 BSON Document 保存嵌套数据，同一 Collection 中结构可灵活变化，但仍需要明确模型和校验。
      - 示例：内容草稿把可变区块保存为嵌套 Document；订单金额和库存等强一致关系数据仍优先关系库。
      - 官方链接：[MongoDB Documents](https://www.mongodb.com/docs/manual/core/document/)
    - MongoDB 数据建模
      - 含义：频繁一起读取且生命周期一致的数据可嵌入，独立增长或多处共享的数据适合引用，设计应围绕查询模式。
      - 示例：订单内少量地址快照直接嵌入；高增长的操作日志使用独立 Collection 并按订单 ID 查询。
      - 官方链接：[MongoDB Data Modeling](https://www.mongodb.com/docs/manual/data-modeling/)
    - MongoDB 索引
      - 含义：索引提升查询和排序速度但增加写入与存储成本，复合索引顺序同样需要依据真实查询设计。
      - 示例：按租户、状态和创建时间查文档时建立相应复合索引，并用 explain 验证是否命中。
      - 官方链接：[MongoDB Indexes](https://www.mongodb.com/docs/manual/indexes/)
    - MongoDB 事务
      - 含义：MongoDB 支持多文档事务，但单文档原子更新和合理嵌入通常更简单；不要用事务掩盖不合理模型。
      - 示例：必须同时修改两个 Collection 时使用短事务，普通嵌入订单状态更新保持单文档原子操作。
      - 官方链接：[MongoDB Transactions](https://www.mongodb.com/docs/manual/core/transactions/)
    - 对象存储
      - 含义：S3 等对象存储用于图片、视频、导出文件和备份，以 Bucket、Object Key 和元数据组织，不提供普通本地文件系统语义。
      - 示例：数据库只保存对象 Key、大小和内容类型，真实文件存 S3，下载时按权限生成访问地址。
      - 官方链接：[Amazon S3 User Guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html)
    - 预签名 URL
      - 含义：后端生成有时效和权限限制的 URL，让客户端直接上传或下载对象，避免大文件经过应用服务器中转。
      - 示例：前端申请 10 分钟有效的上传 URL，限制对象 Key 和 Content-Type，完成后通知后端保存元数据。
      - 官方链接：[Amazon S3 Presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)
    - 数据存储选型
      - 含义：关系库、文档库、Redis、Elasticsearch 和对象存储解决不同问题，应为每类数据指定唯一事实源和同步关系。
      - 示例：订单事实在 MySQL，热点副本在 Redis，搜索副本在 ES，附件在 S3；任何副本都能从事实源重建。
      - 官方链接：[AWS Database Purpose-Built](https://aws.amazon.com/products/databases/learn/)
  - Redis 缓存
    - Key-Value 与内存存储
      - 含义：Redis 以内存为主提供低延迟数据结构操作，适合缓存和临时状态，不自动替代业务数据库。
      - 示例：`order:123` 缓存订单详情 5 分钟，真实订单仍以 MySQL 记录为准。
      - 官方链接：[Redis Data Types](https://redis.io/docs/latest/develop/data-types/)
    - String
      - 含义：String 可保存文本、数字和序列化数据，并支持原子自增和过期。
      - 示例：用 `INCR rate:user:1` 统计请求次数，用 `SET key value EX 300` 写 5 分钟缓存。
      - 官方链接：[Redis Strings](https://redis.io/docs/latest/develop/data-types/strings/)
    - Hash
      - 含义：Hash 在一个 Key 下保存多个字段，适合小型对象的局部读写。
      - 示例：`HSET user:1 name Lin status ACTIVE`，更新状态时无需重写整个 JSON。
      - 官方链接：[Redis Hashes](https://redis.io/docs/latest/develop/data-types/hashes/)
    - List、Set 与 Sorted Set
      - 含义：List 维护顺序，Set 去重，Sorted Set 按分数排序，选择取决于业务访问方式。
      - 示例：Set 保存在线用户，Sorted Set 以积分为 score 维护排行榜。
      - 官方链接：[Redis Data Types](https://redis.io/docs/latest/develop/data-types/)
    - Cache Aside
      - 含义：读时先查缓存，未命中再查数据库并回填；写时先更新数据库再删除缓存。
      - 示例：查询订单未命中 Redis 后查 MySQL 并设置 TTL；订单更新提交成功后删除对应缓存 Key。
      - 官方链接：[Redis Cache-Aside Pattern](https://redis.io/learn/howtos/solutions/microservices/caching)
    - TTL 与淘汰
      - 含义：缓存 Key 应设置合理过期时间；内存达到上限时，Redis 根据淘汰策略移除部分 Key。
      - 示例：普通详情 TTL 5 分钟并加入少量随机抖动，避免大量 Key 同时过期。
      - 官方链接：[Redis Key Eviction](https://redis.io/docs/latest/develop/reference/eviction/)
    - 缓存穿透
      - 含义：大量查询不存在的数据会绕过缓存直达数据库，可用空值短缓存、布隆过滤器和请求校验缓解。
      - 示例：不存在的商品 ID 缓存空结果 30 秒，并限制非法 ID 范围。
      - 官方链接：[Redis Bloom Filter](https://redis.io/docs/latest/develop/data-types/probabilistic/bloom-filter/)
    - 缓存击穿
      - 含义：热点 Key 失效瞬间，大量并发同时回源数据库；可用互斥重建、逻辑过期或提前刷新。
      - 示例：商品首页热点缓存只允许一个请求重建，其他请求短暂等待或读取旧值。
      - 官方链接：[Redis Distributed Locks](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)
    - 缓存雪崩
      - 含义：大量 Key 同时失效或 Redis 故障会让请求集中压向数据库，需要过期抖动、限流、降级和高可用。
      - 示例：批量缓存 TTL 使用 `300 + random(0,60)` 秒，并为数据库设置并发保护。
      - 官方链接：[Redis High Availability](https://redis.io/docs/latest/operate/oss_and_stack/management/sentinel/)
    - 分布式锁
      - 含义：分布式锁用于跨进程互斥，但必须设置唯一持有者、过期时间和安全释放，并评估是否真需要。
      - 示例：`SET lock_key token NX PX 10000` 获取锁，释放时用脚本确认 token 相同后再删除。
      - 官方链接：[Redis Distributed Locks](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)
  - Elasticsearch 搜索
    - Index、Document 与 Field
      - 含义：Index 是文档集合，Document 是 JSON 记录，Field 是可搜索或聚合的字段。
      - 示例：`orders` 索引中的一个文档包含 `order_no`、`customer_name`、`status` 和 `created_at`。
      - 官方链接：[Elasticsearch Index Basics](https://www.elastic.co/docs/manage-data/data-store/index-basics)
    - Mapping
      - 含义：Mapping 定义字段类型和索引方式，类似数据库表结构与 TypeScript 接口的组合。
      - 示例：`status` 用 `keyword` 精确过滤，`description` 用 `text` 全文检索，`created_at` 用 `date`。
      - 官方链接：[Elasticsearch Mapping](https://www.elastic.co/docs/manage-data/data-store/mapping)
    - 倒排索引
      - 含义：倒排索引从词项定位包含它的文档，使全文搜索不必逐行扫描全部内容。
      - 示例：“冷链运输”被分析成词项后，ES 可快速找到包含这些词项的运单文档。
      - 官方链接：[Elasticsearch Inverted Index](https://www.elastic.co/guide/en/elasticsearch/reference/current/documents-indices.html)
    - Text 与 Keyword
      - 含义：`text` 会分词并用于相关性搜索，`keyword` 保留完整值用于精确过滤、排序和聚合。
      - 示例：姓名可有 `name` text 字段做搜索，同时用 `name.keyword` 做精确匹配和分组。
      - 官方链接：[Elasticsearch Text Field](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/text)
    - Analyzer
      - 含义：Analyzer 由字符过滤、Tokenizer 和 Token Filter 组成，索引与查询分析应匹配业务语言。
      - 示例：中文地址需要合适的中文分词方案；订单号应使用 keyword 而不是按普通文本分词。
      - 官方链接：[Elasticsearch Text Analysis](https://www.elastic.co/docs/manage-data/data-store/text-analysis)
    - Query 与 Filter
      - 含义：Query 计算相关性分数，Filter 判断是否匹配且更适合状态、时间、租户等精确条件。
      - 示例：商品名称用 `match` 查询，状态用 `term` filter，创建时间用 `range` filter。
      - 官方链接：[Elasticsearch Query and Filter Context](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-filter-context)
    - Aggregation
      - 含义：聚合对搜索结果做分组、统计、最大最小值和时间桶分析，类似 SQL 的 GROUP BY。
      - 示例：按订单状态统计数量，再按天生成订单趋势图。
      - 官方链接：[Elasticsearch Aggregations](https://www.elastic.co/docs/explore-analyze/query-filter/aggregations)
    - 分页
      - 含义：浅分页可用 `from/size`，深分页成本高，应使用 `search_after` 和稳定排序。
      - 示例：后台前 20 页用普通分页，大批量导出按 `created_at,id` 排序并使用 `search_after`。
      - 官方链接：[Elasticsearch Paginate Search Results](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/paginate-search-results)
    - Shard 与 Replica
      - 含义：主分片分布数据，副本分片提高读取能力和故障容忍；分片过多会增加集群开销。
      - 示例：根据数据量和节点数规划主分片，副本放在不同节点，不能简单为每个小业务建大量分片。
      - 官方链接：[Elasticsearch Clusters, Nodes and Shards](https://www.elastic.co/docs/deploy-manage/distributed-architecture/clusters-nodes-shards)
    - Alias 与重建索引
      - 含义：Alias 为一个或多个索引提供稳定名称，可在重建索引后原子切换，减少停机。
      - 示例：应用读取 `orders_read`，重建 `orders_v2` 完成后把 Alias 从 `orders_v1` 切到 `orders_v2`。
      - 官方链接：[Elasticsearch Aliases](https://www.elastic.co/docs/manage-data/data-store/aliases)
    - Bulk API
      - 含义：Bulk 在一次请求中批量索引、更新或删除文档，降低网络开销，但单批不能无限大。
      - 示例：数据库同步任务每批写入 500 个订单，并逐条检查 Bulk 响应中的失败项。
      - 官方链接：[Elasticsearch Bulk API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-bulk)
    - 数据一致性
      - 含义：业务数据库通常是事实源，ES 是可重建搜索副本；同步失败需要重试、补偿和对账。
      - 示例：订单事务提交后通过 Outbox 发送变更事件，消费者幂等更新 ES，定时任务校验漏同步数据。
      - 官方链接：[Debezium Outbox Pattern](https://debezium.io/documentation/reference/stable/transformations/outbox-event-router.html)
  - 微服务与服务治理
    - 单体与微服务
      - 含义：单体部署简单、事务直接；微服务按业务边界独立部署，但引入网络、数据一致性和运维复杂度。
      - 示例：早期订单系统先做模块化单体；团队和业务边界稳定后，再把支付等独立能力拆成服务。
      - 官方链接：[AWS Microservices](https://docs.aws.amazon.com/whitepapers/latest/microservices-on-aws/microservices-on-aws.html)
    - 服务拆分边界
      - 含义：围绕业务能力、数据所有权和团队职责拆分，不按 Controller、Service、数据库等技术层拆服务。
      - 示例：订单服务拥有订单数据，库存服务拥有库存数据；不会拆成“Controller 服务”和“数据库服务”。
      - 官方链接：[Microsoft Domain Analysis for Microservices](https://learn.microsoft.com/en-us/azure/architecture/microservices/model/domain-analysis)
    - Eureka 服务注册与发现
      - 含义：服务实例向注册中心登记地址，调用方通过服务名发现健康实例，适用于使用 Netflix Eureka 的既有系统。
      - 示例：`order-service` 启动后注册，网关通过服务名选择一个可用实例，不把 IP 写死在代码里。
      - 官方链接：[Spring Cloud Netflix Service Discovery](https://docs.spring.io/spring-cloud-netflix/reference/spring-cloud-netflix.html#service-discovery-eureka-clients)
    - OpenFeign 远程调用
      - 含义：OpenFeign 用声明式 Java 接口调用 HTTP 服务，但网络超时、重试和降级仍需明确处理。
      - 示例：`InventoryClient.getStock(sku)` 调用库存服务，设置连接与读取超时，避免无限等待。
      - 官方链接：[Spring Cloud OpenFeign](https://docs.spring.io/spring-cloud-openfeign/reference/)
    - API Gateway
      - 含义：网关提供统一入口，可处理路由、认证、限流和观测，但不应堆积具体业务逻辑。
      - 示例：`/api/orders/**` 路由到订单服务，网关校验通用 Token，订单权限仍由订单服务判断。
      - 官方链接：[Spring Cloud Gateway](https://docs.spring.io/spring-cloud-gateway/reference/)
    - 负载均衡
      - 含义：把请求分配到多个健康实例，提高吞吐和可用性；算法要结合会话、权重和实例能力。
      - 示例：Nginx 把请求轮询到三个后端实例，健康检查失败的实例暂时移出。
      - 官方链接：[NGINX HTTP Load Balancing](https://docs.nginx.com/nginx/admin-guide/load-balancer/http-load-balancer/)
    - 超时
      - 含义：每个网络调用都应设置连接、读取和总时限，否则下游卡住会耗尽线程与连接池。
      - 示例：页面总预算 2 秒时，库存调用设置 500ms 超时，而不是允许单个下游等待 30 秒。
      - 官方链接：[Resilience4j TimeLimiter](https://resilience4j.readme.io/docs/timeout)
    - 重试
      - 含义：只对短暂且可安全重放的失败重试，使用退避和抖动；非幂等写操作不能盲目重试。
      - 示例：读取配置遇到瞬时网络错误最多重试 3 次；创建支付前先有幂等键再考虑重试。
      - 官方链接：[AWS Retry with Backoff](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/retry-backoff.html)
    - 熔断与降级
      - 含义：下游持续失败时熔断快速拒绝，给系统恢复时间；降级返回可接受的简化结果。
      - 示例：推荐服务故障时首页不再等待，直接隐藏推荐区域；订单核心流程不伪造成功结果。
      - 官方链接：[Resilience4j CircuitBreaker](https://resilience4j.readme.io/docs/circuitbreaker)
    - 限流
      - 含义：按用户、租户、接口或全局限制请求速率，保护服务和下游资源免受突发流量压垮。
      - 示例：登录接口每 IP 每分钟 20 次，超限返回 `429` 和合理的重试提示。
      - 官方链接：[NGINX Rate Limiting](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)
    - Apollo AppId、环境与集群
      - 含义：AppId 标识应用，环境区分开发测试生产，集群允许同一环境下按机房或分组覆盖配置。
      - 示例：`order-service` 在 `PRO` 环境读取默认集群，上海机房可用独立 Cluster 覆盖下游地址。
      - 官方链接：[Apollo 核心概念](https://www.apolloconfig.com/#/zh/design/apollo-introduction?id=%e4%b8%80%e3%80%81%e4%bb%80%e4%b9%88%e6%98%afapollo)
    - Apollo Namespace
      - 含义：Namespace 把数据库、Redis、业务开关等配置按作用域组织，可由多个应用共享公共配置。
      - 示例：`application` 放应用私有配置，`redis.yml` 放共享 Redis 客户端配置，敏感值限制访问权限。
      - 官方链接：[Apollo Java Client 使用指南](https://www.apolloconfig.com/#/zh/usage/java-sdk-user-guide)
    - Apollo 发布与动态更新
      - 含义：修改只形成待发布配置，发布后客户端才收到新版本；动态刷新必须确认代码和 Bean 支持更新。
      - 示例：修改功能开关后先在测试环境发布验证，再灰度到部分生产实例并观察指标。
      - 官方链接：[Apollo 配置发布](https://www.apolloconfig.com/#/zh/usage/apollo-user-guide?id=%e4%b8%89%e3%80%81%e9%83%a8%e9%97%a8%e7%ae%a1%e7%90%86)
    - Apollo 灰度发布
      - 含义：灰度发布让指定实例先获得新配置，降低一次性全量变更风险，并支持观察后全量或回滚。
      - 示例：先让一个订单实例使用新超时配置，确认错误率和延迟正常后再全量发布。
      - 官方链接：[Apollo 灰度发布使用指南](https://www.apolloconfig.com/#/zh/usage/apollo-user-guide?id=%e4%b8%83%e3%80%81%e7%81%b0%e5%ba%a6%e5%8f%91%e5%b8%83)
    - Nacos 配置与服务发现
      - 含义：Nacos 同时提供动态配置和服务发现，是另一种常见治理方案；同一系统不应无目的重复建设多个配置源。
      - 示例：新系统可用 Nacos 注册服务并管理配置，已有 Apollo 加 Eureka 系统则先评估迁移收益和兼容成本。
      - 官方链接：[Nacos Concepts](https://nacos.io/docs/latest/what-is-nacos/)
  - 消息队列与任务
    - 消息队列的作用
      - 含义：消息队列用于异步、削峰和解耦；它增加最终一致性、重复消费和运维复杂度，不是所有调用都需要 MQ。
      - 示例：订单创建后发送事件，短信和积分各自消费；订单创建结果本身仍同步返回。
      - 官方链接：[Apache Kafka Introduction](https://kafka.apache.org/intro)
    - Kafka Topic
      - 含义：Topic 是一类消息的逻辑频道，命名应表达业务事件并明确消息 Schema。
      - 示例：`order-created-v1` 只承载订单创建事件，不把所有业务消息塞进 `common-topic`。
      - 官方链接：[Apache Kafka Introduction](https://kafka.apache.org/intro)
    - Kafka Partition
      - 含义：Partition 是 Topic 的有序分片和并行单位，同一 Partition 内有序，不同 Partition 不保证全局顺序。
      - 示例：用 `orderId` 作为 Key，使同一订单事件进入同一 Partition 并保持顺序。
      - 官方链接：[Kafka Design: Distribution](https://kafka.apache.org/documentation/#design_distribution)
    - Kafka Offset
      - 含义：Offset 表示消费者在 Partition 中的读取位置，提交时机影响重复消费或消息丢失风险。
      - 示例：业务处理和数据库提交成功后再提交 Offset；进程崩溃可能导致重放，因此消费者要幂等。
      - 官方链接：[Kafka Consumer Configs](https://kafka.apache.org/documentation/#consumerconfigs)
    - Consumer Group
      - 含义：同一消费组内实例分摊 Partition，不同消费组各自收到完整消息流。
      - 示例：短信组和积分组都会消费订单事件；短信组的三个实例之间分摊 Partition。
      - 官方链接：[Kafka Consumer Groups](https://kafka.apache.org/documentation/#intro_consumers)
    - 消息幂等
      - 含义：MQ 通常至少一次投递，消费者必须识别重复消息，不能假设每条消息只到一次。
      - 示例：用 `eventId` 建唯一处理记录；同一支付成功事件再次到达时直接返回已处理。
      - 官方链接：[Kafka Delivery Semantics](https://kafka.apache.org/documentation/#semantics)
    - 重试与死信队列
      - 含义：暂时失败进入有退避的重试，无法恢复或格式错误进入死信队列，等待告警和人工处理。
      - 示例：第三方接口超时重试 3 次；缺少必填字段的消息直接进入 DLQ 并记录原消息与错误。
      - 官方链接：[RabbitMQ Dead Letter Exchanges](https://www.rabbitmq.com/docs/dlx)
    - Outbox Pattern
      - 含义：业务数据和待发送事件写入同一数据库事务，再由独立发布器发送，避免“数据库成功但消息没发”。
      - 示例：订单和 `outbox_event` 同事务提交，后台进程把未发送事件发布 Kafka 后标记完成。
      - 官方链接：[Debezium Outbox Event Router](https://debezium.io/documentation/reference/stable/transformations/outbox-event-router.html)
    - RabbitMQ
      - 含义：RabbitMQ 通过 Exchange、Queue 和 Binding 灵活路由消息，常用于工作队列和业务消息分发。
      - 示例：`order` Exchange 按 Routing Key 把创建、取消事件投递到不同 Queue。
      - 官方链接：[RabbitMQ Tutorials](https://www.rabbitmq.com/tutorials)
    - XXL-JOB 调度中心与执行器
      - 含义：调度中心管理 Cron、执行记录和路由，执行器在业务服务中运行具体任务。
      - 示例：每天 02:00 调度对账任务，调度中心记录开始、结束和失败日志，执行器访问业务数据。
      - 官方链接：[XXL-JOB Documentation](https://www.xuxueli.com/xxl-job/)
    - Cron 表达式
      - 含义：Cron 描述重复执行时间，必须明确时区、错过执行策略和是否允许并发。
      - 示例：日报任务每天凌晨运行；发布前在测试环境验证表达式，避免把“每月”写成“每天”。
      - 官方链接：[Spring Cron Expressions](https://docs.spring.io/spring-framework/reference/integration/scheduling.html#scheduling-cron-expression)
    - 分布式任务幂等
      - 含义：多实例、超时重试和故障转移可能让同一任务执行多次，任务必须有业务唯一键或分布式互斥。
      - 示例：对账任务以“账期 + 商户”为唯一键，重复执行只更新同一结果，不重复入账。
      - 官方链接：[XXL-JOB Documentation](https://www.xuxueli.com/xxl-job/)
  - 认证、授权与安全
    - 密码存储
      - 含义：密码必须使用专用慢哈希算法加盐存储，不能明文、可逆加密或普通快速哈希。
      - 示例：使用 Argon2id 或 bcrypt 保存密码哈希，登录时验证，不在日志中记录密码。
      - 官方链接：[OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
    - Session 认证
      - 含义：服务端保存会话状态，浏览器持有不可猜测的会话 ID；适合传统 Web 和可控服务端存储场景。
      - 示例：登录后写 HttpOnly Cookie，服务端 Redis 保存 sessionId 到 userId 的映射并设置过期时间。
      - 官方链接：[OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
    - JWT
      - 含义：JWT 是带签名的声明载体，不等于自动安全；需要校验签名、算法、签发者、受众和过期时间。
      - 示例：Access Token 只放必要用户 ID 和权限声明，短期过期；服务端拒绝未预期算法和错误受众。
      - 官方链接：[RFC 7519 JSON Web Token](https://www.rfc-editor.org/rfc/rfc7519.html)
    - OAuth 2.0 与 OpenID Connect
      - 含义：OAuth 2.0 处理委托授权，OpenID Connect 在其上增加用户身份；客户端类型决定安全流程。
      - 示例：Web 或移动应用使用 Authorization Code + PKCE 登录第三方身份提供商。
      - 官方链接：[OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html)
    - RBAC
      - 含义：RBAC 把权限分配给角色，再把角色分配给用户；最终授权还需结合资源归属和租户边界。
      - 示例：客服角色可读订单但不能退款；管理员也只能管理自己租户的数据。
      - 官方链接：[NIST RBAC](https://csrc.nist.gov/projects/role-based-access-control)
    - 最小权限
      - 含义：用户、服务账号和数据库账号只拥有完成职责所需权限，并定期审查和回收。
      - 示例：报表服务数据库账号只有只读权限，不能删除订单表或修改用户密码。
      - 官方链接：[OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)
    - SQL 注入
      - 含义：把用户输入拼入 SQL 会改变语句结构，应使用参数化查询和受控动态字段白名单。
      - 示例：使用 `WHERE id = ?` 绑定参数；排序字段从允许集合映射，不能直接拼接请求中的 `sort`。
      - 官方链接：[OWASP SQL Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html)
    - CSRF
      - 含义：浏览器自动携带 Cookie 时，恶意站点可能诱导用户发送写请求，需要 SameSite、CSRF Token 和来源校验。
      - 示例：转账 POST 请求要求 CSRF Token，Cookie 设置合适 SameSite，并拒绝异常 Origin。
      - 官方链接：[OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)
    - SSRF
      - 含义：后端按用户提供的 URL 发请求时，攻击者可能访问内网和云元数据；需要目的地址白名单和网络隔离。
      - 示例：图片抓取服务只允许 HTTPS 和批准域名，解析 DNS 后仍拒绝私网、环回和链路本地地址。
      - 官方链接：[OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
    - HTTPS 与 TLS
      - 含义：TLS 加密传输并验证服务端身份，生产接口不应通过明文 HTTP 传递会话和个人数据。
      - 示例：Nginx 终止 TLS，HTTP 自动跳转 HTTPS，内部敏感链路按威胁模型使用 TLS 或 mTLS。
      - 官方链接：[Mozilla TLS Configuration](https://wiki.mozilla.org/Security/Server_Side_TLS)
    - 密钥管理
      - 含义：API Key、数据库密码和私钥不得提交 Git、写入前端包或打印日志，应由专用 Secret 系统注入。
      - 示例：CI 从 Secret Store 注入 `DATABASE_URL`，本地使用不提交的环境文件，发现泄露立即轮换。
      - 官方链接：[OWASP Secrets Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)
- 测试
  - 测试设计基础
    - 测试金字塔
      - 含义：大量快速单元测试覆盖规则，适量集成测试覆盖边界，少量 E2E 覆盖关键流程，避免所有问题都靠慢速 UI 测试发现。
      - 示例：价格计算写单测，Repository 写数据库集成测试，下单支付保留少量关键 E2E。
      - 官方链接：[Martin Fowler Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html)
    - Arrange、Act、Assert
      - 含义：用例先准备输入与依赖，再执行一个行为，最后断言可观察结果，使失败原因清楚。
      - 示例：准备库存 1，执行购买 2 件，断言抛出库存不足且数据库没有新订单。
      - 官方链接：[JUnit Writing Tests](https://docs.junit.org/current/user-guide/#writing-tests)
    - 正常、边界与异常路径
      - 含义：测试不仅覆盖正常输入，还要覆盖空值、最小最大值、状态冲突、超时和依赖失败。
      - 示例：数量分别测试 `1`、`999`、`0`、`1000` 和非数字，支付测试成功、拒绝、超时和重复回调。
      - 官方链接：[OWASP Web Security Testing Guide](https://owasp.org/www-project-web-security-testing-guide/)
    - 可重复与确定性
      - 含义：同一代码和环境下测试应稳定得到相同结果；真实时间、随机数、共享数据和外部网络都会制造 Flaky Test。
      - 示例：注入 Clock 和固定随机种子，每个用例创建独立数据，不依赖公共测试账号的当前状态。
      - 官方链接：[Google Testing Blog: Flaky Tests](https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html)
    - 测试隔离
      - 含义：用例不能依赖执行顺序或前一个用例留下的数据，并行运行时也不能相互覆盖。
      - 示例：每个用例使用唯一订单号，数据库事务回滚或容器重置，文件写入独立临时目录。
      - 官方链接：[Playwright Test Isolation](https://playwright.dev/docs/browser-contexts)
    - 测试数据与 Fixture
      - 含义：Fixture 负责构造可读、最小、可清理的数据；Builder 适合表达不同业务场景而非复制大对象。
      - 示例：`paidOrder()` 创建默认已支付订单，用参数只覆盖退款测试关心的金额和时间。
      - 官方链接：[pytest Fixtures](https://docs.pytest.org/en/stable/how-to/fixtures.html)
    - Test Double
      - 含义：Dummy 只占位，Stub 返回预设值，Fake 是简化实现，Spy 记录调用，Mock 验证交互；应按测试目标选择。
      - 示例：内存 Repository 是 Fake，固定汇率服务是 Stub，验证邮件发送一次可使用 Mock。
      - 官方链接：[Martin Fowler Mocks Aren't Stubs](https://martinfowler.com/articles/mocksArentStubs.html)
    - 代码覆盖率
      - 含义：覆盖率说明哪些代码被执行，不证明断言正确；应结合关键业务、分支和变异测试判断质量。
      - 示例：即使行覆盖率 100%，若没有断言扣款金额，测试仍不能发现计算错误。
      - 官方链接：[Martin Fowler Test Coverage](https://martinfowler.com/bliki/TestCoverage.html)
    - 变异测试
      - 含义：变异测试主动修改条件和运算符，检查现有测试能否失败，用于发现“执行了但没真正验证”的代码。
      - 示例：把 `amount > 0` 改成 `amount >= 0`，若测试仍通过，说明边界断言不足。
      - 官方链接：[PIT Mutation Testing Quickstart](https://pitest.org/quickstart/)

    - HPA 自动扩缩容
      - 含义：HorizontalPodAutoscaler 根据 CPU、内存或自定义指标调整工作负载副本数，需要合理的资源请求和稳定指标。
      - 示例：订单请求量上升时按 CPU 和队列积压扩容，低峰期缩容但保留最小可用副本。
      - 官方链接：[Kubernetes Horizontal Pod Autoscaling](https://kubernetes.io/docs/tasks/run-application/horizontal-pod-autoscale/)
    - StatefulSet
      - 含义：StatefulSet 为有状态工作负载提供稳定网络身份、有序部署和稳定存储关联，不代表数据库天然获得高可用。
      - 示例：每个消息节点保持固定名称和独立 Volume，并由数据库或消息系统自身机制处理复制与选主。
      - 官方链接：[Kubernetes StatefulSets](https://kubernetes.io/docs/concepts/workloads/controllers/statefulset/)
    - PersistentVolume 与 PersistentVolumeClaim
      - 含义：PV 表示集群存储资源，PVC 表示工作负载的存储申请，两者把应用需求与具体存储实现解耦。
      - 示例：PostgreSQL StatefulSet 通过 PVC 申请存储，Pod 重建后重新挂载对应数据卷。
      - 官方链接：[Kubernetes Persistent Volumes](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)
    - Helm Chart
      - 含义：Helm Chart 把 Kubernetes 模板、默认值和版本元数据打包，便于不同环境复用与发布，但模板复杂度需要控制。
      - 示例：同一 Chart 通过不同 values 设置副本数、镜像版本和域名，并在发布前渲染检查最终清单。
      - 官方链接：[Helm Charts](https://helm.sh/docs/topics/charts/)
  - CI
    - 含义：持续集成在每次变更时自动安装依赖、静态检查、测试和构建，尽早暴露问题。
    - 示例：Pull Request 必须通过前端测试、后端测试、数据库迁移检查和镜像构建才能合并。
    - 官方链接：[GitHub Actions Continuous Integration](https://docs.github.com/en/actions/about-github-actions/about-continuous-integration-with-github-actions)
  - CD
    - 含义：持续交付或部署把经过验证的同一构建产物推进环境，并保留审批、审计和回滚能力。
    - 示例：同一镜像先部署测试环境，验证通过后提升到生产，而不是在生产重新构建另一份代码。
    - 官方链接：[GitHub Actions Deployments](https://docs.github.com/en/actions/how-tos/deploy)
  - 日志、指标与 Trace
    - 含义：日志描述离散事件，指标反映聚合趋势，Trace 串联一次请求经过的服务；三者通过 traceId 和标签关联。
    - 示例：告警发现错误率上升，Trace 定位库存服务慢，日志用 traceId 查到具体 SQL 超时。
    - 官方链接：[OpenTelemetry Signals](https://opentelemetry.io/docs/concepts/signals/)
  - Prometheus
    - 含义：Prometheus 按时间序列采集指标并支持 PromQL，适合请求量、错误率、延迟和资源监控。
    - 示例：统计 `http_requests_total` 错误比例，并按服务和接口维度告警。
    - 官方链接：[Prometheus Getting Started](https://prometheus.io/docs/prometheus/latest/getting_started/)
  - Grafana
    - 含义：Grafana 查询多个数据源并展示 Dashboard、告警和关联视图，图表必须有明确单位和维度。
    - 示例：一个服务面板同时显示 QPS、P95 延迟、错误率、CPU、数据库池等待和发布标记。
    - 官方链接：[Grafana Dashboards](https://grafana.com/docs/grafana/latest/dashboards/)
  - traceId 全链路排障
    - 含义：入口生成或接收 traceId，并透传到网关、服务、消息和日志，从而关联一次业务请求的完整链路。
    - 示例：用户提供错误页面的 traceId，先查网关，再查订单、库存和数据库跨度，定位第一个异常点。
    - 官方链接：[OpenTelemetry Traces](https://opentelemetry.io/docs/concepts/signals/traces/)
  - 告警设计
    - 含义：告警应基于用户影响和可行动条件，包含服务、时间、阈值、上下文和处理入口，避免纯噪音。
    - 示例：5 分钟错误率超过 2% 且请求数大于阈值时告警，并附 Dashboard 与 Runbook 链接。
    - 官方链接：[Prometheus Alerting Rules](https://prometheus.io/docs/prometheus/latest/configuration/alerting_rules/)
- 业务
  - Web 查询列表
    - 含义：前端路由加载页面，状态层发请求，网关转发，后端校验并分页查询，结果返回后渲染状态。
    - 示例：`React 页面 -> TanStack Query -> GET /orders -> Gateway -> Controller -> Service -> MySQL -> JSON -> 表格`。
    - 官方链接：[MDN Client-Server Overview](https://developer.mozilla.org/zh-CN/docs/Learn_web_development/Extensions/Server-side/First_steps/Client-Server_overview)
  - 微信登录
    - 含义：小程序取得临时 code，后端与微信服务交换身份信息，再建立应用自己的会话和权限。
    - 示例：`wx.login -> code -> 后端 -> code2Session -> 用户绑定 -> session token -> 小程序 Storage`。
    - 官方链接：[微信小程序登录时序](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)
  - 创建订单
    - 含义：写请求经过前端防重复、后端认证、参数校验、幂等、事务写库和异步事件发布。
    - 示例：`提交按钮 -> Idempotency-Key -> OrderService -> MySQL 事务 -> Outbox -> Kafka -> 短信/索引消费者`。
    - 官方链接：[Debezium Outbox Event Router](https://debezium.io/documentation/reference/stable/transformations/outbox-event-router.html)
  - 缓存查询
    - 含义：后端先读 Redis，命中直接返回；未命中查数据库并回填；写入成功后删除或更新缓存。
    - 示例：`GET /orders/1 -> Redis miss -> MySQL -> SET EX -> response`，更新订单后删除 `order:1`。
    - 官方链接：[Redis Caching](https://redis.io/learn/howtos/solutions/microservices/caching)
  - 全文搜索
    - 含义：数据库作为事实源，变更事件同步到 Elasticsearch，搜索接口查询 ES 并返回业务可见字段。
    - 示例：`MySQL commit -> Outbox/Kafka -> Indexer -> orders 索引 -> /search -> 前端搜索列表`。
    - 官方链接：[Elasticsearch Search](https://www.elastic.co/docs/solutions/search)
  - 配置变更
    - 含义：配置在 Apollo 修改并发布，客户端拉取或接收通知，支持动态的 Bean 更新后才实时生效。
    - 示例：先灰度一个实例的新超时值，观察延迟和错误率，再全量发布或回滚旧版本。
    - 官方链接：[Apollo 用户使用指南](https://www.apolloconfig.com/#/zh/usage/apollo-user-guide)
  - 定时对账
    - 含义：调度中心按 Cron 触发执行器，任务分片读取数据、幂等处理并记录结果和指标。
    - 示例：`XXL-JOB -> 对账 Handler -> 分页查订单 -> 比对支付 -> 保存差异 -> 告警`。
    - 官方链接：[XXL-JOB Documentation](https://www.xuxueli.com/xxl-job/)
  - 故障定位
    - 含义：从用户现象和时间开始，用请求、状态码、traceId、指标、Trace、日志和数据逐层缩小范围。
    - 示例：页面 `500 -> Network 查 traceId -> Dashboard 查错误率 -> Trace 找慢服务 -> 日志查异常栈 -> SQL 执行计划`。
    - 官方链接：[OpenTelemetry Observability Primer](https://opentelemetry.io/docs/concepts/observability-primer/)
