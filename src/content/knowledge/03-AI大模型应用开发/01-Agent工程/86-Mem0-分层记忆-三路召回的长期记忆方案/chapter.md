# Mem0：分层记忆 + 三路召回的长期记忆方案

> 读完你能：理解长期记忆为什么要分层、召回和更新，而不是把用户历史全塞进上下文。
> 来源：`吃透 AI Agent 开发` 截图目录第 34 篇，2026/06/06
> 导入与重写日期：2026/07/07

## 本篇定位

这是长期 Memory 篇，和 85 的短期记忆互补。

## 一个真实场景

用户希望 Agent 记住“我偏好中文回答”“我负责支付系统”“以后生成周报要按这个模板”。这些信息跨会话有效，但不是每次都要全部加载。长期记忆系统要能写入、更新、遗忘，并在相关问题出现时召回。

## 核心拆解

- 长期记忆通常分用户画像、事实记忆、偏好记忆、任务记忆。不同层的更新频率和使用方式不同。
- 三路召回可以理解为：语义相似召回、关键词/标签召回、时间/关系召回。多路组合比单纯向量更稳。
- 记忆需要治理。过期、冲突、敏感、错误记忆都要能删除或覆盖。

## 工程链路

- 从对话中抽取候选记忆。
- 判断是否值得长期保存。
- 写入带类型和时间的记忆库。
- 新请求到来时多路召回相关记忆。
- 注入 prompt 前做冲突和权限过滤。
- 用户可查看和删除记忆。

## 落地建议

- 保存记忆前最好让用户可感知或可管理。
- 记忆条目要短、具体、可验证。
- 冲突记忆按时间和可信来源解决。

## 常见坑

- 把所有聊天总结都当长期记忆。
- 用户改了偏好后旧记忆仍被召回。
- 敏感信息没有删除入口。

## 设计判断

长期记忆最重要的是“用户可控”。Agent 记住用户偏好会提升体验，但记错、记过期、记了敏感内容都会伤害信任。一个合格的长期记忆系统应该让用户知道系统记住了什么，并允许查看、修改和删除。写入记忆时也要区分事实和推测：用户明确说“我负责支付系统”是一条事实；模型从对话里猜“用户可能喜欢后端”就不应该直接写入长期记忆。

## 复述答法

> 长期记忆不是聊天记录仓库，而是经过抽取、分类、召回和治理的用户知识库。分层管理记忆，多路召回相关条目，并提供更新、遗忘和删除能力，才能长期可用。
