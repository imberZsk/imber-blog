# 17 文件上传与文档解析 demo

把 txt / md 文档解析成带元数据的文本块（chunk），这是 RAG 的入库入口。演示三件事：按文件类型选解析方式、把长文档切成大小可控的 chunk、每个 chunk 带上来源和章节元数据。

## 运行

```bash
python3 main.py
```

零依赖，纯标准库。解析的是同目录下的 `sample.md` 和 `sample.txt`。

## 预期输出

```
=== sample.md 解析出 4 个 chunk ===
  [1] (员工报销制度/提交时限) 员工报销需要在费用发生后的 30 天内提交，逾期需要部门经理书面说明。
  [2] (员工报销制度/报销材料) 报销需要提供发票原件、审批单，以及对应的合同或采购单。电子发票需打印后粘贴。
  [3] (差旅管理/交通标准) 经理级别可乘坐高铁一等座，员工乘坐二等座。机票需提前 7 天预订。
  [4] (差旅管理/住宿标准) 一线城市住宿标准为每晚 500 元，其它城市 350 元，超出部分自理。

=== sample.txt 解析出 4 个 chunk ===
  [1] (正文) 公司班车时刻表说明。
  [2] (正文) 早班车每天 8 点从地铁站发车，晚班车 18 点 30 分从公司发车。
  [3] (正文) 节假日班车停运，具体安排以行政通知为准。
  [4] (正文) 雨雪天气班车可能延迟，请关注企业微信群通知。

每个 chunk 都带 source + 章节，检索命中后就能标出「依据：xxx」。
```

注意 md 和 txt 的区别：md 顺着 `#`/`##` 标题切，每个 chunk 知道自己属于「差旅管理 / 住宿标准」；txt 没有结构，只能按段落切、章节统一标「正文」。这就是为什么有结构的文档检索效果更好。

## 代码↔概念对应

| 概念 | 在 main.py 哪里 |
|---|---|
| 按扩展名分派解析器 | `parse_file` |
| Markdown 按标题层级切分 | `parse_markdown` |
| 纯文本按段落切分 | `parse_text` |
| 长文本按标点二次切分 | `split_long` |
| 每个 chunk 带 source + 章节元数据 | 各解析器里构造的 `metadata` |

## 动手改

- 把 `MAX_CHUNK_CHARS` 从 60 调成 20，看长句怎么被 `split_long` 在标点处切成更多小块。
- 往 `sample.md` 加一节新内容，重跑看是否多出对应 chunk。
- 加一个 `.json` 分支到 `parse_file`，体会「加格式只加一个解析分支」——但先让 txt/md 扎实，别一上来支持所有格式。
