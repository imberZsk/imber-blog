# 二、题目与详细答案

## 2.1 第91题：请设计一个企业内部知识问答系统。

**答案：** 离线用连接器获取文档，
布局解析、结构分块，
附租户/ACL/来源/版本，
生成 Embedding，
同时写 ES BM25 与向量库；
作业对账后发布索引版本。
在线鉴权、Query 改写，
多路召回下推权限，
RRF+Rerank，
按 Token 组装证据，
结构化生成并校验引用。
配套评测集、Trace、反馈回流、增量删除、蓝绿索引、超时降级和跨租户安全测试。

## 2.2 第92题：如何设计完全离线的 RAG？

**答案：** 文档解析/OCR、Embedding 权重、向量库、Rerank 和生成模型都在本地网络，
依赖包与模型权重预先镜像；
禁用遥测和外部回调，运行时做出站网络限制。
Milvus/FAISS 本地但 Embedding 调云 API 不算完全离线。
还要准备模型许可、硬件容量、升级包校验、备份恢复和无公网观测方案。

## 2.3 第93题：线上回答错误，第一步怎么排查？

**答案：** 用 trace_id 回放，
找到正确证据最后出现在哪一层：解析原文、Chunk、索引、单路召回、融合、Rerank、Context、生成。
若召回未命中，调 Prompt 无效；
若证据已进 Context 再查冲突、注入、结构化输出和引用。
保存索引/模型/Prompt 版本，确认不是环境漂移。
修复后把案例加入回归集。

## 2.4 第94题：为什么正确文档在库里却搜不到？

**答案：** 依次检查解析是否包含目标段落、分块是否切断、文档/索引版本是否正确、ACL 是否误过滤、Embedding 模型是否一致、中文分词和精确字段是否正确、Top K/阈值是否过严。
分别执行无过滤精确查询、BM25 和向量查询定位。
不要一次同时改多个参数，否则无法确认根因。

## 2.5 第95题：为什么正确证据已召回，答案仍然错？

**答案：** 查看它是否在融合/Rerank 后仍保留、Context Packing 是否截断条件、其他证据是否冲突或过期、文档是否包含注入、Prompt 是否允许外部常识、输出引用是否经过验证。
将生成替换成“只摘录证据”可区分理解问题与检索问题。
高风险数值和状态用规则或工具二次校验。

## 2.6 第96题：如何处理知识库中的冲突文档？

**答案：** Metadata 保存来源权威级、业务生效时间、文档版本和状态；
检索前过滤已废止版本，Rerank/组装时优先当前权威来源。
若两条 active 权威证据仍冲突，答案应明确冲突、列出来源并请求确认，而不是让模型随机选。
离线任务检测同实体/条款冲突并推动数据治理。

## 2.7 第97题：如何设计多租户大模型平台？

**答案：** 身份、配额、模型权限、知识索引、缓存、Memory 和 Trace 全部带租户边界；
高隔离需求可独立索引/密钥，普通场景至少强制过滤并做跨租户测试。
密钥在后端管理，审计所有外部写操作。
按租户统计 Token、并发和费用，限流与预算独立。
用户输入的 tenant_id 不能直接信任。

## 2.8 第98题：如何把用户反馈变成可持续优化闭环？

**答案：** 反馈关联 trace_id，保存问题、版本、候选、证据和输出；
运营或专家把坏例标成解析、召回、重排、生成、权限或数据过期。
补充正确证据与答案要点进入回归集，修复后比较局部样本和全量指标，再走发布流程。
点赞/点踩信号噪声大，不能未经审核直接训练或改权重。

## 2.9 第99题：如何在效果、延迟和成本之间做取舍？

**答案：** 先定义任务 SLO 与错误成本，
再画配置 Pareto 曲线：召回 K、Rerank 候选、模型大小、上下文长度对应成功率、P95 和费用。
按问题复杂度动态路由：精确简单问题走 BM25/小模型，复杂多跳走混合检索/强模型。
设置总预算和降级顺序。
不能用平均延迟掩盖 P95，也不能为省 Token 删除关键证据。

## 2.10 第100题：你会怎样介绍一个有说服力的 AI 应用项目？

**答案：** 用“业务问题与基线 → 数据/权限约束 → 架构取舍 → 自己负责的关键实现 → 真实坏案例与根因 → 指标前后对比 → 上线与回滚”讲述。
明确数据规模、Recall/成功率、P95、成本和安全结果，区分亲自验证与计划项。
重点不是框架名，而是为什么这样选、失败时怎么定位、哪些方案被实验否决。
