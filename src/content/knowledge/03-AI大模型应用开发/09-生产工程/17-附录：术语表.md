# 生产工程（17） - 附录：术语表

> 目标：把 AI Agent 学习中高频术语翻译成前端同学容易理解的工程语言。

## 核心术语

| 术语 | 一句话解释 | 前端类比 |
|---|---|---|
| LLM | 大语言模型，负责理解和生成文本 | 一个很强的远程智能函数 |
| Prompt | 发给模型的任务说明和上下文 | 给协作者写需求说明 |
| Token | 模型处理文本的基本单位 | 接口计费和长度限制单位 |
| Context Window | 模型一次能处理的最大上下文 | 请求体大小上限 |
| RAG | 先检索资料，再让模型基于资料回答 | 先查接口再渲染页面 |
| Chunk | 文档切分后的小段文本 | 列表里的单条数据 |
| Embedding | 文本向量化，用于相似度检索 | 把文本变成可比较坐标 |
| Vector DB | 存储和检索向量的数据库 | 专门做相似搜索的索引库 |
| Rerank | 对召回结果重新排序 | 搜索结果二次排序 |
| Citation | 回答引用的来源 | 参考链接 / 来源展开 |
| Tool Calling | 模型提出调用工具，代码执行工具 | 由模型触发的 API 调用 |
| Agent | 能选择工具并推进任务的编排逻辑 | 带决策能力的业务流程 |
| Workflow | 固定步骤的流程编排 | 表单提交流程 / pipeline |
| Memory | 会话或用户记忆 | store / session state |
| Prompt Injection | 用户试图覆盖系统规则的攻击 | 恶意输入污染业务逻辑 |
| Eval | 评测 AI 输出质量的方法 | 自动化测试 + 业务验收集 |
| Hybrid Search | 关键词检索和向量检索结合 | 搜索框同时查精确词和语义相似 |
| RRF | 融合多路检索排序的方法 | 多个榜单合并成一个榜单 |
| Query Rewrite | 把用户问题改写成更适合检索的表达 | 搜索前先规范关键词 |
| GraphRAG | 用知识图谱增强 RAG 的关系推理 | 先查关系图再回到详情页 |
| MCP | Agent 调用工具/资源/Prompt 的协议化方式 | 给 AI 工具做统一接口层 |
| LLM-as-Judge | 用模型辅助评估模型输出 | 自动化验收里的评审人 |
| TraceID | 串起一次请求全链路的 id | 前端埋点里的 trace |
| 父子分块 | 小块召回、大块回答的切分策略 | 列表项命中后打开详情 |
| VLM | 能理解图片的视觉语言模型 | 会看图的远程智能函数 |
| ASR/TTS | 语音转文字 / 文字转语音 | 输入法听写 / 浏览器朗读 |

## 最容易混淆的三组

- RAG 解决“模型不知道资料”的问题，微调更多解决“模型行为和风格”的问题。
- Agent 更灵活，Workflow 更可控；企业项目通常先 Workflow，再逐步引入 Agent。
- Tool Calling 是一次工具调用机制，Agent 是围绕目标进行多步决策和工具调用的系统。

## 学习建议

每遇到一个新词，都问三件事：

1. 它的输入是什么？
2. 它的输出是什么？
3. 它失败时系统怎么处理？
