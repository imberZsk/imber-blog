# 生产工程（21） - AI 应用威胁建模与纵深防御

> 模型会处理用户、网页、文件和工具返回的不可信文本；安全边界必须写在模型之外，并覆盖数据进入、检索、生成和执行全过程。

> 读完你能：对 RAG 和 Agent 做威胁建模，并在权限、沙盒、网络和数据生命周期设置纵深防御。

## 核心知识清单

- 直接与间接 Prompt Injection
- 知识库数据投毒与来源治理
- 越权检索、tenant_id 与 ACL
- Tool 参数注入与副作用审批
- 沙盒、文件路径边界与网络白名单
- 密钥、日志脱敏与供应链安全
- 攻击评测、审计与应急撤销

## 信任边界

系统和开发者指令属于控制面；用户输入、检索文档、网页和 Tool 输出都属于数据面。仅在 Prompt 中写“忽略恶意指令”不是隔离。检索前按租户和 ACL 过滤，生成前保留来源，工具执行前重新做身份、权限、Schema 和业务规则校验。

## Tool 防护

文件工具将路径解析到固定工作区后再次确认前缀；命令工具使用参数化 allowlist，不把模型文本拼进 Shell；网络工具只访问批准域名和端口；删除、付款和发布等副作用要求幂等键、预览和人工确认。容器或虚拟机沙盒还要限制 CPU、内存、时长、文件系统和网络出口。

## 数据投毒治理

入库记录来源、上传者、版本、校验和与审核状态；不可信内容进入隔离区，扫描后再发布。索引删除必须覆盖向量库、搜索索引和缓存。发现污染时能够按 source_id 或版本撤销并重建，而不是逐条人工寻找 Chunk。
