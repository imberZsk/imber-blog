# Paperclip（5）- 创建你的第一家公司：从目标到 CEO

> 本章目标：在 UI 里建出一家公司、写好目标、招出第一个 CEO Agent、搭起组织架构、设好预算，最后点「启动」让公司跑起来。这是你第一次真正动手「开公司」。

进阶篇从这里开始动手。前面四章建立了认知，现在把空控制台变成一家能干活的公司。

---

# 一、整体六步

```
① 建公司  →  ② 设目标  →  ③ 招 CEO  →  ④ 搭组织  →  ⑤ 设预算  →  ⑥ 启动
```

---

# 二、步骤 1：创建公司

在 Web UI 点「New Company」，填两项：

- **Name（名字）**：你公司的名字。
- **Description（描述）**：这家公司是干嘛的（可选，但强烈建议写）。

> 公司是顶层单元，之后所有 Agent、任务、目标、预算都挂在它下面。

---

# 三、步骤 2：设一个「好目标」

每家公司都需要一个目标——所有工作追溯回去的「北极星」。**目标的质量直接决定 AI 团队的产出质量。**

好目标的标准：**具体、可衡量**。

| ❌ 坏目标 | ✅ 好目标 |
|----------|----------|
| 做个好产品 | 3 个月内做出 #1 的 AI 笔记 App，达到 $1M MRR |
| 搞点营销 | 建一个营销代理公司，Q2 前服务 10 个客户 |
| 做个社区 | 做一个 AI Agent 开发者学习与分享社区，提供课程、技术讨论和热文排行 |

到 Goals 区域，创建你的顶层公司目标。

> 💡 为什么这么强调目标？因为 CEO Agent 会**基于这个目标**自动拆解出所有任务。目标含糊，拆出来的任务就含糊，整支团队都在做无用功。这就是第 01 章说的「你的品味是天花板」。

---

# 四、步骤 3：招聘 CEO Agent

CEO 是你创建的**第一个 Agent**，也是整个组织的根节点。配置项：

- **Name**：比如 "CEO"。
- **Role**：`ceo`。
- **Adapter（适配器）**：这个 Agent 用什么大脑跑。**Claude Local 是个好默认**（第 06 章详解各适配器）。
- **Prompt template（提示词模板）**：每次心跳给 CEO 的指令。
- **Budget（预算）**：每月花费上限，单位是**分（cents）**。

CEO 的 prompt 应该指示它：**review 公司健康度、制定策略、把工作委派给下属。**

> 🧠 为什么 CEO 适合用 Claude Code？因为 CEO 干的活是「规划任务、拆解目标、指挥下属」——这正是 Claude Code 这类能做多步规划、能调工具的 Agent 最擅长的。简单脚本（process 适配器）做不了这种活。

## 4.1 CEO 的 prompt 模板可以用变量

`claude_local` 适配器的 prompt 模板支持 `{{变量}}` 替换：

| 变量 | 值 |
|------|-----|
| `{{agentId}}` | Agent 的 ID |
| `{{companyId}}` | 公司 ID |
| `{{runId}}` | 当前运行 ID |
| `{{agent.name}}` | Agent 名字 |
| `{{company.name}}` | 公司名字 |

这样一套模板能复用给不同 Agent，运行时自动填入各自的身份。

---

# 五、步骤 4：搭组织架构

从 CEO 出发，创建直接下属：

- **CTO** → 管工程类 Agent
- **CMO** → 管市场类 Agent
- 其他高管按需添加

每个 Agent 都有自己的适配器配置、角色、预算。组织树是**严格层级**——每个 Agent 只向一个经理汇报。

> ⚠️ 别一上来就铺满组织。先 CEO 一个人跑通，确认闭环，再让 CEO 自己去申请雇人（雇人会走审批，见第 09 章）。从小开始是铁律。

---

# 六、步骤 5：设预算

在**公司级**和**单 Agent 级**都设每月预算。Paperclip 会强制执行：

- **软告警（soft alert）**：用到 80% 时提醒。
- **硬停（hard stop）**：用到 100% 时——**Agent 被自动暂停**（状态变 `paused`）。

> 预算单位是「分」。比如想给某 Agent 每月 $50 上限，就填 `5000`。这是防止 AI 团队烧钱失控的最后一道闸（第 12 章细讲成本）。

---

# 七、步骤 6：启动

给 Agent 开启心跳，它们就开始干活了。从看板（dashboard）监控进度。

启动后典型的第一幕：

1. CEO 在第一次心跳醒来。
2. 它读公司目标，制定一份策略，**提交给你审批**（这是治理闸门）。
3. 你批准后，CEO 把目标拆成任务，分配给下属（如果还没下属，它会申请雇人，又走一道审批）。
4. 下属在各自心跳里签出任务、干活。
5. 你在看板上实时看到「谁在干什么、花了多少」。

---

# 八、常见错误

- ❌ **目标写得太虚**
  → 「做个好社区」这种目标，CEO 拆不出有效任务。务必具体可衡量。

- ❌ **第一步就建一大堆 Agent**
  → 组织铺太大，协作关系还没理顺就乱套。先 CEO 跑通再扩。

- ❌ **给 CEO 用了不会规划的适配器（如 process）**
  → CEO 要做多步规划和委派，得用 `claude_local` / `codex_local` 这类有 agentic 能力的。process 只适合执行固定命令。

- ❌ **预算填错单位**
  → 单位是「分」不是「元」。想要 $50 要填 `5000`，填 `50` 就只有 $0.5。

- ❌ **忘了 CEO 的策略需要你审批才会往下走**
  → 公司「不动」时，先看是不是有个待审批卡在那等你点头（第 09 章）。

---

# 九、最佳实践

- ✅ **目标里写清「成功长什么样」**：给可衡量的指标（MRR、客户数、发布数量），CEO 才好对齐。
- ✅ **CEO 的 prompt 里写明它的职责边界**：review 健康度、定策略、委派——别让它自己埋头写代码。
- ✅ **预算先保守后放开**：初期设小预算观察 burn rate，跑顺了再调高。
- ✅ **喂「品味输入」**：把品牌指南、参考案例、风格要求放进 CEO 或相关 Agent 的上下文/项目目录，产出质量立刻不一样。

---

# 十、总结

- 六步开公司：**建公司 → 设目标 → 招 CEO → 搭组织 → 设预算 → 启动**。
- 目标要**具体可衡量**，它是所有任务的源头。
- CEO 用 **Claude Local** 这类能规划的适配器，prompt 指示它「定策略、委派」。
- 预算单位是**分**，有 80% 告警和 100% 硬停。
- 启动后第一件事通常是 **CEO 提交策略等你审批**。
