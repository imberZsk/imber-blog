# 工程基础（5）- Python 基础语法

> 读完你能：用变量、条件、循环、函数、字符串格式化，写出一个能处理输入、组织逻辑、调用模型的 AI 脚本骨架，并跑通它。

# 一、一个真实场景

你要做一个最小的知识库问答脚本：用户问"报销流程是什么"，脚本去一堆资料里找相关片段，拼成提示词发给模型，拿回答案。

这个脚本拆开看，只用到五样东西：变量存数据、条件处理异常输入、循环遍历资料、函数封装步骤、字符串格式化拼提示词。Python 的高级语法（装饰器、生成器、元类）这一篇一个都不用。先把这五样写顺，你就能写出第一批 AI 脚本。

# 二、Python 和 JavaScript 的关键差异

你有前端基础，大部分概念能直接迁移，但有几个地方踩了会卡：

| 你在 JS 里 | Python 里 | 注意 |
|---|---|---|
| `{ }` 划分代码块 | **缩进**划分代码块 | 缩进错了直接报 `IndentationError`，跑不了 |
| `const arr = []` | `arr = []` | 不写 `const/let`，直接赋值 |
| `obj.key` / `obj['key']` | `d["key"]` | 字典只能用方括号，没有点语法 |
| `arr.map(f)` | `[f(x) for x in arr]` | 列表推导式，但别为炫技牺牲可读性 |
| `\`${a}\`` 模板字符串 | `f"{a}"` f-string | 拼提示词天天用 |
| `function f() {}` | `def f():` | 函数用 `def`，冒号 + 缩进 |

最容易翻车的就是缩进。JS 里缩进只是好看，Python 里缩进是语法。函数体、`if` 体、`for` 体都必须缩进，且同一块缩进要一致。

# 三、五样语法，对着 AI 场景学

**1. 变量 —— 命名要表达业务含义**

```python
question = "报销流程是什么？"        # 用户问题
retrieved_chunks = ["报销需30天内提交"]  # 检索到的资料，比叫 arr 清楚
```

**2. 条件 —— AI 应用一半的代码在处理失败路径**

```python
if not question.strip():       # 空输入
    return "请输入一个问题。"
if not hits:                   # 一条资料都没检索到
    return "知识库里没有相关资料。"
```

新手只写成功路径，工程代码里失败路径（空输入、检索为空、权限不足、模型超时）往往更多。

**3. 循环 —— 遍历消息、资料、工具列表**

```python
for keyword, chunks in knowledge.items():   # 遍历字典的键值对
    if keyword in question:
        hits.extend(chunks)
```

**4. 函数 —— 把每个步骤封装成可测试的单元**

```python
def build_prompt(question: str, chunks: list[str]) -> str:
    ...
```

`question: str` 和 `-> str` 是类型标注。Python 不强制，但 AI 应用代码里函数传来传去的是 prompt、chunks、tool 结果，标上类型后别人（和三个月后的你）一眼能看懂。

**5. 字符串格式化 —— 拼提示词的核心**

```python
prompt = f"""你是知识库助手，只能基于资料回答。

资料：
{context}

问题：
{question}
"""
```

三引号 `"""..."""` 写多行，`f"..."` 里 `{变量}` 直接插值。提示词又长又多行，用它最合适。

# 五、工程上真正会踩的坑

- **缩进混用空格和 Tab**：肉眼一样，Python 报错。编辑器统一设成 4 空格。
- **函数返回值类型不稳定**：有时返回字符串、有时返回字典，下游解析会崩。一个函数固定返回一种结构。
- **所有逻辑堆在一个 `main` 里**：没法单独测某一步。从一开始就拆成 `build_prompt`、`answer` 这样的小函数。
- **变量名用 `a` `arr` `data`**：AI 应用里数据流很长，名字模糊三天后自己都看不懂。用 `retrieved_chunks`、`tool_result`。
