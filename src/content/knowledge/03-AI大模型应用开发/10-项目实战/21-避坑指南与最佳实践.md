# 一、安装 / 启动阶段

## 1.1 高频坑
- **混用 `npx` 和 `pnpm` 前缀**：`npx` 装的就一直用 `npx paperclipai`；`pnpm paperclipai` 只在克隆的源码仓库里有效。
- **Node 版本 < 20**：装/启动报错，先 `node -v`。
- **端口 3100 被占**：`paperclipai configure` 换端口，或关掉占用进程。
- **删 `~/.paperclip/` 重置，连数据一起删**：这目录装着所有公司/任务/产物，删前确认。

## 1.2 自检
```
□ node -v ≥ 20
□ 前缀用对（npx 装的用 npx）
□ 跑起来看到 UI http://127.0.0.1:3100
□ 出问题先看 ~/.paperclip/instances/default/logs/server.log
```

# 二、建公司 / 招 Agent 阶段

## 2.1 高频坑
- **目标写太虚**：「做个好社区」拆不出有效任务。要具体可衡量。
- **一上来铺一堆 Agent**：先 CEO 跑通闭环再扩。
- **给规划型角色用 `process` 适配器**：CEO/工程师/QA 要用 `claude_local`（能 agentic）。
- **`cwd` 用相对路径或指向敏感目录**：必须绝对路径 + 受控目录（因默认跳过权限）。
- **预算单位填错**：单位是**分**，$50 = `5000`，填 `50` 几乎立刻被硬停。
- **配完不点 Test Environment**：环境问题事后查日志，远不如提前自检。

## 2.2 自检
```
□ 目标具体、可衡量（有指标）
□ 从 CEO + 必要的 1-2 个下属开始
□ 规划型角色用 claude_local / codex_local
□ 每个 Agent 独立绝对路径 cwd
□ 预算单位是分，两级（公司 + Agent）都设
□ 配完点 Test Environment 自检通过
```

# 三、运行 / 协作阶段（最容易卡的地方）

## 3.1 高频坑
- **公司「不动」**：八成 CEO 策略在等审批 → 去 Approvals 页。
- **CEO 派活了下游不动**：查下游 `wakeOnAssignment` 有没有开。
- **两个 Agent 互相等卡死**：任务树断了，子任务没挂 `parentId`，完成事件传不上去。
- **Agent 重试 409**：任务有主了，必须换任务，绝不重试。
- **手动 PATCH 任务到 `in_progress`**：绕过签出，破坏单负责人保证，必须走 checkout。
- **用 @提及代替分配任务**：@ 是沟通/唤醒，分活要建任务，滥用 @ 还烧预算。
- **取消跨团队任务**：铁律禁止，交回经理处理。
- **Agent 卡住默不作声**：必须置 `blocked` + 评论 blocker + 上报。

## 3.2 ⭐ 协作卡壳排查口诀（第 08 章核心）
> **协作不起来，先查两点：① 任务树挂好了吗（`parentId`）？② 下游会自动醒吗（`wakeOnAssignment`）？**
> 这两点解决绝大多数卡壳。别一上来就改 prompt。

## 3.3 自检
```
□ 公司不动 → 先看 Approvals 队列
□ 子任务都设了 parentId（有目标加 goalId）
□ 下游 Agent 开了 wakeOnAssignment
□ 干活前先 checkout，409 换任务不重试
□ 每次心跳留 durable 进展（评论/文档/产物）+ 下一步
□ 卡住就 blocked + 评论 + 上报，不沉默
```

# 四、治理 / 审批阶段

## 4.1 高频坑
- **审批不看 payload 就批**：雇人审批藏着适配器配置和预算，闭眼批可能放进烧钱/配错的 Agent。
- **动不动 Terminate**：不可逆。临时停用 `pause`。
- **所有动作都开审批**：被审批淹没，失去自动化意义。
- **完全关掉审批**：失控风险，至少留 CEO 策略审批 + 预算硬停。

## 4.2 原则
> **靠近「方向」和「钱」的决策要把关，靠近「执行」的要放权。**

## 4.3 自检
```
□ CEO 策略审批：开
□ 雇人审批：初期开，信任后放
□ 日常执行：放权
□ 审批时认真看 payload 和关联任务
□ 临时停用优先 pause，慎用 terminate
```

# 五、成本阶段

## 5.1 高频坑
- **预算单位填错**（元当分）：$50 填 `50` 立刻被硬停。
- **看到成本 0 以为免费**：订阅登录不走按量计费，订阅本身有额度。
- **只设公司预算不设 Agent 预算**：单个 Agent 可能空烧吃光公司预算。
- **从不看 burn rate**：月底超支才发现。

## 5.2 自检
```
□ 预算单位是分，$50 = 5000
□ 公司级 + Agent 级两级预算都设
□ 分清 API Key（计费）还是订阅（可能显示 0）
□ 定期看看板的花费和 burn rate
□ 异常烧钱去 activity 审计查根因
```

# 六、部署 / 上线阶段

## 6.1 高频坑（含安全红线）
- 🚨 **把免登录的 `local_trusted` 暴露到公网**：谁都能控制你的公司。公网必须 `authenticated + public`。
- **切认证模式忘了认领董事会**：访问 board-claim URL 绑定账号。
- **密钥写明文进 Agent 配置**：用 `env` 密钥引用，明文会进数据库/导出包。
- **丢/乱备份 `master.key`**：它能解密所有密钥，丢了全废、泄露全泄。
- **生产用内嵌数据库不做外部备份**：生产切外部 PostgreSQL。
- **靠终端窗口维持运行**：窗口关就停，长期运行用 Docker。

## 6.2 自检
```
□ 模式选对：本地 local_trusted / 远程 authenticated+private / 公网 authenticated+public
□ 绝不把 local_trusted 暴露公网
□ 远程优先 Tailscale（private + tailnet）
□ 切认证模式后完成 board-claim
□ 密钥全走引用，master.key 安全备份
□ 生产：Docker + 外部 PostgreSQL + 对象存储
□ 部署后跑 paperclipai doctor
```

# 七、贯穿全书的 7 条「黄金法则」

如果只记 7 条，记这些：

1. **目标决定一切**：具体可衡量的目标 + 你的「品味输入」，是产出质量的天花板。
2. **从小开始**：先 CEO 跑通闭环，再扩团队。
3. **选对大脑**：规划型用 Claude/Codex，执行型用 process/http。
4. **干活前先 checkout，409 绝不重试**：这是协作不打架的根。
5. **任务树要完整**：子任务永远挂 `parentId`，否则协作流转断。
6. **靠近钱和方向的把关，靠近执行的放权**：治理的平衡点。
7. **安全红线**：免登录模式绝不上公网；密钥永远引用不明文。

# 八、出问题时的排查顺序（总流程图）

```
公司/Agent 行为异常
        │
        ▼
① 看 Approvals：有没有待审批卡着？（公司不动最常见原因）
        │ 无
        ▼
② 看协作两点：parentId 挂对了吗？wakeOnAssignment 开了吗？
        │ 都对
        ▼
③ 看预算：是不是 burn 到 100% 被 paused 了？
        │ 没超
        ▼
④ 看 Run record / logs：心跳到底报了什么错？
        │
        ▼
⑤ 看 activity 审计：谁在什么时候做了什么改动？
```

**按这个顺序查，比盲改 prompt 高效得多。**
