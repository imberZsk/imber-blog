# 你的第一个 Skill

## 本篇你能学到

前面几篇我们聊了知识库的「为什么」和「长什么样」，这一篇彻底动手——带你**完整跑通一次 Skill 调用**，建立操作肌肉记忆。读完你会掌握：

- SKILL.md 的 `frontmatter` 三件套（`name` / `description` / `allowed-tools`）各自管什么
- `description` 里的「触发词」机制：为什么你随口说句话，Claude Code 就知道该调哪个技能
- 用 `wiki-query` 做端到端演示：从触发词到渐进式检索，到返回带引用来源表的答案

> 这一篇是「跟着做」体质，建议你打开终端边看边敲。踩坑点我会用 ⚠️ 标出来，基本都是真人踩过的。

## 先认识 SKILL.md 的「身份证」

一个 Skill 本质上就是一个目录，里面躺着一个 `SKILL.md`。它的开头有一段被 `---` 包起来的 YAML，叫 **frontmatter**，这是整个技能的「身份证」。

我们直接拿真实的 `wiki-query` 来看（这是 `frontend-knowledge` 插件里负责查询知识库的技能）：

```yaml
---
name: wiki-query
description: "从前端知识库中查询并回答问题。按渐进式披露读取 hot.md → _index.md → 目标页面 → areas/，综合答案并内联引用来源。触发词：查一下、查询、解释一下、总结、在知识库里找、根据知识库、按知识库、按照知识库、依据知识库、遵循知识库、知识库查一下、知识库查下、知识库里查、知识库里找、去知识库找、从知识库查、到知识库查、知识库搜、查 wiki、按约定、按规范"
allowed-tools: Read Write Edit Glob Grep Bash
---
```

就这三行，每一行都有讲究：

| 字段 | 作用 | 类比 |
|------|------|------|
| `name` | 技能的唯一标识，目录名通常和它保持一致 | 人的身份证号 |
| `description` | 技能干什么 + **什么时候该被触发** | 招聘启事上的岗位描述 |
| `allowed-tools` | 这个技能被允许使用哪些工具 | 门禁卡能刷开哪几道门 |

`name` 没啥好说的，重点在后面两个。

### description 不是给人看的，是给「匹配」用的

很多人第一次写 SKILL.md，把 `description` 当成 README 里的项目简介来写，洋洋洒洒一大段文学创作。**这是误区。**

`description` 真正的读者是 Claude Code 的调度逻辑。当你在对话框里说话，它会拿你的话去和每个技能的 `description` 做语义匹配，命中了就调用对应技能。所以 `description` 写得好不好，直接决定技能「灵不灵」。

看 `wiki-query` 这段 `description` 的结构，其实分两半：

- **前半句讲职责**：「从前端知识库中查询并回答问题。按渐进式披露读取 hot.md → \_index.md → 目标页面…」——告诉模型这技能是干嘛的。
- **后半句砸触发词**：「触发词：查一下、查询、解释一下、总结、在知识库里找、根据知识库…」——一长串口语化的说法。

> 💡 触发词为什么要堆这么多？因为人说话是发散的。同一个意图，有人说「查一下」，有人说「知识库里找找」，有人说「按规范来」。把这些说法都铺进去，命中率才高。这是写 Skill 的一条核心心法：**触发词要覆盖真实口语，别只写一个标准说法。**

### allowed-tools 是安全边界

`allowed-tools: Read Write Edit Glob Grep Bash` 这行声明了 `wiki-query` 能用的工具。它做的是查询，要读文件（`Read`）、要搜关键词（`Grep` / `Glob`）、要写缓存（`Write` / `Edit`）、要跑环境检查脚本（`Bash`）。

⚠️ 一个常见误解：以为 `allowed-tools` 写得越全越好。恰恰相反，它是**最小权限**原则。一个只读查询的技能如果声明了 `Write`，那它就有了改你知识库的能力。`wiki-query` 虽然声明了 `Write`，但它在正文里明确约束「**只写 hot.md（缓存写回），不修改知识库其他文件**」。能力归能力，行为靠正文兜底。

## 触发词机制：你说话，它接活

这是 Skill 区别于传统命令的最大爽点。

传统 CLI 工具，你得记命令：`wiki query "技术选型"`，记错一个参数就报错。Skill 不一样，**你直接在对话框说人话就行**。

调用流程是这样的：

```text
你输入意图  →  Claude Code 拿你的话和各技能 description 做匹配
            →  命中 wiki-query 的触发词「查一下」「技术选型」
            →  自动调用 wiki-query 技能
            →  技能按内部流程执行
            →  返回结果
```

整个过程你不需要知道技能叫 `wiki-query`，也不需要敲任何命令。你只管表达意图，匹配的活交给 Claude Code。

对比一下两种用法的差别：

| 场景 | ✅ Skill 的方式 | ❌ 传统命令的方式 |
|------|---------------|-----------------|
| 想查技术选型 | 直接说「查一下团队的技术选型」 | 记住 `wiki query --topic=stack` 这种参数 |
| 换个说法 | 「知识库里找找我们用啥框架」照样命中 | 参数写错就报 `unknown option` |
| 不知道有这功能 | 说出意图自动触发，无需提前知道技能名 | 得先翻文档知道有这个命令 |

## 跟着做：完整跑一次 wiki-query

理论说完，动手。我们模拟一个真实场景：**新人入职，想搞清楚团队前端用的什么技术栈。**

### Step 0：先把环境变量配好（最容易翻车的一步）

⚠️ **这是 90% 新人第一次失败的地方。** `wiki-query` 启动时第一件事就是检查环境变量 `FRONTEND_KNOWLEDGE_WIKI_ROOT`，没配它直接红字终止，连查都不查。

根据技能的环境检查规则，它的逻辑长这样：

```bash
# 来自 shared-references/env-check-rules.md 的真实检查逻辑
if [ -z "$FRONTEND_KNOWLEDGE_WIKI_ROOT" ]; then
  printf '环境变量 FRONTEND_KNOWLEDGE_WIKI_ROOT 未配置，流程终止。\n'
  printf '请在 ~/.claude/settings.json 的 env 中配置，指向知识库根目录的绝对路径。\n'
  exit 1
fi
```

配置方式是在 `~/.claude/settings.json` 的 `env` 字段里加一行，指向你本地知识库仓库的**绝对路径**：

```json
{
  "env": {
    "FRONTEND_KNOWLEDGE_WIKI_ROOT": "/Users/你的用户名/Desktop/work/frontend/frontend-knowledge"
  }
}
```

> ⚠️ 三个高频坑：
> 1. **必须绝对路径**，别写 `~/Desktop/...` 或相对路径，技能不会帮你展开。
> 2. 配完要**重启 Claude Code** 让环境变量生效，改完不重启等于没改。
> 3. 路径指向的是知识库**根目录**（里面有 `wiki/` 子目录的那层），别指到 `wiki/` 里面去。

### Step 1：说出你的意图

环境配好，在对话框里直接输入：

```text
查一下团队的技术选型
```

这句话里，「查一下」命中了 `wiki-query` 的触发词，「技术选型」是查询内容。Claude Code 匹配成功，自动拉起 `wiki-query`。

### Step 2：看它怎么「渐进式披露」找答案

这是 `wiki-query` 最值得看的部分。它不会一上来就把整个知识库读个遍——那样既慢又烧 token。它走的是**渐进式披露**：先看路由，再看缓存，逐层下钻，**信息够了立刻停，不多读一个文件**。

完整是 8 步，我们看关键的几步实际发生了什么：

```text
[Step 1] 读取根 _index.md，确定路由
         → 「技术选型」属于跨项目通用知识，命中 wiki 分区

[Step 2] 读取 wiki/hot.md 缓存
         → 缓存没命中，继续下钻

[Step 3] 递归读 _index.md 定位目标页面
         → wiki/_index.md 的意图表里，「新项目技术选型」
           直接指向 conventions/adr/references/tech-stack-selection.md

[Step 4] 读取目标页面
         → 检查 frontmatter 的 status: stable，正常使用
         → 提取「决策摘要」section，拿到答案，停止下钻
```

这里有个细节值得说：Step 3 是怎么「一步到位」找到目标页的？因为 `wiki/_index.md` 里有一张「按意图查找」表，把常见意图和具体页面做了映射：

```text
| 常见意图                        | 优先入口                                          |
| 新项目技术选型 / 团队规范基线    | 团队技术选型规范 (tech-stack-selection.md)        |
```

> 💡 这就是知识库设计的精髓：`_index.md` 是「导航层」，真正的细则在叶子页。`wiki-query` 顺着导航层一路点进去，不用瞎搜。前面几篇讲的目录结构，到这里才显出威力。

⚠️ 注意 Step 4 里那个 `status` 检查。目标页 frontmatter 如果是 `status: draft`，技能会**跳过它**降级去 Grep 搜别的页；`status: developing` 能用但答案里会标「（正在完善中）」；只有 `status: stable` 才是无标注直接用。所以你写知识页时，别忘了标 `status`，不然技能可能直接跳过你辛苦写的草稿。

### Step 3：拿到带引用的答案

找到信息后，`wiki-query` 不会只甩给你一段大白话。命中知识库时，它**必须**在答案末尾附一张「引用来源表」——这是技能的硬约束。你拿到的东西大概长这样：

```text
团队新项目默认技术栈：React + Vite + pnpm + Tailwind...
（来源: [[conventions/adr/references/tech-stack-selection.md]]）

引用来源：

| # | 知识名称       | 文件路径                                          | 分区 | 状态   | 查询路径                                          |
|---|---------------|--------------------------------------------------|------|--------|--------------------------------------------------|
| 1 | 团队技术选型规范 | conventions/adr/references/tech-stack-selection.md | wiki | stable | _index.md → tech-stack-selection.md              |

绝对路径：
/Users/.../frontend-knowledge/wiki/conventions/adr/references/tech-stack-selection.md
```

> 💡 这张引用表是知识库回答和「AI 凭记忆瞎编」的本质区别。每一条结论都能溯源到具体文件、具体状态、具体查询路径。你一眼就能判断这答案是从知识库捞的，还是模型编的——如果末尾没有引用表，那大概率走了 Step 6 的 AI 兜底，意味着知识库根本没覆盖这个问题。

### 对照一下：命中 vs 没命中

| 表现 | ✅ 命中知识库 | ❌ 走了 AI 兜底 |
|------|------------|---------------|
| 答案末尾 | 有引用来源表 + 绝对路径列表 | 标注「以下内容来自 AI 训练知识，非前端知识库」 |
| 结论可信度 | 可溯源到具体页面 | 模型记忆，可能过时或不符合你团队约定 |
| 后续动作 | 直接用 | 技能会反问你「要不要把答案沉淀进知识库」 |

看到没命中的提示别慌，这恰恰是个好信号——它在告诉你知识库有个缺口该补了。这正是后面「知识沉淀」篇要讲的事。

## 小结

跑通这一次 `wiki-query`，你其实已经摸清了 Skill 的全套运作逻辑：

- **frontmatter 三件套**：`name` 是身份，`description` 是触发匹配的依据（前半讲职责、后半堆触发词），`allowed-tools` 是最小权限边界。
- **触发词机制**让你彻底告别背命令——说人话，命中触发词，技能自动接活。写技能时触发词要覆盖真实口语。
- **渐进式披露**是知识库查询不烧 token 的关键：路由 → 缓存 → 下钻 → 够了就停，靠 `_index.md` 导航层精准命中目标页。
- **引用来源表**是知识库回答的信任锚点，没有它就说明走了 AI 兜底，知识库存在缺口。
- 最容易翻车的永远是 `FRONTEND_KNOWLEDGE_WIKI_ROOT` 环境变量：绝对路径、配完重启、指向根目录。

下一篇我们换个角度，看看当知识库**查不到**的时候，怎么把新知识沉淀进去——让你的知识库越用越聪明。
