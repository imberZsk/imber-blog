# 单一事实来源原则

## 本篇你能学到

- 内容漂移的具体场景：同一规范被复制三处、半年后三处不一致的连锁反应
- 单一事实来源的正确做法：链接引用而非复制，源页是唯一真相
- 编辑心跳四动作：updated、父_index登记、冲突以子页为准、项目内容不进wiki

---

## 先讲一个真实的烂摊子

半年前，团队在三个地方都写了「禁止在需求 PR 里混顺手重构」这条规则：

- `wiki/conventions/references/rules-cheatsheet.md` 有一段
- `wiki/hot.md` 的关键决策段有一条
- 某项目的 `CLAUDE.md` 里也 copy 了一份

前三个月相安无事。然后有人修改了 `rules-cheatsheet.md`，加了「例外：附带修复必须在 PR 描述单开段落并拆 commit」。

改的人忘了同步另两处。

之后某个新人让 AI 帮他回答「能不能在需求 PR 里顺手改代码」。AI 检索时碰到了 `hot.md` 那份旧版本，回答「不能，没有任何例外」。

团队 CR 时有人说可以，有人说不行，两拨人各自搬出不同的文档链接争了半小时。

这就是**内容漂移**。同一条规则被复制到多处，各处独立演化，最终没有人知道哪个才算数。

> 💡 AI 不会判断哪个版本更新、哪个更权威。它检索到哪个就用哪个。内容漂移直接击穿 AI 知识库的可信度。

---

## 单一事实来源是什么

一条规则、一个决策、一份约定，**只在一个地方写完整内容，其他所有地方只放链接**。

这个放完整内容的地方叫「源页」（source of truth）。链接指向源页，源页是真相，其他都是指路牌。

知识库里的体现是：

```text
wiki/conventions/references/rules-cheatsheet.md
```

这个文件开头就写了自己的定位：

> 本页是 `conventions/` 下各规则页的**一页聚合速查**，用于查询时快速定位条目。单一事实来源：每条规则所链接到的子页，本页内容以子页为准。

`rules-cheatsheet.md` 本身只是一张索引表，每条规则后面跟的是 `→ [tech-stack-selection.md](...)` 这样的链接，**不重写规则正文**。

## 三类最容易出漂移的场景

### 场景一：`conventions/` 引用 `engineering/` 或 `foundations/`

`conventions/` 是团队约定层，`engineering/` 是工具链知识，`foundations/` 是跨框架原则。这三层之间经常需要交叉引用。

❌ 错误做法：把 `engineering/` 里的内容复制一段到 `conventions/` 里，方便阅读。

✅ 正确做法：

| 做法 | 结果 |
|------|------|
| ✅ 在 `conventions/` 里写一行 Markdown 链接，指向 `engineering/` 源页 | 两处内容永远一致，改一处全生效 |
| ❌ 把源页内容 copy 到 `conventions/` 里 | 日后源页更新，`conventions/` 成为孤岛，AI 可能检索到过期副本 |

实际写法就是这样：

```markdown
<!-- conventions/references/code-review.md 里引用工具链约定 -->

代码质量工具链配置见 [ESLint 配置](../../engineering/code-quality/references/eslint.md)，
本页不重复配置细节。
```

一行链接，源页是真相。

---

### 场景二：`hot.md` 的「关键决策」段

`hot.md` 是 AI 每次回答前都会读的热缓存，它的「关键决策」段记录的是**当前稳定共识**，不是决策历史。

常见的错误操作是「追加」——新共识出来了，旧条目没删，两条并排躺着：

```markdown
<!-- ❌ 错误：追加导致两条矛盾信息并存 -->
## 关键决策

- Tailwind 默认选最新版
- Tailwind 默认 3.x，仅在不要求 CSS 兼容性时选 4.x（2026-03 修订）
```

AI 读到这里会怎么处理？不知道。它可能拼接两条，可能只用第一条，可能随机取一条。

正确做法是**替换，不追加**：

| 操作 | 做法 |
|------|------|
| ✅ 新共识替换旧条目 | 直接覆盖那一行，保持「关键决策」只有一个版本的稳定共识 |
| ❌ 在旧条目后追加新共识 | 两条矛盾信息并存，AI 无法判断优先级 |

```markdown
<!-- ✅ 正确：替换旧条目，保留最新稳定共识 -->
## 关键决策

- Tailwind 默认 3.x，仅在不要求 CSS 兼容性时选 4.x → [tech-stack-selection.md](...)
```

> 💡 `hot.md` 是时间性薄缓存，不是变更日志。决策历史应该进 ADR，不是堆在 hot.md 里。

### 场景三：项目特定内容进了 `wiki/`

`wiki/` 是**团队通用**前端知识，与业务解耦。项目的架构决策、业务组件约定、业务踩坑，不属于这里。

真实反例：有人把「XX 项目的鉴权流程绕过了 token 刷新，直接用长效 cookie」写进了 `wiki/stacks/react/` 里。三个月后另一个项目的同事查鉴权流程，看到这条，以为是团队通用约定，照着做了，上线出问题。

| 内容类型 | 应该放哪里 |
|---------|-----------|
| ✅ 团队技术选型决策（为何选 Zustand） | `wiki/conventions/adr/` |
| ✅ 团队编码约定（命名、CR 规则） | `wiki/conventions/references/` |
| ❌ 项目 A 的业务组件约定 | 项目 A 自己的 `knowledge/areas/` |
| ❌ 项目 B 的架构踩坑 | 项目 B 自己的 `knowledge/areas/` |
| ❌ 某项目绕过通用规则的特殊处理 | 项目自己的 `areas/`，打上「项目特定」标签 |

**边界规则很简单：把这条知识给另一个项目的前端看，他能直接用吗？** 能用，进 `wiki/`；只对这个项目有意义，进项目的 `areas/`。

## 编辑时的心跳动作

「心跳」是一组每次编辑都要做的联动更新，防止局部修改破坏整体一致性。

**动作一：改页面时同步 `updated`**

```yaml
---
title: 团队技术选型规范
type: decision
status: stable
created: 2026-01-10
updated: 2026-05-25  # ← 每次改内容都要更新这个日期
---
```

`updated` 是 AI 判断内容新鲜度的信号。不更新 `updated`，AI 的缓存失效机制就失效了。

**动作二：子页与聚合页冲突，以子页为准，反向修正聚合页**

`rules-cheatsheet.md` 是聚合页，`tech-stack-selection.md` 是子页（源页）。

如果你在修改 `tech-stack-selection.md` 时发现 `rules-cheatsheet.md` 里对应的摘要条目已经过期，**正确流程是**：

1. 先把 `tech-stack-selection.md` 改到位
2. 回头修正 `rules-cheatsheet.md` 里的对应摘要，让它与子页一致
3. 两个文件的 `updated` 都更新

❌ 错误流程：直接改聚合页的摘要，没动子页。子页依然是旧内容，变成了「聚合页比源页新」的倒挂状态。

> 💡 聚合页的内容**以子页为准**，永远是这个方向，不反过来。

## 为什么链接比复制可靠

从工程角度讲，这本质上是「单一依赖 vs 多副本」的问题：

```text
# 链接引用模式（✅）
rules-cheatsheet.md ──→ tech-stack-selection.md（真相）
hot.md             ──→ tech-stack-selection.md（真相）
项目 CLAUDE.md     ──→ tech-stack-selection.md（真相）

改一处，三个入口都生效。
```

```text
# 复制粘贴模式（❌）
rules-cheatsheet.md  [副本 A，2026-01 版]
hot.md               [副本 B，2026-03 版]
项目 CLAUDE.md       [副本 C，2026-05 版，加了例外条款]

改哪处？三处都要改？漏了一处就产生漂移。
```

对 AI 来说，它不知道哪个副本是「权威版」。但链接模式下，AI 顺着链接就能找到源页，源页的 `updated` 是最新的，内容是唯一的。

---

## 小结

核心只有三条：只链接不复制，`conventions/` 引用其他分区时用 Markdown 链接指向源页，源页是唯一真相。`hot.md` 关键决策只存稳定共识，新共识出现时替换旧条目而非追加，避免矛盾信息并存。项目特定内容不进 `wiki/`，进项目自己的 `areas/`，边界就是「这条知识给另一个项目的前端看，他能直接用吗」。配套的心跳动作——改页面同步 `updated`、子页冲突时反向修正聚合页——是让这套机制持续工作的润滑剂。

内容漂移是一个典型的「慢性病」：刚开始不疼，半年后发作，吵架的时候才发现根本原因是有人六个月前 copy 了一段文字没有删。链接引用是唯一的预防药。
