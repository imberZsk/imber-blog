# 提示词工程（10）- 10 复杂任务拆解与工作流编排

> 本章目标：面对一个大而复杂的任务，学会把它拆成多步，用多个提示词串联（prompt chaining）完成，每一步的输出喂给下一步。
> 读完你能做到：把「一次问不清楚」的大任务，拆成几个可控的小步骤，稳定产出高质量结果。

---

# 一、为什么大任务别想着「一句话搞定」

来看个真实需求：

```
把这篇 8000 字的访谈整理成一篇公众号文章
```

你直接这么问，模型大概率给你一篇「平庸的缩写版」——它要同时干提炼、筛选、组织、扩写、润色好几件事，注意力一分散，每件都做不深，最后哪头都不讨好。

这就像让一个人「一口气把一桌菜做出来」，他手忙脚乱；但如果分成「备菜→炒→摆盘」，每步专心做一件，质量立刻上来。

**核心思想：把一个大任务，拆成若干个单一职责的小任务，每一步只让模型专注做好一件事，再把这一步的输出当作下一步的输入。** 这就叫**提示词串联（Prompt Chaining）**。

---

# 二、分步到底好在哪

对比一下「一次问」和「分步问」：

| 维度 | 一次性问 | 分步串联 |
|------|---------|---------|
| **每步专注度** | 同时干多件事，都做不深 | 一步只干一件，做得透 |
| **可控性** | 黑盒，错了不知道错在哪 | 每步可检查、可单独重试 |
| **可干预** | 只能整体重来 | 哪步不满意就只改那步 |
| **质量** | 平庸的「全能凑合版」 | 每步打磨，整体更优 |

一句话：**分步让你把一个不可控的黑盒，变成一条可观察、可调试、可干预的流水线。**

---

# 三、怎么拆：先想「人会怎么一步步做」

拆任务不玄乎，就一招：**想象一个专业的人会怎么分阶段完成这件事，照着拆。**

写公众号文章，一个编辑会怎么做？

1. 先通读访谈，**提炼核心观点**（别急着写）。
2. 根据观点，**列出文章大纲**（搭骨架）。
3. 按大纲**逐段扩写**（填血肉）。
4. 通读全文**润色定稿**（调语气、加标题）。

四步，每步职责单一。下面我们把这四步落成四个提示词，看它们怎么串起来。

---

# 四、完整实例：把长访谈整理成公众号文章

## 4.1 第 1 步：提炼核心观点

```
你是一位资深内容编辑。下面是一段访谈实录。

请通读全文，提炼出受访者最核心的 5 到 8 个观点。
要求：
- 每个观点用一句话概括，力求精准
- 只提炼「有信息量、有态度」的观点，忽略寒暄和重复
- 用编号列表输出

【访谈实录】
"""
{粘贴 8000 字访谈}
"""
```

**这一步的输出**（喂给下一步的「原料 A」）：

```
1. 真正的增长来自留存，而非拉新。
2. 团队规模超过 20 人后，沟通成本会指数级上升。
3. ……
```

## 4.2 第 2 步：根据观点列大纲

注意：这一步的输入，是**第 1 步的输出**，不是原始访谈。

```
你是一位擅长爆款结构的公众号主编。

下面是一篇文章要表达的核心观点列表。请据此设计一个公众号文章大纲。
要求：
- 设计一个抓人的开头钩子
- 把观点重新组织成 3 到 4 个递进的小节，每节给一个小标题
- 标注每节大概要讲什么、用上哪几个观点
- 结尾给一个升华或行动号召

【核心观点列表】
"""
{粘贴第 1 步的输出}
"""
```

**这一步的输出**（原料 B：一份带小标题的大纲）。

## 4.3 第 3 步：按大纲逐段扩写

这一步要同时用到**第 2 步的大纲**和**第 1 步原始素材**，让扩写有据可依。

```
你是一位文笔流畅的公众号写手。

请严格按照下面的大纲，把每个小节扩写成完整段落，组成一篇公众号文章。
要求：
- 忠于大纲结构，不要自己改结构
- 语气口语化、有网感，多用短句
- 可以引用访谈里的具体说法增强可信度
- 全文 1200 字左右

【大纲】
"""
{粘贴第 2 步的输出}
"""

【可引用的访谈原文】
"""
{粘贴第 1 步用的访谈，或相关片段}
"""
```

**这一步的输出**：一篇完整初稿（原料 C）。

## 4.4 第 4 步：润色定稿 + 起标题

```
你是一位公众号资深编辑，负责终审。

请对下面这篇初稿做最后润色：
- 删掉啰嗦和重复，让节奏更紧凑
- 检查每段开头是否抓人，弱的改掉
- 全文风格统一为「专业但亲切」
- 最后另起一行，给出 3 个备选标题（带一点悬念感）

【初稿】
"""
{粘贴第 3 步的输出}
"""
```

走完这四步，你拿到的是一篇结构清晰、有血有肉、可直接发布的文章——而且**每一步你都能检查、不满意就单独重跑那一步**，不用整篇推倒重来。

# 五、串联的几种常见形态

除了上面这种「线性串联」，还有几种好用的编排方式：

- **线性链（最常用）**：A → B → C，一步接一步。本章实例就是。
- **分支处理**：先用一个提示词判断类型（比如「这条反馈是投诉还是建议」），再根据结果走不同的后续提示词。
- **并行后汇总**：把一份长文档切成几段，分别总结（可以并行），最后再用一个提示词把这些小总结合并成总报告。
- **生成 + 校验**：第一个提示词生成结果，第二个提示词专门挑错（「检查上面的 JSON 是否符合格式，列出问题」），形成自检闭环。

挑哪种，还是那句话：**看一个专业的人会怎么组织这件事的工作流。**

# 六、常见错误

1. **拆得太碎**：十几步的链又慢又难维护。拆到「每步职责单一」就够了，别为拆而拆。
2. **步骤之间没对齐接口**：上一步输出的格式，要正好是下一步能直接吃的格式。比如上一步给编号列表，下一步就按编号列表来要。
3. **每一步都重新粘贴所有原始素材**：浪费上下文、还可能超窗口。只传下一步真正需要的东西。
4. **一步失败就整条链重来**：分步的价值就是「哪步错改哪步」，别浪费这个优势。
5. **该分步却图省事一次问**：复杂任务硬塞一个提示词，质量必然打折。

---

# 七、最佳实践

- **先画流程再写提示词**：拿张纸写下「第 1 步干啥、产出啥；第 2 步吃啥、产出啥」，接口对齐了再动手。
- **每步的输出格式，为下一步的输入而设计**：上下游格式约定好，串联才顺滑。
- **给每一步明确单一职责**：提炼就只提炼，别顺手扩写；扩写就只扩写，别改结构。
- **关键步骤加一道校验**：重要产出后面接一个「检查 + 挑错」的提示词，质量更稳。
- **能复用就沉淀成模板**：这套四步链可以复用在所有「长素材 → 成稿」的场景（模板化见第 11 章）。

---

# 八、本章小结

- 大任务别想一句话搞定；拆成单一职责的多步，用提示词串联完成。
- 分步的本质收益：把不可控的黑盒，变成可观察、可调试、可干预的流水线。
- 拆解方法：想象一个专业的人会怎么分阶段做，照着拆；上下游接口对齐是关键。
- 核心心法：**每一步只让模型专注做好一件事，把输出当作下一步的输入。**

下一章，我们把这些反复打磨出来的好提示词「存起来、管起来」，让它们变成可复用的资产。

# 动手实践：demo：Prompt Chaining 实战「长访谈 → 公众号文章」四步流程

这个 Demo 演示一条完整的提示词串联（prompt chaining）。
核心要点：**每一步只干一件事，上一步的输出，原样粘进下一步的 `{}` 里。**

用法：准备一段长访谈文本，按下面四步依次在 AI 工具里执行，每步拿到结果后填进下一步。

---

## 数据怎么流动（先看全局）

```
访谈原文
   │
   ▼
[第1步] 提炼观点 ──输出──▶ 观点列表
                              │
                              ▼
                      [第2步] 列大纲 ──输出──▶ 文章大纲
                                                 │
                                                 ▼
                          [第3步] 扩写(大纲+原文) ──输出──▶ 文章初稿
                                                              │
                                                              ▼
                                                  [第4步] 润色+起标题 ──▶ 成稿
```

## 为什么要这么麻烦地分四步

- **每步专注**：提炼时只提炼、扩写时只扩写，质量比「一次性整理成文章」高得多。
- **可检查**：哪一步结果不满意，只重跑那一步，不用整篇推倒重来。
- **接口对齐**：上一步的输出格式（编号列表、带小标题的大纲），正好是下一步能直接吃的输入。

亲手跑一遍，再用「把这篇访谈直接整理成公众号文章」一次性问一遍，对比两者的成稿质量，差距很直观。
