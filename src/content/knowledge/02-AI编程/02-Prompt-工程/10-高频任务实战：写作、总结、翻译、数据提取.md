# Prompt 工程（10） - 高频任务实战：写作、总结、翻译、数据提取

> 本章目标：把前八章学的技巧（结构化、少样本、格式控制）组合起来，落到四类最常用的日常任务上。
> 读完你能做到：面对写作、总结、翻译、数据提取这四类活，直接套用模板，少踩坑、出活快。

---

# 一、为什么是这四类

你日常用 AI，八成时间都在干这四件事：

- **写作**：写邮件、文案、周报、公告。
- **总结**：把长文、会议记录、文档浓缩成要点。
- **翻译**：中英互译、本地化、风格转换。
- **数据提取**：从一堆乱七八糟的文字里抠出结构化信息。

前面我们一个一个学技巧，这一章把技巧拼起来用。你会发现：**每一类任务都不是靠某一个技巧，而是几个技巧的组合拳。** 下面每一类我都给你一个能直接抄的模板，再点出最容易翻车的地方。

---

# 二、写作类：把「背景 + 要求 + 格式」交代清楚

写作翻车，几乎都是因为背景没给够。模型不知道你写给谁、什么场合、什么语气，只能写出「正确的废话」。

可直接套用的模板：

```
你是一位{身份，例如：资深市场文案}。

请帮我写一篇{文体，例如：产品上新公众号推文}。

【背景信息】
- 主题：{写什么}
- 目标读者：{给谁看}
- 我想达到的效果：{让读者看完做什么}

【写作要求】
- 语气风格：{例如：轻松、专业、有网感}
- 篇幅：{例如：不超过 300 字}
- 必须包含：{关键卖点 / 关键信息}
- 不要出现：{禁忌词 / 不想要的风格}

【输出格式】
- {例如：直接给正文；或：先给 3 个标题备选，再给正文}
```

**踩坑点：**

- **别只说「写得专业一点」**。「专业」太抽象，模型理解的专业和你想要的可能完全不同。改成具体的：「用第一人称、多用短句、每段不超过 3 行」。
- **目标读者一定要写**。同样一篇产品介绍，写给技术人员和写给普通用户，遣词造句天差地别。
- **想要多个备选就明说**。不说就只给一个，回头你还得再问一遍「再来几个」。

---

# 三、总结

总结最常见的失败，是模型把原文又啰嗦地复述了一遍，或者抓错了重点。原因是你没告诉它「按什么标准浓缩」。

可直接套用的模板：

```
请帮我总结下面这段内容。

【总结要求】
- 用途：{例如：给没看过原文的领导快速了解}
- 视角：{例如：只关注和「成本」相关的信息}
- 长度：{例如：3 到 5 条要点，每条一句话}
- 取舍：{例如：忽略寒暄和铺垫，只保留结论和数据}

【输出格式】
- 用无序列表，每条以「• 」开头
- 末尾单独给一句「一句话总结」

【待总结内容】
"""
{把原文粘到这里}
"""
```

注意这里用了一个小技巧：**用 `"""` 把原文包起来**，模型就能清楚区分「哪些是给它的指令」「哪些是要被处理的素材」。这是第 04 章结构化思路的延伸，在长文本任务里特别有用（第 12 章讲安全时，你会发现这招还能防注入）。

**踩坑点：**

- **不限定长度，模型会「越总结越长」**。一定要给条数或字数。
- **不给视角，重点容易跑偏**。同一篇文章，财务关心数字，公关关心口碑——告诉它你关心什么。
- **长文超出上下文窗口**会被截断，导致它只总结了前半段（回顾第 02 章）。太长就先分段总结，再总结这些总结。

---

# 四、翻译类：翻译不是换词，是「带着要求换语言」

直接说「翻译成英文」，你会得到一版「语法对但很生硬」的直译。好的翻译提示词要交代清楚场景、风格和术语。

可直接套用的模板：

```
请把下面的中文翻译成英文。

【翻译要求】
- 场景：{例如：正式商务邮件 / 产品 UI 文案 / 朋友间聊天}
- 风格：{例如：自然地道，像母语者写的，不要逐字直译}
- 术语：{例如：「会员」统一翻成 "membership"，不要用 "VIP"}
- 保留：{例如：保留原文的分段和 Markdown 格式}

【输出格式】
- 只输出译文，不要解释
- 如果某句有多种译法，在译文下方用「备选：」补充

【原文】
"""
{粘贴原文}
"""
```

**踩坑点：**

- **不给场景，语气全靠猜**。「我搞定了」翻给同事和翻进合同里，用词完全不同。
- **专有名词不统一**。同一篇里「用户」一会儿 user 一会儿 customer，看着就不专业。提前用术语表锁死。
- **想要解释 vs 只要译文，要说清楚**。不说的话它经常自作主张加一堆注释。

---

# 五、数据提取类：用「示例 + JSON 格式」双重锁定

这是最该用上 **少样本（第 05 章）+ 格式控制（第 07 章）** 的场景。你要从非结构化文本里抠出字段，光靠描述字段名往往不够稳，给一个示例最管用。

可直接套用的模板：

```
请从下面的文本中提取信息，按指定 JSON 格式输出。

【要提取的字段】
- name：姓名（找不到填 null）
- phone：手机号（找不到填 null）
- intent：咨询意图，只能是 ["购买", "售后", "投诉", "其他"] 之一

【输出要求】
- 严格输出 JSON，不要任何额外文字、不要 Markdown 代码块包裹
- 字段缺失一律填 null，不要瞎编

【示例】
输入：你好，我叫李雷，想问下你们的会员怎么续费，我电话 13800001111
输出：{"name": "李雷", "phone": "13800001111", "intent": "购买"}

【待提取文本】
"""
{粘贴文本}
"""
```

**踩坑点：**

- **不规定「找不到怎么办」，模型会编**。一定要明确「找不到填 null」，否则它会脑补一个手机号给你。
- **枚举值不限定范围，分类会发散**。intent 不写死可选值，它可能给你冒出「咨询续费」这种自创分类，程序没法处理。
- **要程序解析就别让它加废话**。明确「只输出 JSON、不要代码块包裹」，否则你还得写代码剥离 ` ```json ` 这层壳。
- **给一个示例胜过十句描述**。哪怕只有一个例子，模型对齐格式的稳定性也会大幅提升。

# 六、组合的威力：四类任务其实是同一套心法

回头看这四个模板，你会发现它们共享同一个骨架：

1. **交代身份/场景**（你是谁、给谁用）——结构化。
2. **写清要求和约束**（长度、风格、取舍）——结构化 + 约束。
3. **给示例**（尤其提取和分类）——少样本。
4. **锁定输出格式**（列表、JSON、纯译文）——格式控制。
5. **隔离素材**（用 `"""` 包住原文）——结构化 + 安全。

**所以你不用记四套东西，记一套骨架，按任务填空就行。** 这正是前八章铺垫的意义：技巧是零件，实战是把零件按需拼起来。

---

# 七、常见错误（四类任务通用）

1. **背景信息省着给**：模型不读心，你省下的每个细节它都得猜，猜错率很高。
2. **不限定输出长度和格式**：结果忽长忽短、格式飘忽，没法直接用。
3. **该给示例时偷懒只描述**：尤其数据提取和分类，一个示例顶一段废话。
4. **把多类任务塞进一个提示词**：「总结这篇再翻成英文再提取联系方式」——拆开做，成功率高得多（这是第 10 章的主题）。
5. **不告诉模型「没有就别编」**：提取类任务尤其要防幻觉，明确缺失值怎么处理。

---

# 八、最佳实践

- **建立你自己的「填空模板」**：把本章四个模板存下来，下次直接改空填值，别每次从零写（第 11 章教你系统化管理）。
- **素材永远用分隔符包起来**：`"""` 或 `<<< >>>` 都行，让指令和素材泾渭分明。
- **输出格式越具体越好**：要列表就说几条、要 JSON 就给字段和示例。
- **先小样跑通再批量用**：拿一两条数据验证提示词稳定了，再喂大批量，省得错一片。

---

# 九、本章小结

- 写作、总结、翻译、数据提取是四类最高频任务，每类都有可直接套用的模板。
- 四类任务共享同一套骨架：身份/场景 + 要求/约束 + 示例 + 格式 + 素材隔离。
- 核心心法：**技巧是零件，实战是按任务把零件拼起来；记一套骨架，按需填空。**
