# 提示词工程（4）- 04 提示词的结构化设计：五要素框架

> 本章目标：掌握一套通用的提示词「骨架」——五要素框架：角色(Role) + 任务(Task) + 上下文(Context) + 输出格式(Format) + 约束(Constraints)，从此写任何专业提示词都有章可循。
> 读完你能做到：拿到任何需求，都能按框架快速搭出一个结构清晰、效果稳定的提示词。

---

# 一、为什么需要一个「骨架」

上一章我们学了三条原则：清晰具体、给足上下文、明确期望输出。它们很管用，但有个问题——**全靠你临场发挥，容易漏。** 今天记得给上下文，明天忘了说格式；这个需求想到了约束，那个需求又忘了定角色。

解决办法是给提示词一个**固定的骨架**：每次照着填，就不会漏掉关键部分。就像填一张表格，比起对着白纸干想，又快又全。

这个骨架就是 **五要素框架**：

> **角色(Role) + 任务(Task) + 上下文(Context) + 输出格式(Format) + 约束(Constraints)**

这是本书后面所有进阶技巧的**地基**。不管以后你学思维链、学少样本、学多智能体，最底层的提示词，都是在这五个要素上做文章。先把它焊死在脑子里。

---

# 二、五个要素，逐个拆解

## 2.1 角色（Role）—— 你希望它「以谁的身份」回答

给模型一个身份，相当于一次性激活它在这个领域的「专业模式」。

- ❌ 不给角色：「帮我看看这段合同有没有问题。」
- ✅ 给角色：「你是一名有 10 年经验的合同律师。帮我看看这段合同有没有问题。」

加了角色后，它会自动调动更专业的视角、用词和关注点。

**写法**：「你是一名 + 形容词（资深 / 经验丰富）+ 职业 / 专家」。越具体越好，必要时加上它的风格倾向，比如「说话直接、不绕弯子的产品经理」。

> 角色不是必须，但对专业任务几乎总是加分。它本质上就是我们在第 02 章说的 System 人设。

## 2.2 任务（Task）—— 你到底要它做什么

这是核心，一句话说清**你要它干的那件事**。用明确的动词开头：写、总结、翻译、分析、对比、改写、生成……

- ❌ 模糊：「关于这个产品。」
- ✅ 明确：「为这个产品写一段 100 字的卖点文案。」

**写法**：一个动词 + 对象 + 关键要求。一次只聚焦一个主任务，别把五件事塞进一句话。

## 2.3 上下文（Context）—— 它需要知道的背景

把它不知道、但完成任务必须知道的信息给它：你是谁、给谁看、什么场景、相关材料、已有的尝试。

- 比如：「背景：我们是一款面向老年人的健康监测手环，主打操作简单。这次文案要发在子女常看的社交平台，目的是让子女买给父母。」

**写法**：用「背景：」开头，分条列出关键信息。相关材料（原文、数据）也放这里。

## 2.4 输出格式（Format）—— 你要的结果长什么样

明确结果的形式、结构、长度。这一步最容易被忘，但它直接决定结果能不能「拿来即用」。

- 比如：「用表格输出，三列：方案名 | 优点 | 风险」「分三段，每段配一个小标题」「输出 JSON，字段为 title 和 summary」。

**写法**：直接描述你要的形态——列表 / 表格 / JSON / 分段，以及数量、长度、要不要标题。

## 2.5 约束（Constraints）—— 边界和禁忌

告诉它**不能做什么、必须遵守什么**。这是给结果「划红线」。

- 比如：「不超过 200 字」「不要用专业术语」「不要寒暄，直接给结果」「只能基于我提供的资料，不要自行编造数据」「语气要正式」。

**写法**：分条列出「不要 / 必须 / 限制」。尤其针对模型爱犯的毛病（啰嗦、编造、跑题），提前用约束堵住。

# 三、一个可填空的万能模板

把五要素做成一张「填空表」，以后照着填就行：

```
【角色】你是一名 ______（资深/专业身份），擅长 ______。

【任务】请帮我 ______（一个明确的动词 + 要做的事）。

【上下文】
- 背景：______（我是谁 / 做什么的）
- 受众：______（给谁看）
- 场景：______（用在哪里）
- 材料：______（相关原文 / 数据，如果有）

【输出格式】
- 形式：______（列表 / 表格 / 分段 / JSON…）
- 长度：______（多少字 / 几条）
- 结构：______（要不要小标题 / 先结论后展开）

【约束】
- ______（不超过 X 字 / 不要术语 / 不要编造 / 语气要求…）
- ______
```

不是每个空都必须填，但**每次都对着它过一遍**，能确保你不漏掉关键部分。任务越重要，填得越全。

# 四、完整示例：从零搭一个「客服回复」提示词

光看模板没感觉，我们用它从零搭一个真实场景的专业提示词——**电商客服自动回复**。

## 4.1 需求

我开了个网店，顾客经常在收到货后发来各种问题（物流慢、商品有瑕疵、想退换……）。我想要一个提示词，喂进顾客的消息，就能生成一条得体的回复。

## 4.2 第一步：对着模板，一个个填

**【角色】**
```
你是一名经验丰富的电商金牌客服，态度耐心、共情能力强，
擅长安抚情绪并高效解决问题。
```

**【任务】**
```
请根据顾客发来的消息，生成一条客服回复。
```

**【上下文】**
```
- 背景：我们是一家卖手工烘焙饼干的网店，客单价不高，主打口碑和回头客。
- 受众：刚收到货、可能带着情绪的顾客。
- 我们的政策：商品质量问题包退换并补偿一张 5 元优惠券；物流问题可帮忙催单但无法改变时效。
```

**【输出格式】**
```
- 直接输出一条可以发给顾客的回复，不要任何额外解释。
- 100 字以内。
- 结构：先共情安抚 → 再给出具体解决方案 → 结尾留一句暖心话。
```

**【约束】**
```
- 语气真诚、口语化，像朋友，不要机械的官腔。
- 不要承诺我们政策之外的事（比如不能随便答应全额退款 + 退货免邮）。
- 如果顾客情绪激动，先道歉安抚，不要急着讲道理。
- 不要使用「亲」这种过度营销的称呼。
```

## 4.3 第二步：拼成完整提示词

把五块拼起来，再留一个放顾客消息的位置：

```
你是一名经验丰富的电商金牌客服，态度耐心、共情能力强，
擅长安抚情绪并高效解决问题。

请根据顾客发来的消息，生成一条客服回复。

背景信息：
- 我们是一家卖手工烘焙饼干的网店，主打口碑和回头客。
- 政策：商品质量问题包退换并补偿一张 5 元优惠券；
  物流问题可帮忙催单但无法改变时效。

输出要求：
- 直接输出一条可发给顾客的回复，不要额外解释。
- 100 字以内。
- 结构：先共情安抚 → 再给具体解决方案 → 结尾一句暖心话。

约束：
- 语气真诚、口语化，像朋友，不要官腔，不要用「亲」。
- 不要承诺政策之外的事。
- 顾客情绪激动时，先道歉安抚再说方案。

顾客消息如下：
"""
{在这里粘贴顾客发来的消息}
"""
```

## 4.4 第三步：试一条

把顾客消息填进去：「我买的饼干到的时候碎了一大半，太失望了！」

模型会给出类似这样的回复：

```
实在太抱歉了，饼干碎了肯定特别影响心情，是我们包装没做好。
这单我帮您安排重新补发一份，另外送您一张 5 元券作为补偿。
下次一定让它们完完整整到您手上，谢谢您的包容！
```

先共情、给了政策内的方案、结尾暖心，语气也不官腔——**完全符合我们在五要素里定的所有要求**。这就是结构化设计的威力：你把要求拆进框架，结果就稳稳落在你的预期里。

> 注意：这个提示词是**可复用的**。换任何一条顾客消息进去，都能拿到风格一致、合规得体的回复。一次设计，反复使用——这正是把提示词「工程化」的开始。

# 五、常见错误（新手最容易踩的坑）

1. **只有任务，没有其他要素。** 「写条客服回复」——没角色、没背景、没格式、没约束，结果只能是通用废话。
2. **要素混在一起、糊成一团。** 背景、要求、约束全挤在一段里，模型抓不住重点。分块、分条写，它更好理解。
3. **漏掉约束。** 不划红线，模型就容易啰嗦、编造、跑偏。约束是专门用来堵这些坑的。
4. **格式说得太含糊。** 「给我整理一下」——整理成啥样？表格还是列表？说清楚。
5. **死板地非要凑满五个。** 简单任务用不上角色就别硬加。框架是帮你「不漏」，不是逼你「凑数」。

---

# 六、最佳实践（可落地的心法）

- **把五要素当成 checklist，每次过一遍。** 哪个相关填哪个，确保不漏关键部分。
- **分块、分条写，别糊成一段。** 用「角色 / 任务 / 背景 / 输出 / 约束」这样的标题或分隔，模型读得更准。
- **约束专门用来治模型的毛病。** 它爱啰嗦就限字数，爱编造就要求「只基于给定材料」，爱寒暄就「直接给结果」。
- **把好用的提示词模板化、存起来。** 像上面的客服回复，设计一次，以后换内容反复用。
- **复杂任务填满，简单任务精简。** 框架是工具，不是教条。

---

# 七、本章小结

- 五要素框架 = **角色 + 任务 + 上下文 + 输出格式 + 约束**，是写专业提示词的通用骨架。
- 角色激活专业模式，任务说清要做什么，上下文补背景，格式定结果形态，约束划红线。
- 用一张「填空模板」对着填，就不会漏掉关键部分。
- 结构化设计能让结果**稳定落在预期内**，而且提示词可复用、可工程化。
- 这是本书后续所有进阶技巧的地基，务必练熟。

# 动手实践：demo：五要素提示词模板与范例

这个 Demo 配合小册 04 章，给你一套**可直接复制使用**的「五要素提示词模板」，外加 3 个填好的真实范例，让你看到框架在不同场景怎么落地。

## 目录内容

- `五要素填空模板.md`：
  - 一份**空白填空模板**（复制走直接填）。
  - 3 个填好的范例：电商客服回复、产品卖点文案、技术文章大纲。

## 五要素是哪五个

> **角色(Role) + 任务(Task) + 上下文(Context) + 输出格式(Format) + 约束(Constraints)**

- **角色**：让它以什么身份回答（激活专业模式）。
- **任务**：你到底要它做什么（一个明确动词开头）。
- **上下文**：它需要知道的背景（你是谁、给谁看、什么场景、相关材料）。
- **输出格式**：结果长什么样（列表/表格/JSON、长度、结构）。
- **约束**：不能做什么、必须遵守什么（划红线，专治模型爱啰嗦、爱编造的毛病）。

## 怎么用

1. 打开 `五要素填空模板.md`，复制最上面的「空白模板」。
2. 对着五个要素，一个个填空。相关的就填，用不上的（比如简单任务不需要角色）可以删掉。
3. 把填好的提示词粘到任意 AI 工具里运行。
4. 结果不满意？大概率是某个要素没说清——回去补「约束」或「输出格式」往往最见效。

## 一个小提醒

框架是帮你**「不漏」**，不是逼你**「凑满」**。

- 重要、要反复用的任务（比如客服回复模板），五要素尽量填全。
- 随手一问的小任务，填关键的两三个就够。
