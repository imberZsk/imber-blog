# 10-demo：Prompt Chaining 实战「长访谈 → 公众号文章」四步流程

这个 Demo 演示一条完整的提示词串联（prompt chaining）。
核心要点：**每一步只干一件事，上一步的输出，原样粘进下一步的 `{}` 里。**

用法：准备一段长访谈文本，按下面四步依次在 AI 工具里执行，每步拿到结果后填进下一步。

---

## 数据怎么流动（先看全局）

```
访谈原文
   │
   ▼
[第1步] 提炼观点 ──输出──▶ 观点列表
                              │
                              ▼
                      [第2步] 列大纲 ──输出──▶ 文章大纲
                                                 │
                                                 ▼
                          [第3步] 扩写(大纲+原文) ──输出──▶ 文章初稿
                                                              │
                                                              ▼
                                                  [第4步] 润色+起标题 ──▶ 成稿
```

---

## 第 1 步：提炼核心观点

输入：访谈原文。输出：观点列表。

```
你是一位资深内容编辑。下面是一段访谈实录。

请通读全文，提炼出受访者最核心的 5 到 8 个观点。
要求：
- 每个观点用一句话概括，力求精准
- 只提炼「有信息量、有态度」的观点，忽略寒暄和重复
- 用编号列表输出

【访谈实录】
"""
{粘贴访谈原文}
"""
```

> 拿到的输出（假设如此），记作【观点列表】，下一步要用：
> ```
> 1. 真正的增长来自留存，而非拉新。
> 2. 团队超过 20 人后沟通成本指数级上升。
> 3. ……
> ```

---

## 第 2 步：根据观点列大纲

注意输入变了：这一步喂的是【观点列表】，不是访谈原文。

```
你是一位擅长爆款结构的公众号主编。

下面是一篇文章要表达的核心观点列表。请据此设计一个公众号文章大纲。
要求：
- 设计一个抓人的开头钩子
- 把观点重新组织成 3 到 4 个递进的小节，每节给一个小标题
- 标注每节大概要讲什么、用上哪几个观点
- 结尾给一个升华或行动号召

【核心观点列表】
"""
{粘贴第 1 步输出的观点列表}
"""
```

> 拿到的输出记作【大纲】。

---

## 第 3 步：按大纲逐段扩写

这一步要同时喂【大纲】和访谈原文（让扩写有据可依）。

```
你是一位文笔流畅的公众号写手。

请严格按照下面的大纲，把每个小节扩写成完整段落，组成一篇公众号文章。
要求：
- 忠于大纲结构，不要自己改结构
- 语气口语化、有网感，多用短句
- 可以引用访谈里的具体说法增强可信度
- 全文 1200 字左右

【大纲】
"""
{粘贴第 2 步输出的大纲}
"""

【可引用的访谈原文】
"""
{粘贴第 1 步用的访谈原文或相关片段}
"""
```

> 拿到的输出记作【初稿】。

---

## 第 4 步：润色定稿 + 起标题

```
你是一位公众号资深编辑，负责终审。

请对下面这篇初稿做最后润色：
- 删掉啰嗦和重复，让节奏更紧凑
- 检查每段开头是否抓人，弱的改掉
- 全文风格统一为「专业但亲切」
- 最后另起一行，给出 3 个备选标题（带一点悬念感）

【初稿】
"""
{粘贴第 3 步输出的初稿}
"""
```

> 拿到的就是可发布的成稿。

---

## 为什么要这么麻烦地分四步

- **每步专注**：提炼时只提炼、扩写时只扩写，质量比「一次性整理成文章」高得多。
- **可检查**：哪一步结果不满意，只重跑那一步，不用整篇推倒重来。
- **接口对齐**：上一步的输出格式（编号列表、带小标题的大纲），正好是下一步能直接吃的输入。

亲手跑一遍，再用「把这篇访谈直接整理成公众号文章」一次性问一遍，对比两者的成稿质量，差距很直观。
