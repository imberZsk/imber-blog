# AI 编程基础（05） - 规范驱动开发与需求澄清

> 规范不是提前写完所有细节，而是把目标、边界和验收变成开发者与 Agent 都能检查的契约。

> 读完你能：把模糊需求整理成目标、非目标、边界和验收标准，并保持规范与实现可追踪。

## 核心知识清单

- 问题陈述、用户价值与非目标
- 需求澄清、歧义清单与决策记录
- OpenSpec、Spec Kit 与规范驱动开发
- 验收标准、示例、边界和失败场景
- 设计方案、实施计划与任务依赖
- 规范变更、追踪关系与完成证据

## 从模糊需求到可实施任务

先问“用户现在做不到什么”，再定义可观察结果。对接口写请求、响应、错误和兼容性；对 UI 写交互、空态、加载、错误和响应式边界；对数据写来源、权限、迁移和回滚。非目标能阻止 Agent 顺手扩大范围。

```markdown
## 目标
用户提交失败后保留表单内容，并看到可操作错误。
## 非目标
不重做表单组件，不改变后端错误码。
## 验收
- 400：显示字段错误并保留其他输入。
- 500：显示重试入口且只上报一次错误。
- 键盘和移动端流程通过浏览器测试。
```

规范发生变化时同步更新任务和验收，不让代码、测试、文档各自表达不同需求。完成声明必须链接到测试、截图或运行记录。
