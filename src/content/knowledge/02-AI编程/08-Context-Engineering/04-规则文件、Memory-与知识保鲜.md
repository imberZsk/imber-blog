# Context Engineering（04） - 规则文件、Memory 与知识保鲜

> 稳定规则、长期事实和可执行流程应分开存放，否则上下文会同时变得臃肿、过期且难以审计。

## 学习目标

- 区分规则文件、Memory、Skill、README 和 ADR 的职责。
- 为知识写入设置来源、有效期、负责人和敏感信息门槛。
- 用 CI 和定期复盘发现路径、命令、链接和规则冲突的陈旧问题。

## 一、三类载体

| 载体 | 保存什么 | 不保存什么 |
| --- | --- | --- |
| AGENTS.md/CLAUDE.md | 仓库边界、架构、命令、禁止事项 | 某次任务的临时进度 |
| Memory | 稳定偏好、已验证事实、历史决策 | 未验证猜测和敏感原文 |
| Skill | 可复用步骤、脚本、模板和验收 | 与单项目强绑定的业务细节 |

README 负责让人和工具启动项目，ADR 记录关键架构决策，任务计划记录当前工作；不要把所有信息挤进一个规则文件。

## 二、写入门槛

知识写入前回答：是否跨任务仍有效、来源是什么、谁负责、何时过期、变化后如何发现。事实关联提交/文档版本；存在不确定性时标记待验证。规则使用可执行语言，例如“修改 API 后运行 X”，而不是“保持高质量”。

## 三、保鲜机制

- CI 检查规则引用的路径、命令和链接是否存在。
- 代码所有者在架构或发布流程变化时同步更新规则。
- 定期统计未命中、冲突和过期记忆，支持删除与纠正。
- Skill 的脚本在真实环境测试，说明权限与副作用。

## 四、安全

规则与 Memory 都可能被不可信内容污染。写入动作需要来源和权限校验；外部文本不能自动变成高权限指令。团队共享知识与个人偏好分库存储，密钥只保存位置和获取方式，不保存值。
