# 二、后台会话是什么

前面并行干活，你得开好几个终端盯着。
但有些任务很长（跑一大轮重构、补一整套测试），你不想干等。
**后台会话**让任务**脱离终端继续跑**——每个后台会话都是一个**完整的 Claude Code 对话**，
只是没有终端挂在上面。

你派出去就能去忙别的，它在后台自己推进，需要你拍板时再来找你。

---

# 三、用 claude agents 一屏监控

任务一多，怎么知道哪个在跑、哪个卡住要你输入、哪个干完了？
用 **agent view**：

```bash
claude agents
```

它打开一块**统一面板**，列出所有后台 Claude Code 会话，每个的状态一目了然：

- 🟢 **正在跑**：还在干活；
- 🟡 **需要你输入**：卡在某个要你拍板的地方；
- ✅ **已完成**：干完了，等你查收。

在这个面板里你还能**派发新会话**、切进某个会话看详情。
按 `Esc` 退出回到 shell。

> 类比：你是车队调度员，`claude agents` 就是那块大屏，每辆车（会话）在哪、什么状态，尽收眼底。

---

# 四、典型用法：派发 + 巡检

```text
# 1. 派几个后台任务（可结合 worktree 隔离）
#    比如分别让它们去补测试、修 bug、写文档

# 2. 随时巡检
claude agents
#    扫一眼：哪个跑完了？哪个卡住等我输入？

# 3. 进到"需要输入"的那个，给它指示，让它接着跑
```

这套流程让你从「盯着一个终端等」变成「调度一支车队」——**派活 → 巡检 → 只在必要时介入**。

# 六、常见错误

**错误 1：派了一堆后台任务从不巡检**
后台不等于「丢了不管」。
有的会卡在「需要你输入」。
→ 定期 `claude agents` 扫一眼。

**错误 2：把需要你频繁拍板的任务丢后台**
一步一确认的活放后台，反而老来打断你。
→ 后台更适合「能自己跑一长段」的任务。

**错误 3：后台任务都挤在同一目录**
不隔离会互相覆盖。
→ 配合 worktree（第 13 章）给每个后台任务独立工作区。

**错误 4：一次性派太多，自己管不过来**
车队也要量力。→ 从几个开始，熟悉调度节奏再加。

---

# 七、最佳实践

1. **长任务才丢后台**：能自己跑一大段的活适合后台，碎步确认的别放。
2. **定期巡检**：`claude agents` 当成你的「调度大屏」，常扫一眼。
3. **配合 worktree 隔离**：每个后台任务独立工作区，不打架。
4. **只在必要时介入**：让它们自己跑，卡住要输入时你再进去。
5. **控制并发量**：从少到多，匹配你能照看的范围。

# 十三、总结

- **后台会话是什么**：后台会话让任务脱离终端继续跑——每个后台会话都是一个完整的 Claude Code 对话，只是没有终端挂在上面。
- **用 claude agents 一屏监控**：任务一多，怎么知道哪个在跑、哪个卡住要你输入、哪个干完了？
- **典型用法：派发 + 巡检**：这套流程让你从「盯着一个终端等」变成「调度一支车队」——派活 → 巡检 → 只在必要时介入。
- **和前几章的关系**：⚠️ 注意：agent view 目前是研究预览（research preview）特性，不同版本表现可能有差异；
- **常见错误**：有的会卡在「需要你输入」。
- **最佳实践**：长任务才丢后台：能自己跑一大段的活适合后台，碎步确认的别放。 -> 定期巡检：claude agents 当成你的「调度大屏」，常扫一眼。 -> 配合 worktree 隔离：每个后台任务独立工作区，不打架。 -> 只在必要时介入：让它们自己跑，卡住要输入时你再进去。
