# Claude Code（10）- Slash 命令与自定义命令

> 本章目标：掌握内置斜杠命令，把常用流程封装成自定义命令。
> 学完你能：用 `/command` 一键触发重复工作，打造专属工具箱。

---

# 一、什么是 Slash 命令

在对话里输入 `/` 开头的指令，就是 **Slash 命令（斜杠命令）**——一键触发某个功能或流程，不用每次打一长段话。输入 `/` 会弹出所有可用命令列表。

它分两类：**内置命令**（Claude Code 自带）和**自定义命令**（你自己造的）。

---

# 二、常用内置命令

记住这几个高频的，日常够用：

| 命令 | 作用 |
| --- | --- |
| `/help` | 看帮助和可用命令 |
| `/clear` | 清空当前对话上下文，开个干净的（换任务时常用） |
| `/agents` | 管理子代理（第 11 章） |
| `/exit` | 退出 |

> 💡 `/clear` 很重要：一个会话里堆了太多无关任务，上下文会变乱、变贵。换任务时 `/clear` 一下，相当于「翻篇」。（上下文治理见第 22 章。）

---

# 三、重点：自定义命令——把重复流程封装起来

这才是 Slash 命令的威力所在。**某段提示词你反复在用，就该把它做成一个命令。**

## 3.1 怎么做

自定义命令本质是一个 **Markdown 文件**，放在 `.claude/commands/` 目录下。文件名就是命令名。

例如，建一个 `.claude/commands/review.md`：

```markdown
审查当前的代码改动，重点检查：
1. 是否有安全隐患（注入、越权、密钥泄露）
2. 是否有未处理的边界情况
3. 是否符合 CLAUDE.md 里的项目规范

给出问题清单和修改建议。
```

之后在对话里输入 `/review`，就等于把上面这段话发出去——**一键触发标准化审查**。

## 3.2 带参数的命令

命令里可以用占位符接收参数。比如 `.claude/commands/fix-issue.md`：

```markdown
读取 issue #$ARGUMENTS 的内容，定位相关代码，给出修复方案。
```

调用：`/fix-issue 123` → `$ARGUMENTS` 被替换成 `123`。

---

# 四、项目级 vs 用户级命令

和 `CLAUDE.md` 的分级思路一致：

- **项目级**：放项目里的 `.claude/commands/`，提交进 git，**全团队共享**（如团队统一的 review、release 流程）。
- **用户级**：放你的全局 `~/.claude/commands/`，**所有项目都能用**（如你个人的某套调试流程）。

团队规范用项目级，个人习惯用用户级。

---

# 五、常见错误

**错误 1：同一段长提示反复手打**
这是在浪费时间。**复用三次以上，就封装成命令。**

**错误 2：命令写得太死**
该用参数的地方写死了，换个 issue 号就得改文件。→ 用 `$ARGUMENTS` 等占位符。

**错误 3：个人命令塞进项目级**
你的私人流程提交进仓库会污染队友。→ 个人的放用户级。

**错误 4：从不 `/clear`，一个会话用到底**
上下文越堆越杂，回答质量下降、成本上升。→ 换任务时 `/clear`。

---

# 六、最佳实践

1. **复用即封装**：一段提示用了几次，就做成命令。
2. **善用参数**：用占位符让命令通用，别写死。
3. **分级归位**：团队流程→项目级（共享），个人流程→用户级。
4. **命令名见名知意**：`/review`、`/fix-issue`、`/release`，一看就懂。
5. **换任务勤 `/clear`**：保持上下文干净。

---

# 七、总结

- Slash 命令 = 一键触发的指令，`/` 弹出列表。
- 内置常用：`/help`、`/clear`（换任务翻篇）、`/agents`、`/exit`。
- **自定义命令**：把重复提示写成 `.claude/commands/xx.md`，可带 `$ARGUMENTS` 参数。
- 分级：团队共享放项目级，个人习惯放用户级。
