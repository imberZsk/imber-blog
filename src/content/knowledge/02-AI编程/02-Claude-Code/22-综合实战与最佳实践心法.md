# 一、实战一：从零搭一个小项目

> 场景：做一个命令行的「待办清单」小工具，带测试。

```text
1.（立规矩，第05章）我要用 Node 做个命令行待办工具。
   先帮我起草一份 CLAUDE.md：约定用 commonjs、2空格缩进、每个函数带中文注释、改完跑 node 测试。

2.（先规划，第06章）进入 Plan Mode。
   先别写代码，给我一份实现计划：要哪些文件、每个文件职责、先做哪步。

3.（分步实现，第03/04章）按计划第一步：先实现数据存取层 storage.js，只这一个文件。
   （审查 diff，认可后继续下一步）

4.（补测试，第08章）给 storage.js 补测试，覆盖空数据、重复项等边界，然后跑测试，全绿才算完成。

5.（收尾，第09章）帮我看 git diff 确认无误，开分支提交，commit message 按 Conventional Commits 写。
```

**心法**：立规矩 → 先规划 → 分步实现+审查 → 补测试验证 → Git 收尾。**不是「一句话生成整个项目」，而是带着它走完工程闭环。**

# 二、实战二：在陌生代码库修 Bug 并重构

> 场景：接手一个没碰过的项目，有个「偶发的下单失败」要修。

```text
1.（理解，第07章）给我这个仓库的概览，重点讲下单流程怎么走。

2.（并行研究，第11章）用独立子代理并行研究 订单、库存、支付 三个模块，分别给我职责和关键函数。

3.（追链路，第07章）追踪从「点击下单」到「扣库存」的完整代码路径。

4.（诊断，第06章 Plan Mode）下单偶发失败。先别改，分析可能的根因（重点看并发/竞态）。

5.（修复+验证，第07/08章）按你说的根因修复，补一个能复现该并发场景的测试，跑测试全绿才算完成。

6.（自动化护栏，第18/20章）给项目加个 PostToolUse hook：改完文件自动跑 lint；
   再给我一份 GitHub Action，让以后每个 PR 自动做安全审查。
```

**心法**：理解全局 → 并行摸清模块 → 追链路锁定 → 诊断根因 → 修复+补测试 → 加自动化护栏。

# 三、贯穿全书的心法（重点记这些）

## 3.1 心法 1：上下文比提示技巧更重要

与其纠结「怎么把话说得花哨」，不如**把任务输入结构化**：目标、相关文件（用 `@`）、约束边界、验证方式，一次给足。结构化的输入大幅减少它的猜测空间，产出更稳定、更可审查。

> 临时指令写在对话里，长期规则写进 `CLAUDE.md`。

## 3.2 心法 2：复杂任务先规划再执行

复杂需求直接让它写代码，常常逻辑错、反复改。更有效的是**先让它出计划（Plan Mode），认可后再实现**。从「即时生成代码」变成「按计划逐步完成」。

## 3.3 心法 3：让它参与完整开发闭环

别只把它当「代码生成器」。让它走完**实现 → 写测试 → 跑测试 → lint/类型检查 → 审查 diff**。它从「code generator」升级成「开发循环里的 execution node」。

## 3.4 心法 4：会话管理 = 上下文治理

会话不是聊天记录，而是一条**持续积累上下文的工作线程**：任务目标、相关代码、已做的改动、推理过程都在里面。管不好就会变乱、变贵、变笨。实践要点：

- **一个会话一个任务主线**，别在同一线程里堆无关任务；
- 换任务就 `/clear` 翻篇；
- 把探索、跑测试这类「脏活」交给**子代理**，保持主上下文干净（第 11 章）；
- 任务太大撞上下文墙，升级 **Agent Team**（第 12 章）。

## 3.5 心法 5：规则可执行、流程可沉淀

- 规则写成**可检查、可执行**的（第 05 章）：「2 空格缩进」「改完跑 `pnpm test`」，而非「保持整洁」。
- 反复出现的流程**沉淀下来**：一段提示常用就做成自定义命令（第 10 章）/ Skill（第 18 章）；稳定了就 Automation 自动跑。

## 3.6 心法 6：按风险放手，按规模选工具

- **放手程度**按风险定：不熟/高危用「询问」，体力活用「接受编辑」，可控环境才 bypass（第 06 章）。
- **并行工具**按需求选：要结果用 Subagent，要协作用 Agent Team，文件隔离用 Worktree，长任务丢后台 + `claude agents` 监控（第 11-14 章）。
- **自主程度**按场景选：周期查用 `/loop`，干到成用 `/goal`，实时盯用 Monitor（第 15-17 章）。

# 四、能力版图：一句话记住每块拼图

> **CLAUDE.md 管「始终在的上下文」，Skills 管「按需的知识和工作流」，MCP 管「外部连接」，Subagents 管「隔离」，Hooks 管「自动化」。**

再加上本书的另外几块：

- **权限 / Plan Mode**：管「安全地放手」；
- **Subagent / Team / Worktree / 后台**：管「并行规模化」；
- **/loop / /goal / Monitor / Automation**：管「自主运行」；
- **--remote / -p / Action / SDK**：管「远程与无头」。

合起来，就是从「敢用」到「用得好」的完整能力图。

# 五、常见误区总复盘

1. **把 AI 当甩手掌柜**：它是需要 Code Review 的同事，产出永远要你审查。
2. **模糊需求硬上**：想不清就先用 Plan Mode 聊清楚，别让它瞎猜。
3. **一个会话用到底**：上下文越堆越脏，换任务勤 `/clear`、善用子代理。
4. **过度自动化/过度组队**：偶尔用对话解决就行，反复才固化；要结果别硬组队。
5. **无视安全边界**：高危操作、密钥、生产数据、外部不可信输入，时刻设防。
