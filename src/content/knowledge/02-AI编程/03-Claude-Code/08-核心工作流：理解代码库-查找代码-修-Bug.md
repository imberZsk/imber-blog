# Claude Code（08） - 核心工作流：理解代码库 / 查找代码 / 修 Bug

> 本章目标：掌握日常最高频的三类操作——读懂代码库、定位相关代码、复现并修复 Bug。
> 学完你能：独立走完「读懂项目 → 找到问题 → 改掉它 → 验证修好了」的闭环。

---

这一章是「肌肉记忆」章。前面学的都是为了这里——真正干活。三件套：**理解 → 查找 → 修复**。

---

# 一、快速理解一个代码库

接手陌生项目，别自己一头扎进去翻文件。让 Claude Code 先给你「导游」。

**技巧：从宽到窄，逐层下钻。**

```
# 第一层：要个全局概览
给我这个仓库的概览

# 第二层：问架构和关键设计
这里用的主要架构模式是什么？
关键的数据模型有哪些？
认证是怎么处理的？

# 第三层：要术语表（项目黑话）
给我一份这个项目特定术语的词汇表
```

> 💡 提示：用项目里的语言提问（它叫「工单」你就别说「ticket」），它定位得更准。

---

# 二、查找相关代码

知道「想找啥」但不知道「在哪」，正是它的强项。

```
# 1. 先找到文件
找到处理用户认证的文件

# 2. 再问它们怎么协作
这些认证文件是如何协同工作的？

# 3. 追踪一条完整链路
追踪从前端到数据库的登录流程
```

第 3 步特别有用——**让它把一条业务链路从头到尾串给你**，比你自己跳着读快得多。

> 关键习惯：**明确说要找什么 + 用项目里的词**。「找登录相关代码」比「找 auth 那块」更不容易跑偏。

---

# 三、修复 Bug（最核心的闭环）

修 Bug 是验证「读—改—跑—验证」循环的最佳场景。给它的信息越足，它修得越准。

**关键：把「怎么复现」和「怎么算修好」都告诉它。**

```
# 1. 给它报错和复现方式
我运行 `npm test` 时看到一个错误，堆栈如下：[贴报错]。
这个错误是稳定复现的。

# 2. 让它先诊断（可结合 Plan Mode）
先别改，告诉我这个 bug 的根因在哪、你打算怎么修。

# 3. 安全地修，并保持行为
修复它，注意不要改动 sum 之外的函数行为。

# 4. 让它自己验证
修完重新跑 `npm test`，全绿才算完成。
```

第 4 步是灵魂——**带上验证方式**，它改完会自己跑测试确认，没过会自己再改，形成闭环。

> 💡 间歇性 bug 要特别说明：「这个错误是偶发的，不是每次都出现」。它会据此采取不同的排查策略（比如找竞态、找未初始化状态）。

---

# 四、三件套串起来：一个完整例子

> 场景：新接手项目，下单偶尔丢优惠券。

```
1.（理解）给我这个仓库的概览，重点说说下单流程怎么走。
2.（查找）追踪从「点击下单」到「优惠券核销」的完整代码路径。
3.（定位）优惠券偶尔没被核销。先别改，分析可能的根因。
4.（修复）按你说的根因修复，改完跑 `npm test`，并补一个能覆盖这个场景的测试。
```

这就是一次真实的工作闭环：**理解全局 → 锁定链路 → 诊断根因 → 修复并验证。**

---

# 五、常见错误

**错误 1：直接「修一下这个 bug」，啥背景都不给**
它只能猜复现方式。→ 给报错、给复现步骤、说清是稳定还是偶发。

**错误 2：不给验证方式，它「改了就交」**
没有「跑什么算修好」，它无法自我确认。→ 永远附上验证命令。

**错误 3：让它「读完整个仓库」**
大项目这样既慢又抓不住重点。→ 从概览开始，按需下钻到具体模块。

**错误 4：复杂 bug 不先诊断就让它改**
容易头痛医头。→ 先让它（最好在 Plan Mode 下）分析根因，认可了再动手。

---

# 六、最佳实践

1. **理解从宽到窄**：概览 → 架构 → 具体模块，别一上来钻细节。
2. **查找用项目术语**：说它的「黑话」，定位更准。
3. **修 Bug 给全三件套**：复现方式 + 根因诊断 + 验证命令。
4. **先诊断后动手**：复杂 bug 先让它讲根因，再修。
5. **修完必验证**：让它自己跑测试，并尽量补一个覆盖该场景的测试。

---

# 七、总结

- 三件套：**理解（从宽到窄）→ 查找（用项目术语、追链路）→ 修复（带复现+验证的闭环）**。
- 修 Bug 的灵魂是**附上验证方式**，让它自我确认、自我纠错。
- 复杂问题先诊断根因再动手，别头痛医头。

# 动手实践：Demo 07 · 理解 / 查找 / 修复 三件套实战

一个**多文件的迷你项目**（用户登录 + 优惠券下单），故意埋了一个「优惠券偶尔没核销」的 bug。用来完整练习本章三件套。

## 项目结构
- `auth.js`：登录校验
- `coupon.js`：优惠券核销（埋了 bug）
- `order.js`：下单流程，串起 auth 和 coupon
- `order.test.js`：测试（会暴露 bug）

## 怎么练（照着第 07 章三件套）

1. 建基线：`git init && git add -A && git commit -m baseline`
2. 跑测试看失败：`node order.test.js`
3. 三件套对话：
   ```
   （理解）给我这个仓库的概览，说说下单流程怎么走。
   （查找）追踪从 placeOrder 到优惠券核销的完整代码路径。
   （修复）order.test.js 有用例失败。先别改，分析优惠券没核销的根因；
           认可后再修 @coupon.js，修完跑 `node order.test.js` 全绿才算完成。
   ```
