# 二、权限模型

按角色、仓库、环境和动作授权：只读调查、工作树写入、测试命令、创建 PR、合并、部署、生产查询和数据修改分别控制。
默认短期凭据和最小范围，高风险命令需要策略拦截或人工确认。

# 三、隔离与审查

- 每个任务使用独立分支/worktree 和可重建环境。
- Agent 不覆盖用户未提交改动，不把无关文件带入 PR。
- 产出者负责自检，独立审查者优先找缺陷，合并者核对 CI 和范围。
- 生成代码沿用普通安全评审，不能因“由 AI 生成”降低门槛。

# 四、成本治理

记录团队、任务、模型、Token、工具时长、CI 和返工成本。
先以“每个成功任务成本”衡量，而非只看每次调用价格。
为探索、实现、评测设置预算；
超预算时降级模型、缩小上下文或请求人工决策，禁止无界循环。

# 五、供应链与数据

Agent 建议的新依赖需核对来源、许可证、维护状态和漏洞。
Prompt、日志和工具结果按数据分类处理，机密仓库不得发送给未批准服务。
MCP/插件/Skill 是代码与权限扩展，安装前审查发布者、版本、脚本和网络能力。

# 六、发布门禁

发布记录提交 SHA、构建摘要、测试、审批、配置和回滚负责人。
生产变更采用灰度并监控用户指标；
Agent 可以准备命令和证据，但除非授权，不自动越过外部状态变化。
