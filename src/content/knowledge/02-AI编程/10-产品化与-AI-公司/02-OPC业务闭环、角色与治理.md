# 产品化与 AI 公司（02） - OPC 业务闭环、角色与治理

> OPC 的优势是决策链短，不是一个人承担所有工作。Agent 可以扩大执行能力，但使命、风险和最终责任仍属于人类创始人。

> 读完你能：设计市场到财务的最小闭环，划分人和 Agent 的职责，并建立 SOP、知识、绩效和风险治理。

## 核心知识清单

- 人类创始人与适合 OPC 的业务
- 市场、需求、产品、交付、销售与客服
- 财务、合规、数据反馈与迭代
- 使命、目标、指标、角色与责任边界
- 任务工单、SOP、Skill、知识与记忆
- 风险分级、审批、评测与绩效
- 常见失败：伪需求、失控自动化与无责任 Agent

## 先闭环再自动化

适合 OPC 的业务通常有明确用户、可重复交付、较低固定成本和可线上获客。先由人跑通“发现问题 → 提供价值 → 收费 → 交付 → 支持 → 复购”，再把高频、可验证步骤交给 Agent。

人类创始人负责方向、资本、法律、品牌、高风险审批和最终质量；Agent 可负责调研、内容、代码、客服分流、数据分析和例行运营。Agent 输出必须有验收人或确定性验收器。

## 运营底座

每个目标关联指标，每项任务有负责人、截止时间、输入、产物和完成证据。SOP 描述流程，Skill 固化可复用执行，知识库保存事实，记忆保存上下文，四者不能混为一谈。

风险按读取、内部写入、外部沟通、资金/法律动作分级。越高风险越需要最小权限、具体参数审批和不可篡改审计。绩效看任务成功、返工、成本和用户结果，不看 Agent 生成字数。
