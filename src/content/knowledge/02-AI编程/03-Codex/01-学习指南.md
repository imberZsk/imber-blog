# 《Codex》学习路线与目录

这本小册的目标不是把 Codex 的每个按钮背下来，而是帮你建立一套稳定的使用方法：知道什么时候直接问，什么时候给上下文，什么时候让 Codex 改代码、跑命令、审查结果，什么时候把经验沉淀成 AGENTS、配置、Skill 或插件。

如果你有前端背景，可以把 Codex 理解成一个“会读仓库、会操作终端、会写补丁、会自检”的协作开发者。提示词像需求文档，AGENTS.md 像项目规范，MCP 像给它接后端接口，Skill 和插件像把常用工作流封装成可复用工具。

## 学习方式

1. 先读每章正文，重点看“概念解释”和“使用示例”。
2. 再打开同编号 demo，复制其中的提示词或命令试一遍。
3. 最后回到自己的项目里，把当章的最佳实践迁移进去。

## 阶段目标

### 第一阶段：先能用

完成 01-03 章后，你应该能：

- 分清 Codex 的几个使用场景：问答、改代码、审查、跑命令、写文档。
- 写出不空泛的提示词，让 Codex 知道目标、边界、输入和验收标准。
- 用 AGENTS.md 给项目留下长期规范。

### 第二阶段：用得稳

完成 04-07 章后，你应该能：

- 用 CLI 执行一次性的批处理任务。
- 理解 sandbox 和 approval 的关系，知道什么时候该保守，什么时候可以放开。
- 用 config/profile 管理不同项目或不同风险等级的默认行为。
- 用 MCP 把 Codex 接到外部系统或私有工具上。

### 第三阶段：沉淀成体系

完成 08-10 章后，你应该能：

- 把重复提示词整理成 Skill。
- 用 Subagent 拆分复杂任务，用 Hook 做底线检查。
- 设计一个小型 Codex 插件，把技能、代理和市场索引组织起来。

## 目录自查

这套目录按“先把一个任务做好，再把多个任务做稳，最后把流程复用”的顺序设计。前 3 章不会要求读者先理解复杂配置；中间 4 章解决真实使用中的可控性问题；最后 3 章再进入扩展体系，避免一上来就被插件、MCP、Hook 这些概念劝退。

没有把“模型原理”“大而全 API 手册”放进主线，因为它们不是上手 Codex 的最短路径。需要深入时，可以在对应章节后继续扩展专题。
