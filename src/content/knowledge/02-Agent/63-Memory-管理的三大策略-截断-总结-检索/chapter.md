# Memory 管理的三大策略：截断、总结、检索

> 读完你能：理解 Agent 记忆不是无限追加聊天记录，而是在截断、总结、检索之间做取舍。
> 来源：`吃透 AI Agent 开发` 截图目录第 11 篇，2026/01/22，可试读 10%
> 导入与重写日期：2026/07/07

## 本篇定位

这是 31 Agent 记忆与状态的进阶版，重点讲上下文窗口有限时怎么管理历史。

## 一个真实场景

一个客服 Agent 连续和用户聊了半小时，如果每轮 messages 全塞进模型，成本会越来越高，最后还会超上下文。粗暴删除历史又会丢掉用户已经说过的需求。Memory 管理就是在“保留足够信息”和“控制上下文长度”之间找平衡。

## 核心拆解

- 截断是最便宜的策略：保留最近 N 轮，丢掉更早历史。适合短会话，但会遗忘早期关键约束。
- 总结是把旧历史压缩成一段摘要。它能保留主线，但摘要可能漏细节，且摘要本身会随多次压缩失真。
- 检索是把历史拆成记忆条目，需要时按当前问题召回。它更适合长期记忆和跨会话偏好，但要处理过期、冲突和权限。

## 工程链路

- 短会话先保留最近消息。
- 上下文接近阈值时总结旧消息。
- 重要事实写入长期记忆库。
- 新问题到来时检索相关记忆。
- 把近期消息、摘要、检索记忆一起拼成上下文。

## 落地建议

- 用户偏好、身份信息、长期目标适合写长期记忆。
- 临时任务状态适合放 session state，不要写进永久记忆。
- 摘要要带时间和来源，方便判断是否过期。

## 常见坑

- 把所有聊天都永久保存，既贵又有隐私风险。
- 摘要不校验，越压缩越偏。
- 检索到旧记忆后不判断是否仍然有效。

## 复述答法

> Memory 管理主要三招：截断保最近上下文，总结压缩旧历史，检索召回长期记忆。工程上不能无限追加 messages，要区分 session state、摘要和长期记忆，并处理过期、冲突和隐私。
