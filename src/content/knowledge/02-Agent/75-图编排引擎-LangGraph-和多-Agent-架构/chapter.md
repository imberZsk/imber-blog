# 图编排引擎：LangGraph 和多 Agent 架构

> 读完你能：理解为什么复杂 Agent 要用状态图，以及多 Agent 应该按上下文边界拆分。

## 本篇定位

这是 LangGraph 进阶篇。36 讲入门状态图，本篇进入多节点和多 Agent 架构。

## 一个真实场景

一个深度调研助手要搜索资料、阅读网页、提炼观点、反思缺口、继续搜索，最后生成报告。它不是直线流程，而是会根据中间结果回到前面步骤。状态图能把这种循环和分支显式表达出来。

## 核心拆解

- LangGraph 的核心是 State、Node、Edge。State 保存共享上下文，Node 执行一步工作，Edge 决定下一步去哪。
- 多 Agent 不是为了“产品经理 Agent、工程师 Agent”这种角色扮演，而是为了隔离上下文、工具权限和任务目标。
- 图编排让失败路径也可见：节点失败、条件不满足、达到最大轮次时去哪，都要写进图里。

## 工程链路

- 定义全局 State。
- 拆分检索、阅读、计划、写作、检查等节点。
- 用条件边表达命中、失败、继续、结束。
- 为不同子任务配置不同工具和 prompt。
- 记录每个节点输入输出。

## 落地建议

- 先用单 Agent 状态图跑通，再拆多 Agent。
- 每个 Agent 的工具集合越小越好。
- 全局状态只放必要信息，避免所有节点共享一团大对象。

## 常见坑

- 按角色名乱拆 Agent，实际上下文没有隔离。
- 图里没有最大循环次数。
- 状态越来越大，最后每个节点都带着无关历史。

## 复述答法

> LangGraph 适合有循环、分支、回退的 Agent。多 Agent 的拆分依据不是角色好听，而是上下文、工具权限和任务目标是否需要隔离。图里要显式写出成功、失败、重试和停止路径。
