# 31 Agent 记忆与状态 demo

演示两种记忆的区别：**short-term（会话记忆，有容量上限、会话结束就没）** 和 **long-term（长期记忆，持久化、跨会话保留）**。

## 运行

```bash
python3 main.py
```

零依赖，纯标准库。运行中会临时写一个 `long_term_memory.json` 模拟数据库，结束自动清理。

## 预期输出

```
=== 会话 1（首次，建立记忆）===
已把默认客户号 C1001 写入长期记忆（持久化到文件）
短期记忆容量上限 4，当前保留：
  assistant: 好的，已记住你的默认客户号
  user: 帮我查下它的订单
  assistant: C1001 共 2 笔订单
  user: 再看看有没有退款
（注意：最早的『默认客户号是 C1001』已被挤出短期记忆）

=== 会话 2（新会话，验证长期记忆）===
新会话的短期记忆：（空）
从长期记忆读回默认客户号：C1001
所以新会话不用再问一遍，这就是长期记忆的价值

（演示结束，已清理临时记忆文件）
```

两个关键现象：会话1里短期记忆容量是 4，第 5 条消息加入后，最早的「默认客户号是 C1001」被挤出去了（短期记忆装不下全部历史）；但因为它被写进了长期记忆，会话2 短期记忆全空的情况下，依然能读回 C1001，不用再问用户一遍。

## 代码↔概念对应

| 概念 | 在 main.py 哪里 |
|---|---|
| 短期记忆（会话内消息） | `ShortTermMemory` |
| 短期记忆截断（滑动窗口） | `ShortTermMemory.add` 里的截断 |
| 长期记忆读取 | `load_long_term` |
| 长期记忆持久化 | `save_long_term` |
| 建立记忆（写短期 + 持久化长期） | `session_one` |
| 跨会话读回长期记忆 | `session_two` |

## 说明

短期记忆为什么要截断：模型上下文窗口有限，不可能把整个对话历史都塞进去，超长要裁剪（这里用最简单的「保留最近 N 条」，真实项目还会做摘要压缩）。长期记忆为什么要持久化：用户偏好、关键事实不能随会话消失，所以存数据库或向量库，下次会话按需读回。这里用一个 JSON 文件模拟持久化存储。
