# A1 - 附录-Python陷阱对照

> 你在 JS 里被 `var` 提升、`==` 隐式转换、对象引用复制坑过——Python 也有一组"长得人畜无害、踩下去很疼"的坑。本篇专治前端转 Python 最高频的四类翻车：可变默认参数、循环里的闭包、`is` 与 `==` 混用、深浅拷贝。每个坑都给出 JS 对照，告诉你哪里"和 JS 一样别慌"、哪里"和 JS 不一样要改心智"。

## 切入点：你早就被语言坑过

JS 有它的"经典面试题坑"：`for (var i...)` 循环里 `setTimeout` 全打印同一个值、`[] == ![]` 为 `true`、`const obj2 = obj1` 改一个动另一个。Python 的坑结构上一一对应，只是触发点换了位置。把这篇当成"Python 版的 JS 怪异题集"来读最省力。

| JS 的经典坑 | Python 的对应坑 | 本篇章节 |
|------------|----------------|---------|
| `for (var i...)` + 异步闭包打印同值 | 循环里 lambda/闭包共享变量 | 二 |
| `==` 隐式类型转换乱套 | `is` 当成 `==` 用 | 三 |
| `obj2 = obj1` 引用复制改一动二 | 列表/字典赋值与浅拷贝 | 四 |
| 函数参数对象被意外共享 | 可变默认参数只创建一次 | 一 |

## 一、可变默认参数：函数的"默认值"只生成一次

这是 Python **独有、JS 没有对应物**的头号坑，新手几乎必踩。

```python
# bad_append：往列表里加一个元素并返回
# items：默认空列表——这里就是陷阱所在
def bad_append(item, items=[]):
    items.append(item)             # 往这个列表里塞 item
    return items

print(bad_append(1))   # [1]      —— 看起来正常
print(bad_append(2))   # [1, 2]   —— ？！上次的 1 还在
print(bad_append(3))   # [1, 2, 3] —— 默认列表被"记忆"了
```

**为什么会这样（WHY）**：Python 的默认参数值在**函数定义时只计算一次**，之后所有调用共享同一个对象。`items=[]` 这个空列表在 `def` 执行时就被创建好、绑死在函数上，不是每次调用都新建。

JS 程序员的直觉来自这里——JS 的默认参数是**每次调用都重新求值**的：

```javascript
// JS：默认值每次调用都重新生成一个新数组，所以没有这个坑
function append(item, items = []) {
  items.push(item)
  return items
}
append(1)  // [1]
append(2)  // [2]  —— 干净，互不影响
```

**正确写法**：默认值用 `None`（不可变哨兵），在函数体里再创建：

```python
# good_append：正确版本
# items：默认 None，表示"调用方没传"
def good_append(item, items=None):
    # 业务场景：调用方没传 items 时，每次都新建一个独立列表
    if items is None:
        items = []                 # 每次调用都是全新的列表，互不污染
    items.append(item)
    return items

print(good_append(1))  # [1]
print(good_append(2))  # [2]   —— 修好了
```

记忆口诀：**默认参数永远别用可变对象（`[]` `{}` `set()`）当默认值，一律用 `None` 占位再在体内创建。** 这条规则没有例外，背下来。

## 二、循环里的闭包：变量是"晚绑定"的

这个坑 JS 老手会**秒懂**，因为 `var` 时代天天踩。

```python
# 想造 3 个函数，分别返回 0/1/2，结果全返回 2
funcs = []                         # funcs：存放生成的函数列表
for i in range(3):
    # lambda 闭包捕获的是变量 i 本身，不是当时的值
    funcs.append(lambda: i)

print([f() for f in funcs])   # [2, 2, 2] —— 全是 2，不是 [0, 1, 2]
```

**为什么（WHY）**：闭包捕获的是**变量本身的引用**，不是定义那一刻的值。等循环跑完，`i` 已经停在 2，三个 lambda 此时才被调用，读到的都是最终的 `i=2`。这和 JS `var` 的行为一模一样：

```javascript
// JS：var 版本完全同款翻车
var funcs = []
for (var i = 0; i < 3; i++) {
  funcs.push(() => i)
}
console.log(funcs.map(f => f()))  // [3, 3, 3] —— 同样的坑
```

JS 的解法是改用 `let`（块级作用域，每轮新建绑定）。但 **Python 没有 `let`，也没有块级作用域**——这就是边界差异：你不能照搬 JS 的修法。Python 的解法是用**默认参数**在定义时"快照"当前值：

```python
funcs = []
for i in range(3):
    # default=i：利用"默认参数定义时求值"的特性，把当前 i 的值拍快照存进 default
    # WHY：默认参数在 lambda 创建时立即求值，于是每个 lambda 各存各的值
    funcs.append(lambda default=i: default)

print([f() for f in funcs])   # [0, 1, 2] —— 修好了
```

有意思的是：第一节"默认参数只求值一次"是个坑，这里反过来**利用**同一个机制来解题。理解了机制，坑和技巧是一体两面。

> 边界提醒：Python 的循环变量 `i` 在循环结束后**依然存在**（没有块级作用域），这点也和 JS 的 `let` 不同——别以为出了 `for` 它就消失了。

## 三、`is` vs `==`：身份相等 vs 值相等

JS 里你纠结 `==` 和 `===`；Python 里换成纠结 `==` 和 `is`，但**对应关系不是你以为的那样**。

先建立锚点，再立刻划清边界：

| 比较 | JS | Python | 比的是什么 |
|------|----|--------|-----------|
| 值相等 | `==`（带隐式转换） | `==`（不隐式转换） | 内容是否相等 |
| 严格相等 | `===` | —— | （Python 的 `==` 已经不转换类型） |
| 引用/身份相等 | `===`（对象比较引用） | `is` | 是不是**同一个对象** |

关键差异：**Python 的 `==` 不做 JS 那种离谱的隐式类型转换**（不会有 `[] == ![]` 这种鬼故事），所以日常比较值用 `==` 就对了。`is` 比的是"**是不是内存里同一个对象**"，约等于 JS 对象用 `===` 比引用。

```python
a = [1, 2, 3]                      # a：一个列表
b = [1, 2, 3]                      # b：内容相同、但是另一个新建的列表
c = a                              # c：和 a 指向同一个对象

print(a == b)   # True  —— 内容相等
print(a is b)   # False —— 不是同一个对象（两块不同内存）
print(a is c)   # True  —— c 就是 a 本身
```

**最大的坑：用 `is` 比较数字/字符串，会被"小整数缓存"骗到。** Python 把 `-5` 到 `256` 的小整数预先缓存复用，导致 `is` 时灵时不灵。下面用**交互式 REPL（逐行输入）**演示，这样才能稳定看到差异：

```python
# 以下是 REPL 里逐行敲入的效果（>>> 是提示符）
>>> x = 256            # x：值 256，落在缓存区间内
>>> y = 256            # y：同样是 256
>>> x is y             # 256 在 -5~256 缓存范围内，复用同一个对象
True
>>> x = 257            # x：值 257，超出缓存区间
>>> y = 257            # y：同样是 257
>>> x is y             # 超出缓存范围，是两个新建的不同对象
False
```

注意：**这个 `False` 只在逐行输入的 REPL 里稳定出现。** 如果把 `x = 257` / `y = 257` 写进同一个 `.py` 脚本一起运行，编译期的"常量折叠"可能让 `257 is 257` 也变成 `True`——也就是说结果会随运行方式而变（CPython 实现细节，别依赖）。

正因为 `is` 的结果如此不可靠，所以**比较值永远用 `==`，绝不用 `is`**。`is` 只用在一个地方：和单例 `None` / `True` / `False` 比较。

```python
# 正确：判断是否为 None 永远用 is（None 是全局唯一单例）
if items is None:        # ✅ 地道、明确、最快
    ...

if items == None:        # ⚠️ 能跑但不地道，且可能被自定义 __eq__ 干扰
    ...
```

记忆口诀：**`is None` 是唯一该用 `is` 的高频场景；比较内容一律 `==`。**

## 四、深浅拷贝：`b = a` 不会复制内容

这个坑 JS 程序员**完全有共鸣**——`const b = a` 对对象/数组只是复制引用，改一个动另一个。Python 一模一样。

```python
a = [1, 2, 3]            # a：原列表
b = a                    # b：不是拷贝！只是给同一个列表起了第二个名字（同 JS 引用赋值）
b.append(4)
print(a)   # [1, 2, 3, 4] —— 动 b 也动了 a
```

```javascript
// JS 同款行为
const a = [1, 2, 3]
const b = a              // 只复制引用
b.push(4)
console.log(a)           // [1, 2, 3, 4]
```

那怎么真正复制？这里 Python 比 JS 多分了两层概念——**浅拷贝 vs 深拷贝**：

```python
import copy

# 原始数据：一个"嵌套了列表的列表"，用来暴露深浅拷贝的区别
nested = [[1, 2], [3, 4]]   # nested：外层是列表，每个元素又是列表

shallow = copy.copy(nested)        # shallow：浅拷贝，外层是新列表，但内层子列表仍是同一批引用
deep = copy.deepcopy(nested)       # deep：深拷贝，里里外外全部新建，彻底独立

nested[0].append(999)              # 改原始数据里第 0 个子列表

print(shallow)  # [[1, 2, 999], [3, 4]] —— 浅拷贝跟着变了（内层共享）
print(deep)     # [[1, 2], [3, 4]]      —— 深拷贝纹丝不动（完全独立）
```

**浅拷贝（shallow）**：只复制最外层容器，里面的子对象还是共享引用。常见写法有 `copy.copy(x)`、`list(x)`、`x[:]`、`dict(x)`、`{**x}`。

**深拷贝（deep）**：递归复制所有层级，得到一棵完全独立的新树，用 `copy.deepcopy(x)`。

对照 JS 你就秒懂——这正是 JS 里"浅拷贝 vs 真·深拷贝"的同一组概念：

| 操作 | JS | Python | 复制深度 |
|------|----|--------|---------|
| 引用赋值（不拷贝） | `const b = a` | `b = a` | 0 层，同一个对象 |
| 浅拷贝 | `[...a]` / `{...a}` / `Object.assign({}, a)` | `a[:]` / `list(a)` / `{**a}` | 1 层 |
| 深拷贝 | `structuredClone(a)` | `copy.deepcopy(a)` | 全部层级 |

边界提醒：JS 的 `[...a]`、`{...a}` 也是浅拷贝，嵌套对象同样共享——所以这个"浅拷贝只管一层"的坑你其实在 JS 早见过，规则完全迁移得过来。需要彻底独立时，JS 用 `structuredClone`，Python 用 `copy.deepcopy`。

## 五、附赠几个高频小坑（认脸即可）

这些不展开，先混个眼熟，遇到不至于懵：

```python
# 坑 1：整数除法 / 和 // 不同
print(7 / 2)    # 3.5  —— 单斜杠永远返回 float（哪怕能整除：4/2 == 2.0）
print(7 // 2)   # 3    —— 双斜杠才是"地板除"（向下取整）

# 坑 2：链式比较是真的链式（JS 没有）
age = 20                # age：被比较的年龄值
print(18 <= age < 60)   # True —— 等价 (18 <= age) and (age < 60)，别写成 JS 的 18 <= age < 60 那种会错的形式

# 坑 3：and/or 返回的是"值"不是布尔（类似 JS 的 || && 短路，但更要小心）
name = "" or "默认名"   # name：空字符串是 falsy，于是取到 "默认名"（同 JS 的 ||）
print(name)             # 默认名

# 坑 4：可变对象不能当字典 key / 不能放进 set
# d = {[1, 2]: "x"}     # ❌ TypeError：list 不可哈希。要用 tuple (1, 2) 当 key
```

| 小坑 | JS 直觉 | Python 真相 |
|------|---------|------------|
| `/` 除法 | `7/2 === 3.5` | 一致，但 `4/2` 也是 `2.0`（float）；要整数用 `//` |
| 链式比较 | `1 < 2 < 3` 在 JS 是 bug | Python 原生支持，是正确语法 |
| `and`/`or` | `||` `&&` 返回操作数 | 一致，返回值而非布尔 |
| 可变对象做 key | 对象可当 Map 的 key | list/dict/set 不可哈希，要用 tuple |

## 小结

Python 的坑和 JS 的坑结构上高度对应，但触发点搬了家。最该刻进肌肉记忆的是第一节——**可变默认参数**，这是 JS 完全没有、而 Python 几乎人人踩的独有坑。其余三个（闭包晚绑定、`is`/`==`、深浅拷贝）你在 JS 时代多半见过同款，规则基本能平移，只要记住差异点即可。

✅ 该掌握
- 默认参数用可变对象会被所有调用共享；一律用 `None` 占位再在体内 `if x is None: x = []`
- 循环闭包是晚绑定（捕获变量而非值）；Python 用默认参数 `lambda x=i: x` 拍快照（没有 `let` 可用）
- 比较内容用 `==`（不做 JS 那种隐式转换）；`is` 只用于和 `None`/`True`/`False` 比较
- 拷贝分三层：`b = a`（引用）/ 浅拷贝（`a[:]`、`{**a}`）/ 深拷贝（`copy.deepcopy`）

⚠️ 易混淆
- 默认参数"只在定义时求值一次"——既是坑（第一节）也是解题技巧（第二节闭包快照）
- `is` 比小整数/短字符串会被缓存骗到（REPL 里逐行敲 `256 is 256` 为 True、`257 is 257` 为 False；写进脚本因常量折叠结果可能不同），别用 `is` 比值
- 浅拷贝只复制一层，嵌套对象仍共享——JS 的 `[...a]` 同理，需要彻底独立用 `deepcopy`
- `7 / 2` 是 `3.5`，整数除法要用 `//`；list/dict 不能当字典 key（不可哈希）
- Python 没有块级作用域，循环变量出了 `for` 依然存在
