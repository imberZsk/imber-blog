# 二、配置、密钥与业务数据边界

ConfigMap 保存非敏感配置，
Secret 只提供 API 对象层面的分类，
不代表默认加密；
etcd 加密、RBAC 和外部密钥系统共同决定安全。
业务持久数据使用 PVC/PV 或托管存储，不能写入 Pod 临时文件系统。

# 三、注入、更新与版本化发布

环境变量在进程启动时固定，Volume 投影可最终更新但应用是否重载取决于自身。
生产配置应带版本或哈希触发 Deployment 滚动，Secret 不出现在命令参数和日志；
更新前验证新旧版本兼容并保留回滚材料。

# 四、StorageClass、访问模式与恢复

PersistentVolume（PV）由 PersistentVolumeClaim（PVC）按 StorageClass 申请，
访问模式描述挂载能力，
不保证数据库多写安全。
StatefulSet 为有状态副本提供稳定身份，
Helm Chart 管理版本化清单，
Volume Snapshot 进入备份流程后还必须定期恢复并校验业务数据。

# 五、配置与持久卷声明

应用从只读投影读取配置，并把业务数据写入 PVC。

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata: { name: app-data }
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests: { storage: 20Gi }
---
containers:
  - name: app
    envFrom:
      - configMapRef: { name: app-config-v3 }
      - secretRef: { name: app-secret-v2 }
    volumeMounts:
      - { name: data, mountPath: /var/lib/app }
volumes:
  - name: data
    persistentVolumeClaim: { claimName: app-data }
```

Secret 值应由密钥系统或受控流水线创建，不把明文写进清单。
删除工作负载前确认 PVC 和 PV 回收策略。
