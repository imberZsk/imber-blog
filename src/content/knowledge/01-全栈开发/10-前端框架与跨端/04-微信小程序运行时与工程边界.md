# 前端框架与跨端（04） - 微信小程序运行时与工程边界

> 读完你能：解释小程序逻辑层与视图层通信，并处理登录、分包、权限和平台发布边界。

## 核心知识清单

- 逻辑层、视图层与原生组件
- WXML、WXSS、事件与 setData
- 主包、分包、预下载与包体预算
- wx.login、服务端会话与用户身份
- 平台 API、权限授权与隐私合规
- 真机调试、版本审核与灰度发布

## 运行时差异

小程序不是普通浏览器页面，逻辑层与视图层通过桥通信。频繁传大对象给 `setData` 会产生序列化和通信成本，应只更新变化字段。平台 API 受权限、基础库和审核规则约束，Web 组件不能直接假设可用。

`wx.login` 的临时 code 交给服务端换取平台会话，客户端不能保存平台密钥。用户身份、业务 Token 与开放数据解密在服务端完成，并防止 code 重放。

## 数据更新与登录链路

页面状态更新只发送变化字段，列表大批更新时分批或分页，避免每次 `setData` 传整棵对象。请求层统一注入业务 Token、超时和 trace_id，但登录刷新要单航班执行，防止多个 401 同时换 Token 并互相覆盖。

登录链路是：客户端调用 `wx.login` 获取一次性 code → 服务端向平台换取会话信息 → 服务端绑定自身用户并签发业务会话。code 只能短期使用，服务端记录已消费状态；客户端不接触 app secret，也不能把 openid 直接当登录凭证。

## 发布与故障定位

开发工具通过不代表真机可用。验收覆盖最低支持基础库、弱网、拒绝授权、后台恢复、分包首次加载和隐私弹窗。若开发工具正常而真机 API 不存在，检查基础库和机型；若首屏慢，查看主包体积、分包边界和 `setData` 体积；若偶发串号，检查 code 重放、缓存账号和服务端会话绑定。
