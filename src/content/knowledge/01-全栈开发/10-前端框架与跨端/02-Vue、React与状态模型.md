# 前端框架与跨端（02） - Vue、React 与状态模型

> 读完你能：比较 Vue 响应式追踪与 React 状态快照，并为本地、共享和服务端状态选择边界。

## 核心知识清单

- Vue Proxy 响应式、ref、computed 与 watch
- React 状态快照、单向数据流与 Hooks
- 组件身份、Key 与状态保留
- 派生状态、Effect 与副作用边界
- 本地状态、共享状态与服务端缓存
- 可测试组合逻辑与组件契约

## 两种心智模型

Vue 追踪响应式读取并在依赖变化时更新；React 每次渲染得到一个状态快照，通过新状态触发下一次渲染。两者都要求渲染逻辑纯净，网络、订阅和 DOM 集成放入明确生命周期。能从 props 或查询结果计算的值不要复制进 state。

列表 Key 表示业务身份，不是消除警告的序号；身份变化会重建组件状态。服务端数据应交给查询缓存处理新鲜度、去重和重试，避免复制到全局客户端 Store 后出现双源真相。

## 状态归属决策

输入框展开状态等只影响单组件的值留在本地；跨远距离组件但生命周期与页面一致的状态放到最近共同祖先或受控上下文；来自服务端的数据交给查询缓存，用 query key 表达参数和身份；URL 可表达筛选、分页和可分享视图。只有真正跨页面、客户端拥有且需要统一更新的数据才进入全局 Store。

请求结果复制进 Store 后又由查询库刷新，会产生两个更新时间和错误状态。定位“界面偶尔回退”时检查是否同时存在 props、local state 和 store 三份副本。修复方式是确认唯一所有者，其余值按需派生。Effect 循环则检查依赖项是否每次渲染创建新对象，以及 Effect 是否在同步可计算状态。

## 组件契约与验收

以输入、输出事件和可见状态测试组件，不断言框架内部响应式次数。列表重排用稳定业务 Key 验证输入焦点和草稿不会串行；服务端缓存测试过期、取消、失败重试和用户切换后是否清理带身份的数据。
