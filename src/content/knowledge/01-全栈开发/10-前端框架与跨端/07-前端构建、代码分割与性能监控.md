# 前端框架与跨端（07） - 前端构建、代码分割与性能监控

> 构建工具的目标不是“能打包”，而是建立可重复依赖、快速反馈、稳定缓存和可诊断的生产产物。

> 读完你能：解释 Vite、Webpack、Workspace 和增量构建，并通过代码分割、缓存与真实用户监控优化性能。

## 核心知识清单

- Node.js、package.json、依赖分类与锁文件
- Vite 开发服务、生产构建与插件
- Webpack Entry、Loader、Plugin 与 Chunk
- ESM、Tree Shaking 与动态 import
- Monorepo、Workspace 与 Turborepo 增量任务
- 文件哈希、长期缓存与 Source Map
- Core Web Vitals、前端错误与 trace_id

## 可重复依赖

运行时依赖进入 dependencies，构建和测试工具进入 devDependencies；库项目再考虑 peerDependencies。CI 使用锁文件和严格安装，Node 与包管理器版本也要固定。只提交 package.json 而忽略锁文件会让不同机器解析出不同依赖图。

## Vite 与 Webpack

Vite 开发期利用原生 ESM 按需转换，生产仍进行打包优化。Webpack 从 Entry 构建依赖图，Loader 转换模块，Plugin 介入构建生命周期。选择取决于框架、插件生态、存量配置和性能，不应仅按“新旧”判断。

## 分包和缓存

路由和低频重组件使用动态 `import()`；共享依赖分包要避免生成过多小 Chunk。静态资源文件名包含内容哈希并设置长期缓存，HTML 使用短缓存或不缓存。发布时必须保证 HTML 与 Chunk 原子可用，旧页面请求旧 Chunk 时仍有回退策略。

## Monorepo 与任务缓存

Workspace 统一依赖和本地包链接，Turborepo 等工具根据输入、环境和依赖计算任务缓存。缓存键遗漏环境变量或生成文件会产生错误复用；CI 应验证缓存命中和未命中都能正确构建。

## 性能监控

实验室 Lighthouse 不能代表真实用户。生产采集 LCP、INP、CLS、资源错误和 JS 异常，并关联版本、路由和 trace_id。Source Map 上传到受控错误平台，不公开部署包含源码的映射文件。
