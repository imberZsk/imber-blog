# 二、发布证据链与责任边界

一次发布记录需求/变更、commit、评审、测试、制品 digest、SBOM、配置、迁移、审批、操作者、时间和环境。
审计不是截图堆积，关键对象使用稳定 ID 互相链接，并确保人工和自动动作都可追溯。

# 三、时间线、影响与因果分析

复盘用统一时区构建发现前、触发、扩大、止损和恢复时间线，
区分直接触发条件、系统性促成因素与恢复障碍。
避免把最后一个错误或个人操作等同根因，
使用日志、Trace、配置 diff 和发布记录支撑结论。

# 四、行动项、Owner 与闭环验证

行动项必须具体、可验收、有负责人和期限，优先减少同类故障概率或缩短发现恢复时间。
修复进入测试、监控、Runbook 或架构约束，并通过演练验证；
只写“加强意识”“以后注意”不算闭环。

# 十一、总结

- **发布证据链与责任边界**：审计不是截图堆积，关键对象使用稳定 ID 互相链接，并确保人工和自动动作都可追溯。
- **时间线、影响与因果分析**：避免把最后一个错误或个人操作等同根因，使用日志、Trace、配置 diff 和发布记录支撑结论。
- **行动项、Owner 与闭环验证**：行动项必须具体、可验收、有负责人和期限，优先减少同类故障概率或缩短发现恢复时间。
- **发布审计记录骨架**：记录不包含密钥和原始敏感数据。
