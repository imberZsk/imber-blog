# 二、先建立前端锚点：这就是你写过的「一次性 node 脚本」

前端经常写这种脱离框架的独立脚本——不是 web 服务，跑一次出个结果就完事：

```javascript
// JavaScript：一个典型的一次性数据脚本（node 跑）
import axios from "axios"
import fs from "fs"

async function main() {
  const resp = await axios.get("https://api.example.com/sales")  // 抓
  const rows = resp.data.filter(r => r.amount > 0)               // 洗
  const total = rows.reduce((s, r) => s + r.amount, 0)           // 算
  fs.writeFileSync("report.json", JSON.stringify({ total }))     // 出
}
main()
```

Python 的数据脚本是**同一个心智模型**，只是每一段换了更专业的工具：

| 阶段 | 前端（node） | Python | 本质 |
|------|-------------|--------|------|
| 抓 | `axios` / `fetch` | `requests` | 发 HTTP 请求拿数据 |
| 洗 | `filter` / `map` 手撸 | `pandas` | 整列运算去脏数据 |
| 算 | `reduce` 手撸 | `pandas.groupby` | 分组聚合（像 SQL） |
| 出 | 写文件 / 前端图表库 | `matplotlib` / `to_csv` | 存结果 / 画图 |

**边界（这里和前端不一样）**：node 脚本里抓数据是 `await axios.get(...)`，**默认异步**；Python 的 `requests.get(...)` **默认同步阻塞**——没有 `await`，就是一行卡住直到拿到响应（详见第 17 篇异步篇）。一次性脚本里这反而更省事：不用包 `async function main()`，从上往下顺着写就行。

# 三、用 AI 生成脚本的正确姿势

阶段七的核心不是「自己一行行敲」，而是「**把活儿描述清楚，让 AI 产出初版，你来审查和迭代**」。这跟你让 Copilot/Cursor 写前端组件是一回事，但数据脚本有它特有的注意点。

## 3.1 一个好的 prompt 长什么样

新手最容易写「帮我写个抓数据的脚本」这种含糊需求，AI 只能瞎猜。好 prompt 要把**输入、输出、约束**都钉死，就像你给后端提接口需求一样：

```text
帮我写一个 Python 数据脚本，要求：
1. 用 requests 从 https://api.example.com/sales 抓销售数据（GET，返回 JSON 数组，
   每条形如 {"city": "上海", "amount": 1200, "date": "2026-01-05"}）
2. 用 pandas 清洗：丢掉 amount 为空或 <= 0 的脏数据，date 转成日期类型
3. 按 city 分组，算每个城市的总销售额和订单数，按总额从高到低排序
4. 用 matplotlib 画一张「各城市总销售额」的柱状图，保存成 sales.png（要能正常显示中文）
5. 同时把分组结果导出成 city_report.csv
约束：加 timeout 防止卡死；每个函数加注释；用 if __name__ == "__main__" 作入口
```

> 类比：这就是你给 AI 写前端组件时「props 是什么、渲染成什么样、有哪些边界 case」的那套描述法。**需求越具体，返工越少**——含糊的 prompt 换来的是含糊（且经常跑不起来）的代码。

## 3.2 边界：AI 生成的数据脚本不能盲信

这是本篇最该记住的一条。AI 写数据脚本特别容易在这几处出错，**你必须有能力看懂并验证**，所以下面几节才要把流水线讲透：

- **幻觉 API / 参数**：编出库里根本不存在的函数名或参数（比如 `pd.read_csv` 写个不存在的 kwarg）。
- **中文乱码**：matplotlib 画中文默认显示成方框（第六节专门讲），AI 经常忘了配字体。
- **没有错误处理**：网络请求失败、字段缺失直接崩，AI 默认走「happy path」。
- **数据结构假设错**：它没见过真实返回，常假设的 JSON 结构和实际对不上。

正确姿势：**AI 出初稿 → 你跑一遍 → 报错/结果不对 → 把真实报错和真实数据样例贴回去让它改**。这个「人审 + 喂反馈」的循环，是阶段七实战的真正技能。

# 四、抓数据：requests ≈ axios

`requests` 是 Python 事实上的 HTTP 客户端（第三方库，需要装），用法和 axios 高度对应：

```bash
pip install requests
```

```javascript
// JavaScript（axios）
const resp = await axios.get("https://api.example.com/sales", {
  params: { year: 2026 },                  // 查询参数
  headers: { "User-Agent": "my-script" },  // 请求头
  timeout: 5000,                           // 超时 5 秒
})
const data = resp.data                     // axios 自动帮你 JSON.parse
```

```python
import requests  # HTTP 客户端，pip install requests

# resp：一次 HTTP 响应对象，对应 axios 返回的 resp
resp = requests.get(
    "https://api.example.com/sales",
    params={"year": 2026},                    # params：查询参数，自动拼成 ?year=2026
    headers={"User-Agent": "my-script"},      # headers：请求头，反爬站点常要带 UA
    timeout=5,                                # timeout：超时秒数（注意是秒，不是毫秒！）
)

# raise_for_status：状态码不是 2xx 就主动抛异常（≈ 你在 axios 拦截器里判 resp.status）
# WHY：不写这行的话，404/500 也不会报错，data 会拿到一堆错误页 HTML，后面清洗全乱
resp.raise_for_status()

# data：把响应体当 JSON 解析成 Python 的 list/dict（≈ axios 的 resp.data）
data = resp.json()
```

**几个和前端不同、AI 也常漏的点：**

| 项 | 前端（axios） | Python（requests） |
|----|--------------|-------------------|
| 超时单位 | 毫秒 `5000` | **秒** `5` |
| 拿 JSON | `resp.data`（自动） | `resp.json()`（要调方法） |
| 拿原始文本 | `resp.data` | `resp.text` |
| 状态码 | `resp.status` | `resp.status_code` |
| 非 2xx 报错 | 默认 reject | **默认不报**，要 `raise_for_status()` |
| 查询参数 | `params` | `params`（一样） |

> 边界：requests **默认不会因为 404/500 抛错**，这跟 axios 不一样。所以抓完第一件事就是 `resp.raise_for_status()`，否则脏响应会一路流进后面的清洗环节，最后报一个莫名其妙的错，极难排查。

抓回来的 `data` 是个「字典的列表」（对象数组），直接喂给 pandas 就成了一张表（详见第 21 篇）：

```python
import pandas as pd

# df：把抓回来的对象数组直接变成 DataFrame，每个 dict 一行
df = pd.DataFrame(data)
```

# 五、清洗：pandas 整列操作 ≈ filter/map（但别写 for）

真实抓回来的数据一定有脏的：空值、负数、类型不对。前端你会 `filter` 一遍，pandas 里**对整列下指令**，更快更短（详见第 21 篇）：

```javascript
// JavaScript：循环 + filter 手撸清洗
const clean = data
  .filter(r => r.amount != null && r.amount > 0)  // 去掉空值和非正数
```

```python
# 1. 体检：先看数据有没有缺失，别上来就处理（≈ 先 console.log 看一眼）
print(df.shape)            # (行数, 列数)
print(df.isnull().sum())   # 每列有多少空值，排查数据质量第一句话

# 2. 去空值：只看 amount 列，amount 为空的订单无效，删整行
df = df.dropna(subset=["amount"])

# 3. 类型转换：抓回来 date 经常是字符串，转成真正的日期类型才能按时间分析
#    errors="coerce"：转不动的脏值变成 NaT（缺失），而不是直接报错中断
df["date"] = pd.to_datetime(df["date"], errors="coerce")

# 4. 去掉非正数订单：amount <= 0 是无效数据
#    这里用布尔索引（≈ filter），条件直接写方括号里
df = df[df["amount"] > 0]

# 5. 去重：完全重复的行只留一条（真实数据接口偶尔会吐重复）
df = df.drop_duplicates()
```

> 边界：清洗时**别下意识写 `for` 循环逐行改**。pandas 的灵魂是「对整列一次性运算」，几万行时 for 循环会明显卡。心智从「遍历每个元素」转成「对整列下达一条指令」。

# 六、分析：groupby ≈ SQL 的 GROUP BY

需求是「按城市算总销售额和订单数」，这正是 SQL 的 `GROUP BY`。pandas 写法和 SQL 思路一一对应（详见第 21 篇）：

```sql
-- SQL：你熟悉的写法
SELECT city, SUM(amount) AS total_amount, COUNT(*) AS order_count
FROM sales
GROUP BY city
ORDER BY total_amount DESC;
```

```python
# report：分组聚合结果。groupby("city") 后用 agg 一次算多个指标
# agg 里：新列名=(原列, 聚合方式)，可读性比 SQL 还直白
report = df.groupby("city").agg(
    total_amount=("amount", "sum"),    # total_amount = 该城市 amount 求和
    order_count=("amount", "count"),   # order_count  = 该城市订单条数
).sort_values("total_amount", ascending=False)   # 按总额从高到低排（≈ ORDER BY DESC）

print(report)
#       total_amount  order_count
# city
# 上海          52000           38
# 北京          41000           30
```

# 七、出图：matplotlib ≈ 后端版 ECharts（中文字体是头号坑）

前端画图用 ECharts/D3 给个 `option` 就行，matplotlib 是命令式的：一步步「画 → 配 → 存」（详见第 22 篇）。这里的脚本不弹窗，直接**存成图片文件**交付：

```python
import matplotlib.pyplot as plt   # plt：matplotlib 绘图入口的标准别名

# 关键！否则中文标题、城市名全显示成方框 □□□
# WHY：matplotlib 默认字体不含中文字形，必须手动指定一个系统里有的中文字体
# mac 上常用 "PingFang HK" / "Arial Unicode MS"；Windows 上是 "SimHei"
plt.rcParams["font.sans-serif"] = ["Arial Unicode MS"]  # 指定中文字体
plt.rcParams["axes.unicode_minus"] = False              # 让负号正常显示，别变成方框

# 画柱状图：x 轴是城市名（report 的索引），y 轴是总销售额
plt.figure(figsize=(8, 5))                       # 新建画布，设定宽高（英寸）
plt.bar(report.index, report["total_amount"])    # bar(x, y)：柱状图
plt.title("各城市总销售额")                        # 图标题
plt.xlabel("城市")                                # x 轴标签
plt.ylabel("销售额")                              # y 轴标签

# savefig：把图存成文件，而不是 plt.show() 弹窗（脚本场景一律存文件）
# dpi 控制清晰度，bbox_inches="tight" 自动裁掉多余白边
plt.savefig("sales.png", dpi=150, bbox_inches="tight")
plt.close()   # 关闭画布释放内存（脚本里画多张图时尤其要记得）
```

> 边界：**中文方框问题是 matplotlib 第一坑，AI 生成的代码几乎总会漏掉那两行 `rcParams`**。看到图里中文变 □□□，第一反应就是去配 `font.sans-serif`。字体名要填你**操作系统里真实存在**的，填错了静默回退、依旧是方框。

# 八、把整套串起来：一个完整可运行脚本

下面是 AI 生成、你审查修正后该长成的样子——读 → 洗 → 算 → 出，分成几个带注释的函数，入口用 `if __name__ == "__main__"`（≈ node 脚本里 `main()` 的调用约定）：

```python
import requests                     # HTTP 客户端
import pandas as pd                 # 数据分析
import matplotlib.pyplot as plt     # 绘图

# API 地址：抓销售数据的接口（实际项目里建议从配置/环境变量读，别硬编码）
API_URL = "https://api.example.com/sales"


def fetch_data(url: str) -> pd.DataFrame:
    """抓数据：发 GET 请求并转成 DataFrame。
    参数 url：数据接口地址。
    返回：原始数据组成的 DataFrame。
    """
    # resp：HTTP 响应；timeout=10 防止网络卡死整个脚本
    resp = requests.get(url, timeout=10, headers={"User-Agent": "data-script"})
    resp.raise_for_status()             # 非 2xx 主动抛错，避免脏响应流入后续
    return pd.DataFrame(resp.json())    # resp.json() 是对象数组，直接建表


def clean_data(df: pd.DataFrame) -> pd.DataFrame:
    """清洗数据：去空值、转类型、去非正数和重复。
    参数 df：原始 DataFrame。
    返回：清洗后的 DataFrame。
    """
    df = df.dropna(subset=["amount"])                            # amount 为空的删掉
    df["date"] = pd.to_datetime(df["date"], errors="coerce")     # date 转日期，脏值变 NaT
    df = df[df["amount"] > 0]                                    # 只留正数金额
    return df.drop_duplicates()                                  # 去掉完全重复行


def analyze(df: pd.DataFrame) -> pd.DataFrame:
    """分析数据：按城市聚合总销售额和订单数，按总额降序。
    参数 df：清洗后的 DataFrame。
    返回：分组聚合结果。
    """
    return df.groupby("city").agg(
        total_amount=("amount", "sum"),     # 各城市总销售额
        order_count=("amount", "count"),    # 各城市订单数
    ).sort_values("total_amount", ascending=False)


def plot(report: pd.DataFrame, out_path: str) -> None:
    """出图：把聚合结果画成柱状图并保存。
    参数 report：分组聚合结果；out_path：图片保存路径。
    """
    # 配中文字体，否则中文显示成方框（见第六节）
    plt.rcParams["font.sans-serif"] = ["Arial Unicode MS"]
    plt.rcParams["axes.unicode_minus"] = False
    plt.figure(figsize=(8, 5))
    plt.bar(report.index, report["total_amount"])
    plt.title("各城市总销售额")
    plt.xlabel("城市")
    plt.ylabel("销售额")
    plt.savefig(out_path, dpi=150, bbox_inches="tight")
    plt.close()


# 脚本入口：≈ node 里调 main()。被别的文件 import 时这段不会执行
if __name__ == "__main__":
    raw = fetch_data(API_URL)              # raw：抓回来的原始表
    df = clean_data(raw)                   # df：清洗后的表
    report = analyze(df)                   # report：分析结果
    report.to_csv("city_report.csv")       # 导出 CSV 交付（保留 city 索引）
    plot(report, "sales.png")              # 画图保存
    print(report)                          # 终端也打印一份，方便即时确认
```

跑它：

```bash
python sales_script.py
```

跑完你会得到一个 `city_report.csv` 和一张 `sales.png`。这就是阶段七的一个最小但完整的交付物。

# 九、AI 生成代码的审查清单

把这个清单当成「拿到 AI 数据脚本后必过一遍」的 checklist，能挡掉八成翻车：

| 检查项 | 为什么 |
|--------|--------|
| 有没有 `timeout` | 没有会因网络卡死整个脚本 |
| 有没有 `raise_for_status()` | requests 默认不报 4xx/5xx，脏响应会污染后续 |
| 引用的字段名和真实数据对得上吗 | AI 没见过真实返回，常假设错字段 |
| matplotlib 配中文字体了吗 | 没配中文就是方框 □□□ |
| 库的 API / 参数真实存在吗 | AI 会幻觉出不存在的函数或参数 |
| 空值/异常有没有兜底 | AI 默认只写顺利路径 |
| 出图用 `savefig` 而非 `show` | 脚本场景要存文件，不是弹窗 |

> 核心心态：**AI 是高效的初稿生成器，不是免检的交付者**。前面几节把流水线讲透，就是为了让你有能力当这个「审稿人」——看得懂、跑得通、改得动。

# 十、总结

「抓 → 洗 → 算 → 出」这条数据流水线，本质就是你写过无数遍的一次性 node 脚本，只是 `axios → requests`、`filter/reduce → pandas`、`前端图表库 → matplotlib`。阶段七的新技能是把这条线**交给 AI 生成**：用具体的 prompt 钉死输入输出和约束，再用「跑一遍 + 喂真实报错」的循环迭代，最后靠你对每段的理解做审查把关。

✅ **该掌握**
- 流水线四段各自对应的库：`requests`（抓）/ `pandas`（洗+算）/ `matplotlib`（出）。
- `requests.get(url, params=, headers=, timeout=)` + `raise_for_status()` + `resp.json()` 的标准抓取套路。
- 清洗三件套 `dropna` / `to_datetime` / 布尔索引，分析靠 `groupby().agg()`。
- 出图存文件用 `savefig`，画中文先配 `rcParams["font.sans-serif"]`。
- 写 prompt 让 AI 生成脚本：把输入、输出、约束都写具体。

⚠️ **易混淆（前端最容易栽的坑）**
- **`requests` 超时单位是秒**，不是 axios 的毫秒；拿 JSON 要 `resp.json()` 调方法。
- **requests 默认不报 4xx/5xx**，必须 `raise_for_status()`，否则脏响应静默流入。
- **matplotlib 中文默认是方框**，要手动配中文字体，且字体名得是系统真实存在的。
- **脚本里用 `savefig` 存图**，别用 `show()` 弹窗。
- **AI 生成的数据脚本必须审查**：幻觉 API、字段假设错、缺错误处理是高频翻车点。
