# 数据与安全（02） - 关系型数据库、索引与事务

> 关系型数据库的价值不只是 SQL，而是用约束和事务把业务不变量放到并发环境中仍然守住。

## 学习目标

- 用约束表达唯一性、引用完整性和业务不变量。
- 根据查询模式设计联合索引并用执行计划验证收益。
- 在并发、重试和迁移场景下选择事务与一致性策略。

## 一、先写业务不变量

订单号唯一、库存不能为负、子记录必须属于有效父记录，这些应优先由主键、唯一约束、外键和检查约束表达。应用校验改善错误提示，但无法单独阻止两个并发请求同时越过检查。

## 二、索引服务查询，不服务字段

```sql
-- 查询模式：租户内按状态筛选，再按创建时间倒序翻页。
CREATE INDEX idx_orders_tenant_status_created
ON orders (tenant_id, status, created_at DESC, id DESC);
```

联合索引顺序来自过滤、排序和范围条件。使用 `EXPLAIN ANALYZE` 检查实际行数、扫描方式和排序开销；不要因为字段“常用”就单列建索引。索引提高读取，也增加写放大和磁盘占用。

## 三、事务与并发

事务保证一组操作原子提交，但隔离级别决定并发可见性。涉及余额、库存等竞争资源时，选择条件更新、悲观锁或乐观版本，而不是“先查再写”裸奔。

```sql
UPDATE inventory
SET available = available - 1
WHERE sku_id = :sku_id AND available > 0;
```

应用必须检查受影响行数；0 表示库存不足或条件不满足。重试事务时要限制次数、加入退避，并确保外部副作用不会重复执行。

## 四、分页与迁移

- 深分页优先使用基于稳定排序键的游标，不用越来越慢的巨大 OFFSET。
- Schema 迁移采用“扩展 -> 双写/回填 -> 切读 -> 收缩”，避免代码与表结构瞬时不兼容。
- 数据库连接池按实例、并发和数据库上限共同规划；池越大不一定越快。

## 五、生产排障

按慢查询日志 -> 执行计划 -> 锁等待 -> 连接池 -> 业务调用链定位。优化前保存真实参数和基线，不要只在空测试库运行 SQL。
