# 数据与安全（03） - 缓存、搜索、文档库与对象存储选型

> 先确定主数据和访问模式，再引入 Redis、Elasticsearch、MongoDB 或对象存储；它们通常是协作关系，不是互相替代。

## 学习目标

- 按事务、检索、缓存、文档和文件访问模式选择存储。
- 设计 Cache Aside、索引同步和最终一致性恢复流程。
- 为对象存储上传、下载、版本和权限建立安全契约。

## 一、选型矩阵

| 系统 | 强项 | 不能默认承担 |
| --- | --- | --- |
| 关系型数据库 | 事务、约束、关联查询 | 大规模全文相关性检索 |
| Redis | 低延迟缓存、计数、短期状态 | 无边界永久主数据 |
| Elasticsearch | 倒排、分词、相关性、聚合 | 强事务事实来源 |
| MongoDB | 文档聚合模型、灵活 Schema | 任意跨文档强关联 |
| 对象存储 | 大文件、版本、生命周期 | 复杂字段查询与事务 |

## 二、Cache Aside 的一致性

读取先查缓存，未命中查主库并回填；写入先提交主库，再删除缓存。需要为热点穿透设置空值短 TTL，为击穿使用请求合并或互斥重建，并为雪崩加入过期抖动。分布式锁不是数据库事务替代品，锁必须有租约、所有者标识和安全释放。

## 三、搜索索引同步

主库提交后通过 Outbox/CDC 异步更新 Elasticsearch。事件携带实体版本，消费者幂等处理；定期对账发现漏事件，并通过 Alias 切换完成零停机重建。读者应接受“搜索短暂最终一致”，但详情页回主库确认关键状态。

## 四、对象存储安全

数据库只保存对象键、租户、哈希、大小、媒体类型和状态。上传使用短期预签名 URL，并在完成后校验大小、类型、哈希和恶意内容。对象键不能由用户任意拼路径；下载同样先做资源权限校验。

## 五、验收

- Redis 故障时主链路有受控降级，不出现缓存风暴。
- 搜索事件重复、乱序和丢失均可检测、幂等或重放。
- 对象上传未完成、越权读取和伪造 Content-Type 都会被拒绝。
