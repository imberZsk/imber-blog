# 二、窗口是有生命周期的资源

多窗口应用不能只保存一个全局变量。
每类窗口要定义唯一性、父子关系、关闭语义和恢复策略：设置窗口通常只允许一个实例，
重复打开应聚焦；
编辑窗口可按文档 ID 复用；
模态窗口需要 `parent` 与 `modal`；
后台任务不应依赖隐藏窗口存活。

`ready-to-show` 可减少白屏，但复杂页面还要提供应用内骨架。
窗口外部链接应由 `setWindowOpenHandler` 拦截，
可信 HTTPS 域名才交给系统浏览器；
未知协议和站内导航必须拒绝。

```ts
import { BrowserWindow, shell } from 'electron'

/** 按业务键保存仍然存活的窗口。 */
const windowsByKey = new Map<string, BrowserWindow>()

/** 获取现有窗口或创建一个新的业务窗口。 */
export function openWorkspaceWindow(workspaceId: string): BrowserWindow {
  /** 当前工作区已经存在的窗口。 */
  const existingWindow = windowsByKey.get(workspaceId)

  if (existingWindow && !existingWindow.isDestroyed()) {
    existingWindow.focus()
    return existingWindow
  }

  /** 新创建的工作区窗口。 */
  const workspaceWindow = new BrowserWindow({ width: 1100, height: 760, show: false })
  windowsByKey.set(workspaceId, workspaceWindow)

  workspaceWindow.once('ready-to-show', () => workspaceWindow.show())
  workspaceWindow.once('closed', () => windowsByKey.delete(workspaceId))
  workspaceWindow.webContents.setWindowOpenHandler(({ url }) => {
    /** 页面请求打开的目标 URL。 */
    const targetUrl = new URL(url)
    if (targetUrl.protocol === 'https:' && targetUrl.hostname === 'docs.example.com') {
      void shell.openExternal(targetUrl.toString())
    }
    return { action: 'deny' }
  })

  void workspaceWindow.loadFile('index.html')
  return workspaceWindow
}
```

# 三、菜单是命令入口，不是静态装饰

菜单项应调用统一 command 层，键盘快捷键、应用菜单和右键菜单复用相同授权与状态判断。
macOS 第一项是应用菜单并保留 About、Services、Hide、Quit 等平台角色；
Windows/Linux 通常从 File 开始。
优先使用 Electron `role`，它能提供正确标签、快捷键和原生行为。

菜单的 enabled/checked 状态来自当前聚焦窗口和文档状态。
不要在模板创建时把状态永久写死；
窗口切换、选区变化或权限变化后要重新同步。
全局快捷键会占用系统按键，注册失败必须可观测，并在退出时注销。

# 四、系统能力统一走授权层

通知、托盘、剪贴板、文件对话框、协议注册和电源事件都属于系统副作用。
页面只表达业务意图，
例如“复制分享链接”，
主进程负责校验内容、记录审计并调用 `clipboard.writeText`。
敏感剪贴板内容可设置过期清理，但不能假设一定能覆盖用户后续复制的数据。

托盘常驻会改变“关闭窗口”等于“退出应用”的预期，需要在首次关闭时明确提示。
通知要处理权限、点击回调和重复去重；
深链接协议要校验来源和参数，单实例锁确保链接不会被多个进程同时消费。

# 五、失败边界与验收

- 窗口 Map 不在 `closed` 清理会产生悬挂引用和错误复用。
- 无限制创建窗口会消耗大量内存，应按业务键去重并设数量上限。
- 菜单命令直接操作当前窗口但未检查空值，在应用激活但无窗口时会异常。
- `shell.openExternal` 接受任意协议可能触发危险本地处理器，必须使用 allowlist。
- 开发环境正常的快捷键可能与目标操作系统冲突，需要真实平台验收。

验收矩阵应覆盖首次打开、重复打开、最小化、关闭、重新激活、多显示器和系统休眠恢复。
菜单需要键盘与鼠标两条路径，
系统能力则检查拒绝权限、无默认应用和 API 调用失败时是否有明确降级。

# 十、总结

- **窗口是有生命周期的资源**：多窗口应用不能只保存一个全局变量。
- **菜单是命令入口，不是静态装饰**：macOS 第一项是应用菜单并保留 About、Services、Hide、Quit 等平台角色；
- **系统能力统一走授权层**：页面只表达业务意图，例如“复制分享链接”，主进程负责校验内容、记录审计并调用 clipboard.writeText。
- **失败边界与验收**：shell.openExternal 接受任意协议可能触发危险本地处理器，必须使用 allowlist。
