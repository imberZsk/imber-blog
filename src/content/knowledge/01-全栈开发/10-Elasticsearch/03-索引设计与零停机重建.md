# 二、索引边界来自数据生命周期

索引应围绕 Mapping、访问模式、权限和生命周期形成稳定边界。
日志和时序数据适合 Data Stream 与滚动策略；
业务搜索常使用版本索引加读写 Alias；
不同租户是否独立索引要权衡隔离、字段差异和分片数量，不能每个小租户都创建大量空分片。

主分片数在索引创建后不能直接修改。
分片过大影响恢复和迁移，
分片过小但数量过多会增加 Cluster State、文件句柄和协调开销。
容量规划同时估算原始数据、索引膨胀、副本、段合并临时空间和未来增长。

# 三、Alias 驱动的发布流程

```json
PUT product_search_v2
{
  "aliases": {
    "product_search_write": { "is_write_index": true }
  },
  "mappings": { "dynamic": "strict", "properties": {} }
}
```

推荐流程：创建 `v2` 并应用 Mapping/Settings；
从权威数据源全量回填；
记录回填期间增量变更；
校验文档数、抽样摘要、权限和查询质量；
在单次 `_aliases` 请求中把读 Alias 从 `v1` 切到 `v2`；
观察后再停止旧索引写入和删除。

Alias 切换是原子的，但全量回填与增量同步不是。
可以使用双写、CDC 或带水位的增量补偿，必须处理重复和乱序。
文档 ID 稳定可让重复 Upsert 收敛；
删除事件也必须传播，否则新索引会留下幽灵数据。

# 四、批量写入与资源控制

Bulk 请求按字节和处理时间控制，而不是盲目固定一万条。
重建期间可临时调大 Refresh Interval、减少副本以提高吞吐，
但切流前必须恢复生产设置并等待索引健康。
并发过高会触发拒绝、段合并和磁盘压力，
应根据节点 CPU、Heap、磁盘吞吐与 Merge 速率动态限速。

重建任务要保存源快照、水位、成功/失败计数和可重入 Checkpoint。
失败批次进入死信并可修复重放，不能只打印日志后继续切流。

# 五、失败与回滚边界

切换后若相关性、错误率或延迟退化，应在旧索引仍保留且增量可追赶时切回 Alias。
若写入已只进入新索引，回滚前要把新产生的变更同步回旧索引。
删除旧索引的门槛应包含完整业务周期、备份和回滚窗口。

常见事故包括 Alias 同时指向两个写索引、重建遗漏删除事件、动态 Mapping 漂移、磁盘水位触发只读、分片恢复占满网络。
Runbook 必须给出检查命令、停止条件和负责人。

## 验收清单

- 分片数、分片目标大小、副本和保留周期有容量依据。
- 全量与增量数据以稳定 ID 收敛，删除传播经过验证。
- Alias 切换前后文档数、权限、搜索质量和 P99 均通过门禁。
- 旧索引在回滚窗口内保留，回切路径已演练。

# 十、总结

- **索引边界来自数据生命周期**：索引应围绕 Mapping、访问模式、权限和生命周期形成稳定边界。
- **Alias 驱动的发布流程**：Alias 切换是原子的，但全量回填与增量同步不是。
- **批量写入与资源控制**：Bulk 请求按字节和处理时间控制，而不是盲目固定一万条。
- **失败与回滚边界**：若写入已只进入新索引，回滚前要把新产生的变更同步回旧索引。
