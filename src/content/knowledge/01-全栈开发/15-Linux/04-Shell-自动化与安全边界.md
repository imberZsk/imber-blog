# 二、退出状态、管道与错误传播

Shell 以命令退出码表达成功失败，管道默认只返回最后一个命令状态。
set -Eeuo pipefail 能暴露未定义变量和中间失败，但不能替代显式错误处理；
预期可失败的探测命令应在 if 中判断，不能用全局忽略错误。

# 三、参数、引用与临时资源

所有外部输入都要作为独立参数传递并使用双引号，禁止 eval 拼接命令。
临时目录用 mktemp 创建，trap 在 EXIT 中清理；
破坏性操作先把目标解析为绝对、非空且位于允许根目录的路径，再执行最小范围变更。

# 四、幂等、Secret 与静态检查

自动化脚本应重复执行得到同一状态，写文件采用临时文件加原子替换，远程调用设置超时和有限重试。
Secret 从环境或密钥服务读取，不使用 set -x 输出；
ShellCheck、测试夹具和 dry-run 都进入 CI。

# 五、安全的配置发布骨架

示例验证目标目录并用原子替换发布配置。

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
readonly target_dir='/srv/app/config'
readonly source_file="${1:?usage: deploy-config FILE}"
[[ -f "$source_file" ]] || { echo 'source missing' >&2; exit 2; }
readonly temp_file="$(mktemp "$target_dir/.config.XXXXXX")"
trap 'rm -f "$temp_file"' EXIT
install -m 0640 "$source_file" "$temp_file"
mv -f "$temp_file" "$target_dir/app.yml"
```

固定目标根目录避免变量展开到意外位置。
真实发布还应校验配置语法、保留旧版本并在替换后执行健康检查。
