# 二、inode、路径与权限检查顺序

目录项把文件名映射到 inode，
权限检查同时受进程有效 UID/GID、所有者位、组位、其他位及 ACL 影响。
目录的 x 表示可穿越而不是可执行文件；
排查 Permission denied 要逐级检查父目录、符号链接和挂载选项，
不能只看目标文件。

# 三、进程、信号与文件描述符

进程通过 PID、父子关系、环境和打开的文件描述符使用资源。
SIGTERM 允许应用优雅退出，SIGKILL 无法捕获且可能留下半写数据；
先用 ps、pstree、lsof 和 /proc 证明进程状态，再决定发送信号或调整服务。

# 四、最小权限与审计边界

服务应使用专用非登录用户，只授予工作目录和必需设备权限；
sudo 规则精确到命令并记录审计。
setuid、Linux capabilities 和 ACL 能减少 root 使用，
但仍需验证继承、容器映射和备份恢复后的权限是否一致。

# 五、权限与进程证据命令

下面的命令从路径、身份到文件描述符逐层取证。

```bash
namei -l /srv/app/config.yml
stat -c '%U %G %a %n' /srv/app/config.yml
id appuser
ps -o pid,ppid,user,stat,etime,cmd -C node
lsof -p 1234 | head
```

修改权限前保存输出。
chown 通常比 chmod 777 更接近根因；
终止服务前确认 PID 属于目标版本并先发送 SIGTERM。

| 现象 | 常见根因 | 验证与处理 |
| --- | --- | --- |
| 文件是 644 仍 Permission denied | 父目录无 x、ACL 拒绝或只读挂载 | 使用 namei、getfacl 和 mount 逐层验证 |
