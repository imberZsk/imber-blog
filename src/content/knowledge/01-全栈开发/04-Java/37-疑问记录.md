# Java（37） - 疑问记录

> 读完后，你应能区分 Java 源码、字节码与类名入口，正确组合 `javac` 和 `java`，并定位后缀、类名、工作目录导致的启动失败。

## Q1: 怎么执行一个 Java 文件？（已解决 2026/06/14）

Java 8 分两步：**先编译，再运行**。

### 编译与运行链路

`javac` 把 `.java` 源码编译为 JVM 可加载的 `.class` 字节码；`java` 接收的是类名，由类加载器定位字节码并调用 `main` 入口。编译失败时不会产生可信的字节码，因此组合命令应使用 `&&`，避免继续运行旧的 `.class` 文件造成误判。

排障时先确认 `javac` 的退出码和 `.class` 更新时间，再检查当前工作目录、包名与类路径。看到 `Could not find or load main class` 时，应优先检查类名和 classpath，而不是重新安装 JDK。

```bash
# 第一步：编译，.java 源码 → .class 字节码
javac -encoding UTF-8 HelloWorld.java

# 第二步：运行，java 后面跟「类名」，不带 .java 后缀
java HelloWorld

# 一行搞定（日常推荐，&& 表示前一步成功才跑后一步）
javac -encoding UTF-8 HelloWorld.java && java HelloWorld
```

### 三个易错点

1. `java` 后面是「类名」不是文件名：✅ `java HelloWorld`　❌ `java HelloWorld.java`
2. 类名必须和文件名完全一致（含大小写）：`public class HelloWorld` → `HelloWorld.java`
3. 中文乱码就加 `-encoding UTF-8`

### 和 JavaScript 的执行模型对比

| | 前端 JS | Java |
|---|---|---|
| 运行 | `node app.js`（直接跑） | `javac` 编译 + `java` 运行（两步） |
| 中间产物 | 无 | `.class` 字节码 |
| 执行者 | V8 引擎 | JVM 虚拟机 |

> 为什么多一步：Java 是「编译型 + 虚拟机」语言，javac 把代码变成 JVM 能懂的字节码，再由 JVM 跨平台执行 —— 这就是「一次编译，到处运行」。

Node.js 通常直接读取脚本文件，Java 命令则从 classpath 按全限定类名加载字节码。两者的入口参数不同，因此不能把 `node app.js` 的文件路径心智直接套到 `java HelloWorld` 上。
