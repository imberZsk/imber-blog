# Web 基础（04） - 浏览器事件、存储、性能与安全

> 用浏览器运行机制解释“为什么页面卡、事件顺序错、状态丢失或被攻击”，而不是背 API 名称。

## 学习目标

- 解释事件传播、微任务、任务队列与渲染之间的关系。
- 按数据生命周期选择 Cookie、Storage、IndexedDB 和 Service Worker。
- 用 Web Vitals、Performance 和安全边界定位真实问题。

## 一、事件与任务队列

事件先捕获、到达目标、再冒泡。列表类 UI 使用事件委托时，应从 `event.target` 向上找可信目标，不能假设点击的一定是按钮本身。

```javascript
/** 承载动态按钮的列表容器。 */
const list = document.querySelector('#list')
list.addEventListener('click', (event) => {
  /** 与当前点击最近且声明了动作的按钮。 */
  const button = event.target.closest('button[data-action]')
  if (!button || !list.contains(button)) return
  console.log(button.dataset.action)
})
```

Promise 回调进入微任务队列，计时器进入任务队列；一次长时间同步计算会同时阻塞渲染、输入和计时器。CPU 重任务应切片或交给 Web Worker。

## 二、存储选型

| 存储 | 适合 | 不适合 |
| --- | --- | --- |
| Cookie | 服务端会话标识，配合 HttpOnly/Secure/SameSite | 大对象、可被脚本读取的敏感令牌 |
| sessionStorage | 当前标签页临时 UI 状态 | 跨标签共享或长期数据 |
| localStorage | 少量非敏感偏好 | 凭据、大数据、并发事务 |
| IndexedDB | 离线结构化数据和较大缓存 | 简单一次性键值 |

缓存必须带版本、过期和清理策略。浏览器存储是用户设备上的不可信副本，不能作为权限事实来源。

## 三、渲染性能

浏览器经历样式计算、布局、绘制与合成。频繁交替读取布局属性和写样式会触发布局抖动；优先批量读取、批量写入，并用 Performance 面板确认 Long Task。核心指标关注 LCP、INP、CLS，而不是只看本地首屏“感觉很快”。

## 四、安全边界

- 不可信内容用 `textContent`；确需 HTML 时使用经过审计的消毒器。
- Cookie 会话请求需要 SameSite 与 CSRF 防护；跨域开放按明确 Origin、方法和 Header 配置。
- `postMessage`、WebSocket 消息和 Service Worker 响应都要校验来源与 Schema。
- 前端权限控制只用于界面体验，服务端必须再次鉴权。

## 五、排障清单

1. Performance 找长任务和重复布局。
2. Memory 检查未释放监听器、计时器和闭包引用。
3. Application 检查缓存版本、Service Worker 和存储内容。
4. 使用弱网、后台标签页、刷新和多标签并发复现生命周期问题。
