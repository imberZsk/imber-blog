# 业务链路（04） - 缓存、全文搜索与数据同步

> Redis 和 Elasticsearch 都是派生数据系统。主库、缓存和搜索索引必须有清晰的事实来源、更新顺序和失败修复机制。

> 读完你能：实现 Cache-Aside、缓存防护、索引同步和权限过滤，并处理旧数据、重建与回滚。

## 核心知识清单

- Cache-Aside、TTL 与主动失效
- 缓存穿透、击穿、雪崩与热点 Key
- 版本化缓存键与权限作用域
- Elasticsearch Mapping、分词与 Alias
- CDC/Outbox 索引同步与幂等更新
- 全量重建、双写校验与切换回滚
- 查询权限、结果回源与一致性窗口

## 缓存查询

Cache-Aside 先查缓存，未命中回源并写入；更新通常先提交数据库，再删除缓存。TTL 提供最终修复窗口，热点 Key 使用互斥或逻辑过期防击穿，空结果短暂缓存防穿透，过期时间加入抖动防雪崩。

缓存键包含租户、资源版本和影响结果的参数。缓存整页权限结果时尤其要避免不同用户共享越权数据。

## 搜索同步

主库是事实来源，Outbox 或 CDC 将变更投递给索引消费者。消费者按实体 ID 和版本幂等更新，迟到旧事件不能覆盖新文档。查询 ES 得到 ID 后，后端可按当前权限和关键状态回源确认。

Mapping 或分词器变化使用新索引全量重建，运行文档数、抽样内容、查询回归和权限用例后，通过 Alias 原子切换。旧索引保留回滚窗口。
