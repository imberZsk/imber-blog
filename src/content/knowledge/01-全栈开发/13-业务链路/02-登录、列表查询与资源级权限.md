# 业务链路（02） - 登录、列表查询与资源级权限

> 登录只是获得身份，列表查询还必须把租户、角色和资源权限落实到后端查询条件。

> 读完你能：实现微信/OIDC 登录、账号绑定、分页查询和资源级授权，并避免前端筛选造成越权。

## 核心知识清单

- 微信登录 Code、服务端换取身份与账号绑定
- OIDC Authorization Code + PKCE
- Session、短期 Token 与刷新边界
- 查询参数、游标/偏移分页与稳定排序
- tenant_id、owner_id、RBAC 与 ABAC
- 字段级脱敏与导出权限
- 审计、限流与异常登录

## 登录链路

客户端取得一次性 Code 后交给后端，后端调用身份提供方换取稳定外部标识，再与内部用户绑定。客户端不能把外部返回的 user_id 自报给后端。首次绑定、换绑和注销都要防止账号接管，并记录审计。

Web OIDC 使用 Authorization Code + PKCE，回调校验 state、nonce、issuer 和 audience。后端创建 Session 或签发短期访问令牌，刷新凭据采用旋转和撤销机制。

## 列表查询

接口明确过滤、排序和分页字段，稳定排序包含唯一键。大表深分页优先游标，游标绑定排序条件和权限作用域。数据库查询直接加入 tenant_id、资源所有者或权限关系，而不是查出全部数据后由前端隐藏。

字段级授权在序列化前执行，手机号、证件号和成本等敏感字段按权限脱敏。导出通常风险更高，需要独立权限、数量限制和审计。
