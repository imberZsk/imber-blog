# 二、Secret 与短期联合身份

长期云密钥泄露后的影响持续存在，
优先用 OIDC 与云角色交换短期凭据，
并限制 issuer、audience、仓库、分支和 Environment 条件。
Secret 只在需要的 Job 注入，日志脱敏不能防止恶意代码主动外传。

# 三、Environment、审批与最小权限

生产 Environment 配置审批人、允许分支、等待规则和环境 Secret，
部署 Job 使用独立身份。
工作流 Token 顶层只读，再按 Job 增加 packages 或 id-token；
Fork PR、依赖机器人和外部贡献不进入生产信任域。

# 四、依赖、Action 与制品供应链

第三方 Action 固定 commit SHA，
依赖锁定并扫描许可证与漏洞，
构建生成 provenance、SBOM 和签名。
部署验证制品签名及构建身份；
发生泄露时撤销会话、轮换密钥、下线 Runner 并审计历史 Job。

# 五、OIDC 最小权限 Job

Job 只申请读取源码和签发 OIDC Token 的权限。

```yaml
jobs:
  deploy:
    environment: production
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: cloud-provider/login@COMMIT_SHA
      - run: ./verify-signature-and-deploy.sh "$IMAGE_DIGEST"
```

云端信任策略必须绑定具体仓库、受保护 ref 和 audience；
仅在工作流里写 role 名称并不能形成权限隔离。
