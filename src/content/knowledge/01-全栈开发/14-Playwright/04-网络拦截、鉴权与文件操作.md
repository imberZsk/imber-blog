# 二、Route、Response 与网络证据

page.route 可以继续、修改、中止或 fulfill 请求，适合隔离不稳定第三方依赖；
page.waitForResponse 用于观察真实后端结果。
过度 Mock 会让前端契约与生产漂移，因此关键链路至少保留一组真实服务端集成测试。

# 三、鉴权状态的生成与隔离

推荐 setup project 登录一次并保存 storageState，
依赖 project 再加载它。
状态文件等同会话凭据，应加入 .gitignore、限制文件权限并设置短期测试账号；
角色不同或会修改服务端状态时，不应共用同一账号。

# 四、上传、下载与文件安全

上传应使用 setInputFiles 并覆盖 MIME、大小和恶意扩展名边界；
下载要先注册 download 事件再触发动作。
验收不仅检查文件名，还应读取保存后的字节、哈希或解析结果，并确认未授权角色无法访问下载地址。

# 五、拦截与下载验证

示例只 Mock 第三方汇率，并保留订单接口真实调用。

```typescript
await page.route('**/third-party/rates', async (route) => {
  await route.fulfill({ status: 200, contentType: 'application/json', body: JSON.stringify({ CNY: 1 }) })
})
const downloadPromise = page.waitForEvent('download')
await page.getByRole('button', { name: '导出' }).click()
const download = await downloadPromise
await download.saveAs(testInfo.outputPath(download.suggestedFilename()))
expect(await download.failure()).toBeNull()
```

下载写入 testInfo.outputPath 可随测试制品归档；
敏感导出还要验证响应头、审计记录和越权访问。

- **拦截与下载验证**：敏感导出还要验证响应头、审计记录和越权访问。
