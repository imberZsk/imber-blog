# 二、Cache-Control、验证器与代理缓存键

强缓存由 max-age 和 immutable 控制，
协商缓存使用 ETag 或 Last-Modified。
带内容哈希的静态资源可长期缓存，HTML 应短缓存或重新验证；
代理缓存键必须包含会改变响应的 Host、路径、查询和必要请求头。

# 三、limit_req、突发与排队语义

limit_req 使用共享内存区按键维护漏桶状态，
rate 控制长期速率，
burst 吸收短时突发，
nodelay 决定突发请求立即执行还是排队。
键应使用可信客户端 IP、用户或租户，不能直接信任外部可伪造头。

# 四、私有数据、失效与容量验证

含 Authorization、Cookie 或租户数据的响应默认不进入共享缓存，
除非缓存键和权限模型经过证明。
发布时使用哈希文件名避免手工 purge；
限流用真实并发压测 2xx、429、延迟和上游负载，确认不会形成排队雪崩。

# 五、静态缓存与 API 限流

静态资源长期缓存，登录接口按受信客户端地址限流。

```nginx
limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
location /assets/ {
    expires 1y;
    add_header Cache-Control 'public, max-age=31536000, immutable';
}
location = /api/login {
    limit_req zone=login burst=3 nodelay;
    proxy_pass http://app_backend;
}
location /api/ {
    add_header Cache-Control 'no-store';
    proxy_pass http://app_backend;
}
```

真实系统应在受信代理链解析客户端地址，并让 429 携带可理解的重试提示。
资源文件只有在名称含内容哈希时才适合 immutable。
