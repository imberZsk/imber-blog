# 二、请求匹配、proxy_pass 与 URI 语义

Nginx 先按 server_name 选择虚拟主机，再按 location 规则匹配请求。
proxy_pass 是否带 URI 会影响上游路径替换；
上线前要用带前缀、尾斜杠和编码字符的请求验证，避免接口路径被静默截断。

# 三、上游连接与负载策略

默认轮询适合实例能力相近的无状态服务，
least_conn 适合请求耗时差异较大，
ip_hash 只能提供有限粘性且会影响扩缩容分布。
连接、读取和发送超时分别约束不同阶段，keepalive 需与上游容量匹配。

# 四、身份头、协议与故障隔离

代理应覆盖 Host、X-Forwarded-For、X-Forwarded-Proto 和 request_id，
并只信任受控代理写入的头。
用直连上游和经过 Nginx 的同一请求比较状态码、路径和耗时；
失败实例应被摘除，但非幂等请求不能盲目重试到另一实例。

# 五、最小反向代理配置

配置保留原 Host 与客户端链路，并设置有界超时。

```nginx
upstream app_backend {
    least_conn;
    server app-1:8080 max_fails=3 fail_timeout=10s;
    server app-2:8080 max_fails=3 fail_timeout=10s;
    keepalive 32;
}
location /api/ {
    proxy_pass http://app_backend/;
    proxy_connect_timeout 2s;
    proxy_read_timeout 30s;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

该 proxy_pass 会去掉 /api/ 前缀；
若上游需要保留前缀，应修改 URI 设计并用集成测试固定行为。

- **上游连接与负载策略**：默认轮询适合实例能力相近的无状态服务，least_conn 适合请求耗时差异较大，ip_hash 只能提供有限粘性且会影响扩缩容分布。
- **身份头、协议与故障隔离**：失败实例应被摘除，但非幂等请求不能盲目重试到另一实例。
- **最小反向代理配置**：配置保留原 Host 与客户端链路，并设置有界超时。
