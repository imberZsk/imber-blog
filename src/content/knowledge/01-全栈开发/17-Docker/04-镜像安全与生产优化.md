# 二、镜像来源、SBOM 与签名链

镜像 tag 可变，digest 才标识具体内容。
构建流水线记录源码提交、构建器、基础镜像和依赖，生成 SBOM 后对镜像摘要签名；
部署策略验证签名与来源，防止未授权制品进入集群。

# 三、最小权限与只读运行时

最终镜像删除编译器和包管理缓存，
使用非 root UID、只读根文件系统、临时 tmpfs，
并 drop 不需要的 Linux capabilities。
需要写入的路径显式挂载；
健康检查、CA 和诊断工具由运行需求决定，不为追求极小体积盲目删除。

# 四、漏洞优先级与持续更新

扫描结果按可利用性、运行路径和业务暴露排序，不以漏洞数量代替风险。
修复优先升级基础镜像与直接依赖，重新构建后回归功能；
对无法立即修复的项记录影响、补偿控制、负责人和到期时间。

# 五、生产运行约束

用只读文件系统和能力裁剪验证应用真实写入边界。

```bash
docker run --rm \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  --user 10001:10001 \
  app@sha256:REPLACE_ME
```

若应用失败，先定位真实写目录并显式挂载，而不是取消全部约束。
镜像摘要与签名必须来自 CI 制品，不手工替换占位符发布。
