# 前端框架与跨端（06） - 前端应用状态、数据请求与错误边界

> 前端状态管理不是统一放进全局 Store，而是区分本地 UI 状态、URL 状态、服务端状态和跨会话状态。

> 读完你能：设计表单、请求缓存、竞态取消、加载/空/错状态和错误边界，并在 Vue、React 中保持相同工程原则。

## 核心知识清单

- 本地状态、全局状态、URL 状态与服务端状态
- 单向数据流、状态提升与受控表单
- Pinia、Redux Toolkit 与状态边界
- TanStack Query、缓存、失效与重新验证
- AbortController、请求竞态与去重
- 加载、空、错误、成功与局部刷新状态
- Error Boundary、错误上报与恢复入口

## 状态应该放在哪里

弹窗开关、输入框草稿留在组件；筛选、分页和排序进入 URL 以支持刷新和分享；用户、权限和主题等少量跨页面状态进入全局 Store；接口列表、详情、缓存和重试交给服务端状态库。复制接口数据到多个 Store 会造成失效和并发覆盖。

Vue 用 Props/Emit 和 Pinia，React 用 Props、Context 或 Redux Toolkit，但核心仍是单向数据流。表单可使用受控模式获得明确状态，也可让库管理非受控输入以降低大表单渲染成本；提交前后都要处理服务端字段错误。

## 请求层

请求函数负责基础 URL、认证、超时、错误解析和取消。连续搜索通过 AbortController 取消旧请求，或使用请求序号忽略过期响应。缓存键必须包含所有影响结果的参数和权限作用域，Mutation 成功后精确失效关联 Query。

## 页面状态

首次加载使用骨架或占位，空结果说明下一步，错误状态展示可操作的重试，后台刷新尽量保留旧数据。不能把权限拒绝、资源不存在和网络失败都显示成“暂无数据”。

React Error Boundary 或框架错误页只能捕获特定渲染错误；事件回调、异步请求仍需显式处理。错误上报携带路由、版本、trace_id 和用户操作摘要，不上传敏感表单正文。
